# 분류 검토 보고서 — rx_s1 (dq_rx_unit)

## 1. 검토 요약
- 검토 대상: `runs/rx_s1/glm/out/` (`classification.md`, `annotations.json`, `block_dictionary.json`)
- 검토 근거: `spec/DRAWING_PLAN.md` §2.3–2.7
- 판정: **PASS (수정 권고 0건, 분류 및 사전 대응 타당)**

## 2. 세부 검토 항목
1. **고속 데이터 입력 및 클럭 입력 판정 (§2.4)**:
   - `pad`: ESD(`xi20`), ODT(`xi21`), 전치증폭기(`xi24`, `rx_pre`) 입력 트랜지스터 게이트에 연결되어 단일 종단 고속 데이터 입력으로 판정 타당.
   - `vref`: RC 저역통과 필터(`r0`, `mn0`)를 거쳐 `rx_pre`의 차동 한쪽 기준 전압으로 들어가므로 비고속 아날로그 기준 전압(VREF, 회색 실선) 판정 타당.
   - `lb_p`, `lb_n`: 루프백 시험용 차동 데이터 입력으로 판정 타당.
   - `ck`, `ckb`: 클럭 게이팅 버퍼(`xi25`, `ck_gbuf`)를 거쳐 센스앰프(`xi28`, `xi29`, `sa_dt`)의 클럭 꼬리로 연결되므로 고속 차동 클럭 입력 판정 타당.
   - `dout_e`, `dout_o`: even/odd SR 래치 출력을 받아 인버터 체인을 거쳐 최상위 포트를 구동하므로 고속 데이터 출력 판정 타당.

2. **제어 분류 및 K# 끝점 판정 (§2.5)**:
   - `tap<3:0>`: `dfe_sum` 내부 IDAC 전류원 스위치 게이트로 연결되어 DFE 피드백 차동쌍의 꼬리 전류를 조절하며 주 입력과 합산되므로 K1(DFE 가중치, 버스) 판정 정확.
   - `tap_sgn`: DFE 피드백 극성 스티어링 스위치 게이트로 연결되므로 K1(DFE 탭 극성, 1비트 실선) 판정 정확.
   - `lb_en`: `rx_pre`의 주 입력쌍(`pad/vref`)과 루프백 쌍(`lb_p/lb_n`) 간 선택을 제어하는 상보 스위치 선택 신호이므로 K2(선택, 1비트 실선) 판정 정확.
   - `rx_en`: 클럭 게이팅 버퍼(`ck_gbuf`), 바이어스(`rx_bias`), 전치증폭기(`rx_pre`), DFE 여름(`dfe_sum`)의 꼬리를 켜고 끄는 정적 활성화 신호이므로 K3(켜기, 1비트 실선) 판정 정확.
   - `odt_en`, `rtt<2:0>`: 패드에 직접 연결된 풀업 종단 저항 뱅크(`odt_pu`)를 제어하므로 K4(종단, 버스 및 실선) 판정 정확.
   - `ofe_p<1:0>`, `ofe_n<1:0>`, `ofo_p<1:0>`, `ofo_n<1:0>`: 센스앰프 내부 노드에 매달린 커패시터 뱅크 스위치로 연결되어 오프셋을 조절하는 정적 트림이므로 K7(일반 제어, 숨김) 판정 정확.
   - `ibias`: 바이어스 발생기 입력으로 K11(바이어스, 숨김) 판정 정확.
   - `vdd`, `vddq`, `vss`, `vssq`: PMOS 및 NMOS 벌크에 연결된 전원/접지 레일로 전원(숨김) 판정 정확.

3. **사전 대응 (§2.6)**:
   - `esd_dq`: ESD 클램프 소자 및 직렬 R -> `termination_esd` (입력선 위 표시)
   - `odt_pu`: 패드 풀업 가변 저항 -> `termination` (입력선 위 가변 R 표시)
   - `odt_dec`: ODT 제어 디코더 -> DEC 박스
   - `rx_pre`: 입력쌍, 루프백쌍, 부하저항, 중화 커패시터로 구성된 전치증폭기 -> 사전에 없는 구조이므로 일반 박스 `PREAMP` 및 질문
   - `dfe_sum`: 차동 주입력쌍 + 피드백쌍 + IDAC 가중치 + 극성 스티어링 -> `summer` (Σ 기호)
   - `sa_dt`: 1단 동적 차동 증폭 + 2단 래치/클럭 꼬리 + 오프셋 트림 -> `comparator` (삼각형 SA + 클럭 기호)
   - `sr_nor`: NOR 게이트 교차 결합 -> `sr_latch` (SR 래치 박스)
   - `ck_gbuf`: 클럭 입력과 rx_en의 NAND/INV 게이팅 -> `composite` (게이팅 클럭 버퍼)
   - `rx_bias`: 고속 신호 경로와 직접 연결 없음 -> 생략 (omit)

4. **질문 고르기 (최대 10개)**:
   - GLM 초안의 8개 질문이 모두 확신도 low 항목이고, 규칙이 이미 정한 것을 묻지 않으며, 가정한 답이 명세서 원칙과 완벽히 부합하므로 8개 질문을 확정함.

## 4. 사용자 질문 목록 (확정 8개)
1. **Q1 (고속 입력)**: `pad`가 주 고속 데이터 입력 포트이고, `lb_p/lb_n`은 루프백 데이터 입력이 맞습니까?
   - 선택지: (pad 주입력, lb_p/n 루프백 / pad와 lb_p/n 모두 주입력)
   - 가정한 답: pad 주입력, lb_p/n 루프백
   - 이유: 패드 및 ESD/ODT 연결 구조 확인
2. **Q2 (클럭 입력)**: `ck, ckb`가 차동 고속 클럭 입력 포트가 맞습니까?
   - 선택지: (예 / 아니오)
   - 가정한 답: 예
   - 이유: 클럭 게이팅 버퍼 거쳐 SA 꼬리 구동 구조 확인
3. **Q3 (블록 역할)**: `rx_pre`는 일반 박스 `PREAMP`로 그립니다. 맞습니까?
   - 선택지: (일반 박스 PREAMP / VGA / CTLE)
   - 가정한 답: 일반 박스 PREAMP
   - 이유: 사전 VGA/CTLE와 다른 전치증폭기 구조 확인
4. **Q4 (블록 역할)**: `sa_dt`는 double-tail 비교기로서 사전 비교기 기호(삼각형 SA + 클럭)로 그립니다. 맞습니까?
   - 선택지: (삼각형 SA + 클럭 / 일반 박스)
   - 가정한 답: 삼각형 SA + 클럭
   - 이유: 동적 비교기 구조 확인
5. **Q5 (블록 역할)**: `dfe_sum`은 summer 기호(Σ)로 그립니다. 맞습니까?
   - 선택지: (Σ 기호 / 일반 박스)
   - 가정한 답: Σ 기호
   - 이유: DFE 가중치 합산 구조 확인
6. **Q6 (블록 역할)**: `odt_dec`는 DEC 박스, `odt_pu`는 패드 위 가변 종단 R 기호로 그립니다. 맞습니까?
   - 선택지: (예 / 아니오)
   - 가정한 답: 예
   - 이유: 종단 디코더 및 가변 저항 표기 규정 확인
7. **Q7 (제어 분류)**: `ofe_p<1:0>, ofe_n<1:0>, ofo_p<1:0>, ofo_n<1:0>`는 센스앰프 내부 오프셋 트림 제어로 K7 일반 제어(숨김) 처리합니다. 맞습니까?
   - 선택지: (숨김(K7) / 그리기)
   - 가정한 답: 숨김(K7)
   - 이유: 내부 노드 정적 용량 트림 스위치 판단
8. **Q8 (미사용 출력)**: `xi9`와 `xi12` 인버터의 출력 `net27, net29`는 미사용 출력으로 짧은 선 + 이름표로 유지합니다. 의도된 것입니까?
   - 선택지: (유지 / 제거)
   - 가정한 답: 유지
   - 이유: 넷리스트 상 미연결 출력 규정 준수
