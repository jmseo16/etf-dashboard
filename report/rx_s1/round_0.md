## 분류 (회차 0에서 채우고, 바뀌면 다시 적는다)
- 고속 데이터 입력: `pad` (주 고속 입력), `lb_p`, `lb_n` (루프백 시험 입력) / 고속 클럭 입력: `ck`, `ckb` / 고속 출력: `dout_e`, `dout_o` / 기준 전압: `vref`
- 그리는 제어 (이름, K#, 끝점 핀):
  - `tap<3:0>` (K1, `xi26/mn10.g`) — DFE 탭 가중치 IDAC 스위치 버스
  - `tap_sgn` (K1, `xi5/mn0.g`) — DFE 탭 극성 스티어링 스위치 구동
  - `lb_en` (K2, `xi0/mn0.g`) — pad/vref 경로 vs 루프백 lb_p/lb_n 경로 선택
  - `rx_en` (K3, `xi25/xi0/mn1.g`) — 수신기 및 클럭 게이팅 버퍼 enable
  - `odt_en` (K4, `xi22/xi2/mn0.g`) — 패드 ODT 풀업 종단 enable
  - `rtt<2:0>` (K4, `xi22/xi2/mn1.g`) — 패드 ODT 가변 종단 저항 코드 버스
- 숨기는 제어 (이름, K#):
  - `ofe_p<1:0>` (K7), `ofe_n<1:0>` (K7), `ofo_p<1:0>` (K7), `ofo_n<1:0>` (K7) — Even/Odd 센스앰프 내부 커패시티브 오프셋 트림 제어
  - `ibias` (K11) — rx_bias 정적 바이어스 전류 입력
  - `vdd`, `vddq`, `vss`, `vssq` (power) — 코어 및 IO 전원/접지 레일
- 블록 역할 표 (셀, 사전 행 또는 일반 박스, 확신도):
  - `esd_dq`: RX 종단 · ESD (입력선 위 R/ESD 표시, 확신 높음)
  - `odt_pu`: RX 종단 (입력선 위 가변 종단 R 표시, 확신 높음)
  - `odt_dec`: 제어 디코더 (박스 DEC, 확신 높음)
  - `rx_pre`: 전치증폭기/MUX (일반 박스 PREAMP, 확신 낮음)
  - `dfe_sum`: RX Summer (Σ 기호, 확신 높음)
  - `sa_dt`: RX 비교기 · 샘플러 (삼각형 SA + 클럭 기호, 확신 높음)
  - `sr_nor`: 공통 SR latch (박스 sr_nor, 확신 높음)
  - `ck_gbuf`: Clock 게이팅 버퍼 (게이팅 클럭 버퍼 삼각형, 확신 높음)
  - `inv_a`, `inv_c`: 공통 논리 게이트 (인버터 기호, 확신 높음)
  - `nand2_a`, `nand2_c`: 공통 논리 게이트 (박스 + 출력 동그라미, 확신 높음)
  - `nor2_c`: 공통 논리 게이트 (박스 + 출력 동그라미, 확신 높음)
  - `ls_lh`: 공통 Level shifter (박스 LS, 확신 높음)
  - `rx_bias`: 공통 바이어스 발생기 (생략/omit, 확신 높음)
  - `dq_rx_unit`: 최상위 복합 블록 (박스, 확신 높음)
- 질문과 가정한 답 (최대 10개, 총 8개):
  - Q1: `pad`가 주 고속 입력이고 `lb_p/lb_n`은 루프백 데이터 입력인가? → 가정한 답: 예, `pad`는 주 고속 입력, `lb_p/lb_n`은 루프백 입력.
  - Q2: `ck, ckb`가 차동 고속 클럭 입력인가? → 가정한 답: 예.
  - Q3: `rx_pre`는 일반 박스 `PREAMP`로 그리는가? → 가정한 답: 예.
  - Q4: `sa_dt`는 double-tail 비교기로 사전 비교기 기호(삼각형 SA + 클럭)로 그리는가? → 가정한 답: 예.
  - Q5: `dfe_sum`은 summer 기호(Σ)로 그리는가? → 가정한 답: 예.
  - Q6: `odt_dec`는 DEC 박스, `odt_pu`는 패드 위 가변 종단 R 기호로 그리는가? → 가정한 답: 예.
  - Q7: `ofe_p/n`, `ofo_p/n`은 K7 일반 제어(숨김) 처리하는가? → 가정한 답: 예.
  - Q8: `xi9`, `xi12` 인버터 출력 `net27, net29` 미사용 출력을 유지하는가? → 가정한 답: 예 (짧은 선 + 이름표).
- netlist에서 이상하다고 본 곳:
  - `rx_pre`의 `mn8`과 `mn9`: 드레인과 소스가 동일한 노드(`outp`, `outn`)에 묶여 MOS 커패시터(중화 용량)로 동작함.
  - `sa_dt`의 `mn8, mn10, mn12, mn14`: 드레인/소스/벌크가 모두 `vss`에 묶여 커패시터 부하로 동작함 (스위치 `mn7, mn9, mn11, mn13`과 함께 용량성 오프셋 트림 구성).
  - `xi9`와 `xi12`의 출력 `net27`, `net29`: SR 래치의 반전 출력 인버터이지만 후속 연결이 없는 미사용 출력임.

## 명세서·묶음에서 막힌 곳
- 기준 코드 `analyze.py`의 `find_rails()`가 최다 빈도 단일 전원/접지만 레일로 인식하여, 다중 전원(`vdd`, `vddq`, `vss`, `vssq`) 회로인 `rx_s1`에서 `vddq`를 신호선으로 오인하는 문제가 있었음. 명세서 §2.1-1("PMOS 벌크에 쓰인 넷은 모두 전원, NMOS 벌크에 쓰인 넷은 모두 접지")에 따라 `self.supplies`, `self.grounds` 집합으로 다중 레일을 올바르게 처리하도록 수정함.
- `analyze.py` 373번째 줄에서 단일 차동쌍 꼬리 스위치 판정 시 2-tuple을 반환하여 언팩 오류가 발생하던 문제를 3-tuple (`'general'`, `'K7'`, ...)로 정정함.
