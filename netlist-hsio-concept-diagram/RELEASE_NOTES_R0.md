# Release 0 (R0) — 넷리스트 기반 High-Speed IO 개념도 그리기

> 명세서 v6.1 · 2026-11-16 · 첫 사내 배포

HSPICE/Virtuoso netlist를 받아 고속 IO 회로의 **개념도**(블록에서 클릭으로 MOSFET 유닛 화면까지 내려가는 단일 HTML + 수정 가능한 PPTX)를 그리고, 그린 것이 netlist와 같은지 스스로 검증하는 스킬이다. 사람이나 LLM이 명세서만 보고 같은 규칙으로 그리도록 쓴 **명세서 + 구현 가이드 + 기준 결과**와, 사내 GLM과 Claude Code를 나눠 쓰는 **실사용 흐름**이 들어 있다.

## 받는 파일

| 파일 | 내용 | 필수 |
|---|---|---|
| `HSIO_R0_SOURCE.md` | 스킬 전체 (텍스트 묶음, 맨 위에 복원 스크립트) | 예 |
| `HSIO_R0_TESTS.md` | 회귀 시험 세트 (시험 netlist 9개 + 정답지 + 설계 메모) | 스킬을 고쳐 다시 시험할 때만 |

## 처음 쓰는 순서

1. **복원**: 묶음 맨 위의 복원 스크립트를 `restore.py`로 저장 → `python3 restore.py HSIO_R0_SOURCE.md netlist-hsio-concept-diagram` → 모든 줄 `OK`, 체크섬 불일치 0.
2. **환경**: Python 3.6+ + `python-pptx`, Node.js 18+ + Playwright(Chromium). 인터넷이 막힌 서버는 `SKILL.md` §2의 오프라인 설치 참고.
3. **기준 결과 재현**: `bash netlist-hsio-concept-diagram/reference/rx_afe/work/run_all.sh` → 17개 화면 모두 연결·품질 통과, `out/`의 분류 파일이 `expected/`와 같아야 한다. 도구가 제대로 깔렸는지 보는 시험이다.
4. **읽기**: `SKILL.md`(구현 가이드) → `DRAWING_PLAN.md`(규칙, 0–4장 + 부록 A–C).
5. **실사용**: `workflow/WORKFLOW.md` — GLM(토큰 무제한)이 분류 초안·그리기·수정을, Claude Code(토큰 제한)가 분류 검토·최종 검토를 짧게 하고, 사용자가 분류를 확인한다. 실사용에는 정답지가 필요 없다. 단계는 사람이 넘겨도 되고(방식 1) `workflow/orchestrate.py`로 돌려도 된다(방식 2, `orchestrate_config.json`의 명령 두 줄만 사내에 맞춘다).

## 검증 상태 (루프 1–4회차)

맥락 없는 그리는 에이전트가 명세서와 netlist만으로 그리고, 독립 검증 에이전트가 체크리스트와 설계자 정답지로 판정했다(안쪽 루프 최대 3라운드). 모든 회차에서 **틀린 연결은 0**이었다.

| 회차 | 회로 | 규모 | 결과 |
|---|---|---|---|
| 1 | Rx(CML), Tx(4:1 SST + FFE), DCC | 소형 | 연결 정확, 명세 v2의 계기 |
| 2 | BIST, ZQ 보정, DQS-RX | MOS 0.9–2.4천 | 그린 쪽 불통과 0(2라운드), 명세 원인 → v4 |
| 3 | NAND 플래시 IO 전체 | MOS 6833, 셀 92 | 그린 쪽 0(3라운드), 명세 원인(제어 분류) → v5 |
| 4 | NAND IO(v5로 다시), 그 이름 가림판, LPDDR5형 바이트, 포워디드 클럭 링크 | MOS 4–7천 | 그림 PASS 3개(3라운드), 닮은꼴 함정 23/23·10/12 식별. 이름 가림 시험으로 이름 의존 빈틈 4개 발견. 명세 원인 → v6.1 |

기준 결과(RX AFE)는 v6.1 규칙으로 다시 만들었다: 17개 화면 통과, 자동 검사 29종, 일부러 넣은 오류 57개 모두 잡힘.

## 알려진 한계

1. **4회차 시험은 명세서 v5로 돌렸다.** v6.1에서 메운 규칙(느린 클럭, (mon) 출력, 루프 신호, 자기 리셋, 핀 방향 표, 논리 출력 극성 등)으로 시험 세트 전체를 다시 돌린 것은 아니다 → 다음 배포 전에 회귀 시험.
2. **정답지와 일부러 다르게 정한 정책**(부록 C.8): 레지스터·포트에서 오는 정적 코드(slew, CTLE 피킹, 디스큐·지연 트림)는 숨긴다(V7). 공통모드 전압은 바이어스(V14). 보정 루프가 만드는 아날로그 트림은 중요 제어(V15).
3. **열린 문제**(부록 C.9): 클럭 핀을 구동하지 않는 분주기 출력의 분류, 구조 특징이 정해지지 않은 일부 사전 항목, keeper 배치와 대칭 규칙의 관계, 사이드 패널 변경 지문 등.
4. **`orchestrate.py`는 가짜 명령으로만 시험했다.** 사내 `opencode`/`claude` 명령줄 실행은 사내에서 처음 확인해야 한다.
5. **공용 도구 묶음이 없다.** 그리는 쪽은 기준 결과 코드를 출발점으로 netlist마다 분석·배치 코드를 넓혀 쓴다(검증기는 `reference/rx_afe/work/verify.py`에서 시작). 큰 netlist는 이 단계에 토큰이 가장 많이 든다 → 다음 배포 후보.
6. 그림 화면 수가 많은 회로(70–90개)는 HTML이 1MB 가까이 된다. 화면 데이터 압축(브라우저 내장 해제)으로 한 파일을 유지한다.
