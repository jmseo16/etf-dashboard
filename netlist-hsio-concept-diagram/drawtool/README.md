# hsio_draw — netlist에서 고속 IO 개념도를 그리는 도구 (v0.4)

netlist 하나를 넣으면 분류 → 화면 구성 → 배치·배선 → 검증까지 한 번에 하고 결과를 폴더에 씁니다.
**그림은 도구가 그립니다.** 사람(또는 모델)이 할 일은 도구를 돌리고, 도구가 묻는 질문에 답하고, 결과를 확인하는 것뿐입니다.

## 실행

```bash
python3 tool/hsio_draw.py <netlist.sp> -o <결과 폴더>
python3 tool/hsio_draw.py <netlist.sp> -o <결과 폴더> --annotations <answers.json>   # 답을 넣어 다시 그리기
```

필요한 것: Python 3.8+. PPTX는 `python-pptx`, PNG는 Node.js + Playwright가 있으면 만들어집니다(없으면 그 파일만 빠지고 나머지는 나옵니다).
끝나면 한 줄 요약이 나옵니다: `views N, connectivity N, quality N` — 세 숫자가 같으면 모든 화면이 검사를 통과한 것입니다. 종료 코드는 모두 통과 0, 아니면 1.

## 결과 폴더

| 파일 | 내용 |
|---|---|
| `draw_report.md` | 한 장 요약: 화면 수, 검사 통과 수, 화면별 문제 |
| `classification.md` / `.json` | 포트마다 분류(고속 데이터·클럭, 중요 제어 K1–K6, 숨김 K7·K10·K11, 기준, 상태)와 근거 |
| `questions.json` | 도구가 확신하지 못한 항목과 가정한 답 |
| `annotations.json` | 이번 실행에 쓴 답 (처음에는 빈 틀) |
| `concept.html` | 뷰어 한 파일: 블록 클릭 → 하위 화면, ▲ 위로, W/L 표시 토글, PPT 내려받기 |
| `concept.pptx` | 화면마다 한 장, 수정 가능 |
| `screenshots/<화면 id>.png` | 화면별 그림 |
| `verify_report.json` | 화면별 검사 결과와 `scene_sha`, 검증기 오류 주입 결과 |
| `scenes.json` | 그림 좌표 원본 (검증기가 읽는 것) |

## 질문에 답하기 / 분류 고치기 (`annotations.json`)

```json
{
  "answers":        {"ctl:wl_ck": "K9"},
  "net_class":      {"some_port": "K3"},
  "block_role":     {"some_cell": "box"},
  "hide_instances": ["xi38"],
  "pairs":          [["ckp", "ckn"]]
}
```

- `answers`: `questions.json`의 질문 id → 그 질문의 선택지 중 하나.
- `net_class`: 최상위 포트의 분류를 직접 지정. 값: `hs_data`, `hs_clock`, `reference`, `bias`, `hidden`, `K1` … `K11`.
- `block_role`: 셀의 기호. 값: `box`, `inv`, `buf`, `samp`, `sum`, `vref`, `dec`, `omit`.
- `hide_instances`: 그리지 않을 인스턴스 이름.
- `pairs`: 이름으로 찾지 못한 차동 포트 쌍.
- 쓰지 않는 항목은 비워 두거나 지우면 됩니다. 도구의 판정이 맞으면 아무것도 적지 않습니다.

## 도구가 지키는 그리기 규칙

1. **모든 핀은 이어져 있다.** 선으로 잇지 못하면 같은 이름의 이름표로 잇고, 끝이 떠 있는 선은 만들지 않는다.
2. **직선이 먼저다.** 두 끝을 직선으로 이을 수 있으면 직선으로 긋고, 불가피할 때만 꺾는다(꺾임 수 최소 → 길이 최소 순으로 찾는다). 직선 거리의 1.5배를 넘게 돌아가야 하면 선 대신 이름표로 잇는다.
3. 블록 화면에서는 선이 교차하지 않는다(교차가 생길 곳은 이름표). 트랜지스터 화면에서는 거울 쌍의 두 넷만 한 번 교차할 수 있다.
4. 신호는 왼쪽에서 오른쪽으로 흐른다. 제어는 위, 클럭은 아래, 출력은 오른쪽, 기준은 왼쪽 둘째 자리.
5. 트랜지스터는 접지에서 전원 쪽으로 세로로 쌓고, 직렬 소자는 한 열에 둔다. 차동 회로는 쌍마다 자기 축에 대칭, 여러 쌍은 나란히.
6. 버스는 사선과 `<MSB:LSB>` 이름, 같은 셀의 반복 인스턴스는 한 블록 `×N` + 주석.
7. 숨기는 것(정적 트림, 바이어스, 전원, 고속 신호와 무관한 블록, 더미, 안테나 다이오드)은 그리지 않고 생략 목록에 적는다. 전원은 화면에서 국소 전원 기호로만 보인다.
8. 한 점에 선은 세 개까지, 접점에는 점. 글자는 서로, 또 선과 겹치지 않는다.

검증기(`hd/verify.py`)는 배선기의 내부 자료를 쓰지 않고 **그림 좌표만으로** 연결을 다시 읽어 netlist와 비교하며, 위 규칙 1–3과 8을 화면마다 셉니다.
실행할 때마다 정상 그림에 오류를 일부러 넣어(선 지우기, 선 끝 당기기, 불필요한 꺾임, 접점 지우기, 이름표 바꾸기, 글자 겹치기, 핀 뒤바꾸기) 검증기가 잡는지도 시험합니다.

## 아직 하지 않는 것

- 개념 기호로 묶기(가변 저항·가변 전류원·가변 커패시터), 패드 위 ESD·종단 표시: 지금은 소자와 박스 그대로 그립니다.
- 비교기·증폭기 삼각형, MUX 사다리꼴: 지금은 박스입니다(인버터·버퍼만 삼각형).
- 보정 루프 화면, 워드 속도 디지털 박스, 유닛 화면의 20개 상한에 따른 화면 나누기, cross-coupled 인버터의 90° 배치.
- 분류는 구조 규칙의 일부만 구현했습니다. 확신이 낮으면 질문으로 남기지만, 틀린 채 확신하는 경우가 있을 수 있습니다.
