# v6.1 결정 (오케스트레이터, 4회차 결과 반영) — 사용자 승인: B안, 정적 코드 = 1번(그대로)

모든 결정은 v6 골격 안에서 그 규칙이 있는 문장을 고쳐 반영한다 (부록 C.10). 새 장 금지. 이력은 C.1 v6.1 행, 바뀐 규칙은 C.6 "v6.1" 행, 정한 것은 C.8 표에 V1… 번호로, C.9 열린 문제는 정리.

## 분류 (§2.5)
- V1 **K6 좁히기**: 다비트 **레벨** 코드(비교기·샘플러 기준 레벨)와 여러 비트 경로(슬라이스)가 공유하는 이득 코드만. 기준 **원천** 선택(내부 발생기 ↔ 외부 패드)과 발생기 켜기·끄기는 K10(일반).
- V2 **순서**: K8(명령)과 K9(시험 입력)을 K3보다 먼저 본다. 루프의 상태 소자 enable·갱신 클럭 게이트·리셋·검출기 클럭 게이트에만 닿는 1비트 포트 = K8. K3의 "보정 루프를 켜고 끄는 곳"은 루프의 아날로그 전원·꼬리·분압 스위치와 복제 다리 게이트로 좁힌다.
- V3 **K2 넓히기**: 같은 원천에서 나온 서로 다른 경로(정합/비정합, 지연/비지연 등) 중 하나를 고르는 선택도 K2.
- V4 **K5**: 코드로 켜는 병렬 다리는 출력이 패드든 내부 고속 노드든 K5. K1은 다리의 데이터 입력이 주 신호와 **다른** 고속 신호(FFE 탭)일 때만; 주 데이터 다리의 enable은 K5(또는 출력 끄기면 K3).
- V5 **경로 상속**: 중요 제어가 논리를 거쳐 오버라이드 선택에도 닿으면 그 경로는 그 중요 제어의 분류.
- V6 **K7/K11 경계**: 바이어스 발생기 안의 코드 스위치(바이어스 DAC로만 가는 코드)는 K7 정적 = 일반. K11은 바이어스 노드 자체만. (C.9 열린 문제 2 해소)
- V7 **정적 코드 = 그대로 (사용자 결정, 1번)**: 포트·레지스터에서 오는 정적 코드(slew, CTLE 피킹, 디스큐, 지연 트림)는 K7 일반 = 숨김. 정답지마다 다르다(NAND 정답지 = 일반, F 정답지 = 중요)는 사실과 이 결정을 C.8에 적는다.
- V8 **(mon) 모니터 출력 구조 정의**: 출력 포트가 (a) 다른 고속·클럭·아날로그 노드의 주 경로에서 갈라진 가지(버퍼·게이트·직렬 R)로만 구동되고 (b) 그 가지가 칩 안 다른 곳에서 쓰이지 않으면 (mon). 그 가지를 켜고 끄는 1비트 입력 = K9. 상태 소자 출력(카운터 값 등)을 내보내면 O1 상태 출력(모니터 표시는 하지 않음). (C.9 열린 문제 1 해소)
- V9 **느린 클럭**: 상태 소자(FSM·카운터·레지스터)의 클럭 핀에 닿는 입력은 고속이 아니어도 **클럭**(느린 클럭)이다. K8로 보지 않는다. 그림은 클럭과 같고 이름 옆 "(slow)"는 붙이지 않는다. 슬로우 스트로브 패드도 같다.
- V10 **단일 종단 슬로우 패드**: 종단 없이 ESD만 붙은 단일 종단 패드는 고속 입력 후보가 아니다(§2.4). 끝점으로 분류한다(명령·시험·느린 클럭·상태 등).
- V11 **루프 검출기 출력**: 루프 안 검출기(위상 검출기·비교기·적분기)의 출력(up/dn 등)은 고속 데이터가 아니라 **루프 신호** — 그림은 느린 신호와 같은 실선, 분류 표에는 "루프 신호(검출기 출력)".
- V12 **자기 리셋**: 블록 안에서 그 블록의 출력으로 만들어져 자기 상태 소자를 리셋하는 경로(예: 두 출력이 모두 서면 스스로 리셋)는 신호 경로 — 숨기지 않는다. K10은 블록 밖(포트·제어 허브)에서 오는 비동기 set/reset만.
- V13 **P2 넓히기**: 직렬화기 데이터 입력이 "1비트 입력 하나와 그 반전" 또는 "1비트 입력 하나와 상수"로만 채워져도 패턴 생성 슬라이스.
- V14 **공통모드(vcm)**: 지금처럼 바이어스(숨김). 정답지 G는 기준으로 둔다는 차이를 C.8에 기록.
- V15 **루프 출처 아날로그 트림**: 보정 루프가 만드는 아날로그 트림 전류·전압(오프셋 보정 DAC 출력 등)은 루프 출처 K7 = 중요 (c). 정답지 F는 바이어스로 둔다는 차이를 C.8에 기록.

## 사전 (§2.6)
- V16 **MUX 행 특징**: 두 데이터 입력 + 상보 선택(셀 안 인버터로 만들든 밖에서 sel/selb로 받든). AO22/AOI22 구조에 상보 선택이 들어오면 MUX.
- V17 **Latch/DFF 행**: TSPC(진정한 단상 클럭) 구조는 지금처럼 사전에 없음 — 일반 박스. (변경 없음, 확인만)

## 그리기 (§3)
- V18 **핀 방향 표** (§3.2): 블록 화면의 박스·삼각형에서 중요 제어·명령·시험 입력은 **위**, 클럭은 **아래**(그 블록이 클럭을 흘려보내는 블록이면 왼쪽 허용), 데이터는 왼쪽·출력은 오른쪽. 1비트 중요 제어도 위. 예외: 제어 허브 입력, 루프 고리 넷(루프 화면의 주 경로), P2 패턴 데이터, 제어 전달 셀(레벨 시프터 등)의 단일 입력, 핀 자리가 정해진 기본 소자(§3.4 게이트 입력 왼쪽, MUX 선택 아래 경사, 선택 스위치 위).
- V19 **극성 범위**: 출력 동그라미는 **논리 출력**에만. 아날로그 출력(차지 펌프, OTA, 바이어스, DAC)에는 극성 동그라미를 그리지 않고 출력별 극성 검사도 하지 않는다.
- V20 **역순 비트**: 합친 반복 블록의 연결이 비트 역순이면 버스 이름은 `<MSB:LSB>` 그대로 두고 범례에 연결 관계(예: `X1[j].q → rxd<7−j>`)를 적는다.
- V21 **차동 입력 표시**: 비교기·증폭기 기호의 차동 입력에 +/− 표시. (SKILL에 이미 있으면 확인만)
- V22 **루프 화면 안 상태 소자**: 루프에 속한 FSM·카운터·SAR은 루프 화면 안에서 박스로(하위 화면 없이 가능).

## 산출물 (§1)
- V23 **PPT 내장 필수**: HTML 한 파일 안에 PPTX를 base64로 넣는다. 크기 상한은 없다. 커지면 화면 데이터를 압축(gzip)하고 브라우저 내장 DecompressionStream으로 푼다. 옆 파일 링크 금지.

## 검증 (§4)
- V24 **자동 검사 추가** (§4.1, 각각 오류 주입): 핀 방향(V18), 회색 이름표 허용 범위, 질문 검사(확신 낮음·템플릿·규칙이 정한 것 아님), 끝점 핀 검사(instance.pin 형식·존재·넷에서 도달·구동원 아님), 표 간 분류 일치(분류 표·포트 표·annotations·사이드 패널), 블록 핀 이름 = 셀 포트, R/C 값 = 인스턴스 실제 값, 글자가 박스·화면 밖으로 나감.
- V25 **필수 오류 주입 목록**: OPEN(선 끊기), SHORT, 블록 교차, 동그라미 지우기, 미사용 출력 지우기, 없는 핀 이름, 그리지도 생략하지도 않은 넷, 짧은 꺾임(<20px), 글자 겹침, 점선, 핀 방향 위반. AGENT 2 검증기는 기준 결과의 `reference/rx_afe/work/verify.py`에서 시작해 넓힌다(처음부터 약한 검사기를 새로 짜지 않는다).
- V26 **체크리스트 v6.1**: M13 핀 방향(자동, §3.2 표) · M14 표 간 분류 일치(자동). J3에서 핀 방향 부분을 빼고 "M13" 참조. id는 그대로, 새 번호만 끝에.
- V27 **검증 쪽(AGENT 3) 규칙** (§4.3): 규칙형 항목은 모든 화면·모든 핀을 전수 검사하고 전체 목록을 첨부(표본 금지). 검증 스크립트에도 오류 주입. fix_request에는 "이 목록은 최소 범위 — 같은 규칙을 전체에 적용하고 바뀐 화면을 보고"를 쓴다.

## 열린 문제 (C.9) 정리
- 1(mon) → V8로 해소, 2(바이어스 DAC 코드) → V6로 해소, 4(클럭 핀을 안 구동하는 분주기 출력) → 남김, 3(특징 없는 사전 항목) → MUX(V16)만 해소, 나머지 남김, 5(고속 클럭 FF 입력의 K 행) → 남김.
