# 회귀 시험 세트

명세서(`DRAWING_PLAN.md`)나 도구를 고친 뒤 다시 돌려, 전에 맞던 것이 틀려지지 않았는지 보는 시험 netlist 모음이다.
모두 시험용으로 만든 가상 회로다(실제 사내 설계 아님). 루프 1–4회차에서 쓴 것과 같다.

## 쓰는 법 (반드시 지킬 것)

- **그리는 쪽(AGENT 2 / GLM)에게는 `netlist.sp`만 준다.** 파일 이름도 중립적으로 바꿔 준다(예: `netlist_x.sp`).
- **`answer_key.json`, `answer_key_README.md`, `intent.md`, `name_map.json`은 검증 쪽(AGENT 3)에게만** 준다. 그리는 쪽으로 가는 수정 요청(`fix_request.md`)에는 이 내용을 넣지 않는다(명세서 §4.3).
- 정답지 분류 이름은 명세서 부록 B로 명세서 분류에 맞춰 대조한다. 정답지와 일부러 다르게 정한 정책(정적 slew·CTLE 코드, 공통모드, 루프가 만든 아날로그 트림 — 명세서 부록 C.8 V7·V14·V15)은 불일치로 세지 않는다.
- 판정은 두 축: 그림(그린 쪽 원인 불통과 0) / 명세(명세서 원인 불통과 0).

- 기준 결과(RX AFE)는 이 세트가 아니라 `reference/rx_afe/`에 있다(정답 그림까지 있음).
- 이름 가림 시험(`t4_nameblind`): 같은 그리는 절차를 `t3_nand_io`와 `t4_nameblind`에 각각 돌린 뒤, `name_map.json`으로 분류·블록 역할을 맞대어 본다(체크리스트 N1). 이름 있는 판과 가림판이 다르면 명세서가 이름에 기대고 있다는 신호다.
- 실업무 netlist에서 새 문제가 나오면, 사용자가 확인한 `annotations.json`을 그 netlist의 정답지로 올려 이 세트에 더할 수 있다(사내에만 보관).
