# 넷리스트 기반 High-Speed IO 개념도 그리기 — 도면 계획서

> 스킬 이름: **넷리스트 기반 high speed IO 개념도 그리기** (폴더/식별자: `netlist-hsio-concept-diagram`)
> 상태: 계획서 (스킬화 전). 기존 `hspice-schematic`(v1)과 `hspice-schematic-v2`에서 검증된 부분을 기반으로 한다.

---

## 0. 목적과 우선순위

**목적**: HSPICE/Virtuoso netlist를 받아 **High-Speed IO 회로의 개념을 설명하는 그림**을 그린다.
회로를 빠짐없이 옮기는 회로도가 아니라, "신호가 어디로 흐르고 어떤 구조로 처리되는가"를 한눈에 보여주는 **개념도**다.
그래서 **덜 그리는 것**이 기본이다. 개념에 필요 없는 신호·포트·블록은 그리지 않는다.

**판단 우선순위** (충돌하면 위가 이긴다)
1. **정확성** — 그린 것은 모두 netlist와 일치해야 한다. 생략은 허용하되, 틀리게 그리는 것은 절대 안 된다.
2. **고속 신호 경로가 한눈에** — 고속 데이터·클럭만 선으로 그리고, 나머지는 지우거나 버스 하나로 줄인다.
3. **대칭** — 차동 회로는 무조건 좌우 대칭.
4. **최소 선·최소 노드·최소 교차** — 불필요하게 꼬인 선, 군더더기 접점, 짧게 꺾이는 선을 만들지 않는다.
5. **교과서(Razavi) 스타일** — 지금까지 정한 그림 규칙(트랜지스터 모양, Virtuoso 핀 등).

| 차동 증폭기 배치 | 가능하면 대칭, 안 되면 쌍별 대칭 | **무조건 대칭**, 신호선 꼬임 금지, 노드 최소 |

## 3. 1단계 — 고속 신호 판정 (모든 것의 전제)

### 3.1 신호 분류

| 분류 | 정의 | 그림 |
|---|---|---|
| **HS 데이터** | 고속 데이터 입력에서 출발해 신호 경로를 따라 도달하는 넷 (출력·피드백 포함) | 선 |
| **HS 클럭** | 클럭 입력에서 출발해 도달하는 넷 (분주기·버퍼 출력 포함) | 굵은 선 |
| **중요 제어** | 개념의 핵심 동작을 정하는 제어 (예: DFE 탭 계수 DAC 코드) | 버스 1개 |
| **일반 제어** | 경로의 파라미터만 조절 (이득, 피킹 R/C, 트림) | 그리지 않음 |
| **바이어스** | 전류원 게이트, 다이오드 연결 노드, 기준 전류, 공통모드 | 그리지 않음 (중요하면 버스/이름표) |
| **전원** | VDD/VSS | 블록도에서 숨김, 유닛 레벨에서 레일 |

### 3.2 판정 방법 — 입력에서 회로를 따라간다

1. **시작점 정하기 (HS 입력)**
   - 자동 후보: 최상위 포트 중 이름·구조로 추정 (차동 짝 이름, 차동쌍 게이트로 들어가는 포트, CLK 이름).
   - **애매하면 사용자에게 묻는다**: "고속 데이터 입력과 클럭 입력이 이것이 맞습니까?" 사용자가 알려준 입력이 항상 우선한다.
2. **신호 흐름 추적 (계층을 넘나들며)**
   - MOS: 게이트가 HS면 → 드레인(및 소스 팔로워면 소스)이 HS. 소스가 HS면 → 드레인이 HS (캐스코드).
   - latch / flip-flop / 인버터 / 버퍼 블록: 입력이 HS면 출력이 HS.
   - 수동소자: 직렬로 신호를 전달하는 R/C/L은 양끝을 같은 분류로 (전원으로 가는 부하·디커플링은 제외).
   - 피드백도 따라간다 (DFE: 플립플롭 출력 → summer 탭 입력은 HS 데이터).
   - **멈추는 곳**: 전원, 전류원 게이트(바이어스), 스위치 게이트(제어).
   - 클럭은 클럭 입력에서 같은 방식으로 따로 추적한다 (클럭 버퍼·분주기 출력 = HS 클럭).
3. **나머지 분류**: 추적에서 닿지 않은 넷 = 비고속. 그중
   - 전류원과 직렬인 스위치·degeneration 노드 사이 스위치의 게이트 → **제어**
   - 전류원 게이트, 다이오드 노드, 공통모드 노드 → **바이어스**
4. **중요 제어 판정**: 제어 넷이 조절하는 가지(branch)의 신호 입력이 **주 입력과 다른 HS 신호**이고, 그 가지가 HS 노드에서 **합산**되면 → 중요 제어 (= 다른 신호를 얼마나 섞을지 정하는 가중치. DFE 탭 계수가 대표적). 주 경로의 이득·피킹만 바꾸는 제어 → 일반 제어.
5. **확인 표 제시**: 판정 결과를 표로 보여주고, 추적과 이름이 어긋나는 넷(예: 이름은 CLK인데 데이터 경로에서 도달)은 사용자에게 확인받는다.

### 3.3 사용자 지정 (annotations)
```json
{
  "hs_inputs": ["RX_INP", "RX_INN"],
  "clock_inputs": ["CLK_INP", "CLK_INN"],
  "hs_outputs": ["DOUT_EVEN_P", "DOUT_EVEN_N", "DOUT_ODD_P", "DOUT_ODD_N"],
  "important_controls": ["W<1:4>_<0:3>"],
  "show_bias": [],
  "hide": []
}
```
자동 판정보다 항상 우선한다. 처음 한 번 확인받은 내용은 이 파일로 저장해 다음부터 묻지 않는다.

## 4. 2단계 — 블록 레벨 연결도

1. **보이는 넷만 남긴다**: HS 데이터, HS 클럭, 중요 제어(버스), (지정된 경우) 중요 바이어스.
2. **나머지는 완전히 지운다**: 선도, 이름표도, 블록 심볼의 핀도, 셀의 포트(Virtuoso 핀)도 그리지 않는다. 블록 심볼은 보이는 핀만으로 크기를 다시 정한다.
3. **고속 신호와 연결이 하나도 없는 블록은 생략**한다 (예: BIAS_GEN). 생략한 블록·넷은 사이드 패널과 PPT 메모의 **"생략 목록"** 에 남긴다 (조용히 사라지는 것은 없다).
4. **중요 제어는 버스 하나**로: 같은 기능의 비트는 모두 한 버스(`W<1:4>_<0:3>`)로 묶어, 블록 위쪽에서 한 줄로 들어간다. 같은 버스를 여러 블록(DFE even/odd)이 받으면 줄기 하나에서 갈라진다.
5. **배치**: 왼쪽→오른쪽 신호 흐름, 피드백은 아래로, 클럭은 아래에서, 중요 제어 버스는 위에서. 주 데이터 경로는 한 줄로 곧게 정렬.
6. **선 수 최소화**: 같은 넷은 줄기 하나 + 가지, 블록 핀은 받는 쪽과 같은 높이로 정렬해 꺾임 없이.

### 하위 블록으로 내려가도 같은 규칙
- 각 하위 셀의 핀은 **위에서 정한 분류**로 판단한다 (같은 셀이 여러 곳에 쓰이면 한 곳에서라도 보이는 핀은 보인다).
- 그 셀 안에서도 보이는 넷만 그리고, 보이지 않는 포트는 Virtuoso 핀을 만들지 않는다.

## 5. 3단계 — 유닛 레벨 (MOSFET 단위)

### 5.1 유닛 종류 판정
차동 증폭기형(CML 버퍼, CTLE, VGA, summer, CML latch, StrongARM), 단일 종단 논리(INV, NAND), DAC, 바이어스 회로로 나눈다. 차동 증폭기형이면 아래 규칙이 최우선이다.

### 5.2 차동 증폭기 = 무조건 대칭
1. **한 축 대칭**: P쪽 절반은 왼쪽, N쪽 절반은 오른쪽, 정확한 거울상. 자기대칭 소자(tail 등)는 축 위.
2. **여러 차동쌍이 출력을 공유하면 (VGA, summer) — 중첩 대칭**: 주 차동쌍을 안쪽, 추가 쌍(이득 단, 탭)을 바깥쪽에 두고 모두 같은 축 기준으로 대칭. 꼬리 전류원들은 축 위에 위아래로 쌓고, 바깥 쌍의 소스 버스는 안쪽 꼬리 아래로 지나간다.
   ```
            VDD ───────────────────────────
              MP_LP                 MP_LN
       OUTP ──┤                         ├── OUTN
         M_G_P    M_MAIN_P   M_MAIN_N    M_G_N
           │         └────┬────┘           │
           │            MB_M               │
           └──────────────┬────────────────┘
                        MS_G<0:3>
                        MB_G<0:3>
   ```
3. **degeneration 스위치는 가로로**: CTLE의 SP–SN 사이 스위치(MR<0:2>, MC<0:2>)는 R_S/C_S처럼 두 소스 세로선 사이에 가로로 놓는다 (지금처럼 세로 소자로 취급해 대칭이 깨지는 일 금지).
4. **공유 게이트(바이어스 등)는 꼬지 않는다**: 거울 쌍의 공유 게이트(VGA의 VBP, CTLE의 VBN)는 두 게이트 사이를 **곧은 가로선 하나**로 잇고, 바이어스를 그린다면 축 위에서 수직으로 들어온다. 소자를 돌아가는 배선 금지.
5. **입력·출력 위치**: INP 왼쪽·INN 오른쪽(게이트 높이), OUTP 왼쪽 끝·OUTN 오른쪽 끝(드레인 노드 높이) — 출력도 대칭.
6. **바이어스·일반 제어 게이트**: 트랜지스터 게이트는 반드시 무언가에 연결돼 보여야 하므로, 짧은 회색 이름표만 단다 (포트 핀 없음, 배선 없음). 공유 게이트는 4번 규칙.

### 5.3 선과 노드 규칙 (모든 레벨)
1. **노드 최소화**: 넷에 가지를 붙일 때 **이미 꺾이는 모서리**에서 나가게 한다 (모서리 → T 하나). 기존 접점 바로 옆(20px 이내)에 새 접점을 만들지 않는다.
   - 예: VGA의 OUTN/OUTP는 부하에서 내려온 선이 꺾이는 모서리에서 곧게 나가야 한다 (지금은 그 살짝 위에 새 접점을 만들어 지저분함).
2. **꼬임 금지**: 한 넷의 선 길이가 두 끝점 사이 최단 거리(맨해튼)의 1.5배를 넘거나 소자를 한 바퀴 돌아가면 "꼬임"으로 보고 다시 배치·배선한다.
3. **짧은 꺾임 금지**: 20px 미만의 짧은 꺾임(계단)은 곧게 편다.
4. **대칭 배선**: P쪽 넷의 경로는 N쪽 넷 경로의 거울상이어야 한다.
5. **교차**: 구조상 피할 수 없는 곳(cross-coupled의 X 등)만 허용.

### 5.4 대표 유닛 목표 모양
- **CTLE**: 부하 위(대칭) → 입력쌍 → 소스 세로선 사이에 R_S·C_S·스위치 R/C를 가로로 → 전류원 둘(축 대칭) → 접지.
- **VGA / summer**: 5.2-2 중첩 대칭.
- **CML latch**: 지금 v2 모양 유지 (입력쌍 바깥, cross-coupled 안쪽 X, 클럭쌍 거울, tail 축).
- **StrongARM**: 교과서 배치 — 위: 리셋 PMOS(M7–M10)와 cross-coupled PMOS(M5/M6), 중간: cross-coupled NMOS(M3/M4), 아래: 입력쌍(M1/M2), 맨 아래: 클럭 tail. 전부 한 축 대칭.

## 6. 검증

1. **그린 것은 모두 맞다**: 그림에서 다시 읽은 연결이 netlist(합친 소자는 펼쳐서)와 어긋나는 곳이 없어야 한다.
2. **보이는 고속 넷은 완전하다**: 화면에 나온 HS 넷의 모든 핀이 이어져 있어야 한다 (일부만 그리면 안 됨).
3. **생략은 분류대로만**: 그리지 않은 넷·블록은 정확히 "숨김" 분류와 같아야 하고, 생략 목록에 모두 나와야 한다.
4. **그림 품질 검사 (모두 0이어야 통과)**: 글씨 겹침, 선이 소자 관통, 대칭 위반, 꼬임, 짧은 꺾임, 접점 근접(20px 이내), 피할 수 있는 교차.
5. **눈 확인**: 화면별 스크린샷, PPT를 그림으로 바꿔 확인.

## 7. 스킬 사용 흐름

1. netlist 받기 → 파싱·자동 분류.
2. **분류 확인 표**를 사용자에게 보여주기 — HS 입력/출력, 클럭, 중요 제어, 생략될 신호·블록. 애매한 것만 질문한다. 답은 annotations로 저장.
3. 개념도 생성 (블록 → 하위 블록 → 유닛).
4. 검증(6장) 전부 통과 확인.
5. 전달: HTML + PPTX + 생략 목록 요약.

## 8. RX AFE 예시에 적용했을 때의 예상 결과 (확인 필요)

| 분류 | 예상 |
|---|---|
| HS 데이터 입력 | RX_INP, RX_INN |
| HS 데이터 출력 | DOUT_EVEN_P/N, DOUT_ODD_P/N |
| HS 데이터 내부 | CTLE1_P/N, CTLE2_P/N, VGA_P/N, E_T2/E_T3, O_T2/O_T3, O_DOUTP/N (DFE 피드백) |
| HS 클럭 | CLK_INP/N → CLKI, CLKIB, CLKQ, CLKQB |
| 중요 제어 (버스) | W<1:4>_<0:3> (DFE 탭 계수) |
| 숨김 (일반 제어) | C<0:2>, R<0:2> (CTLE), G<0:3> (VGA) |
| 숨김 (바이어스) | IREF, VBN, VBP |
| 생략 블록 | BIAS_GEN (HS 연결 없음) |
| 최상위 포트 | 37개 → 약 9개 (RX_IN 2, CLK_IN 2, DOUT 4, W 버스 1) |

예상 모양: 왼쪽 입력 종단 → CTLE1 → CTLE2 → VGA → DFE even/odd(가운데에 W 버스가 위에서), 클럭 분배는 아래에서 DFE로, 출력 4개는 오른쪽.

## 10. 결정이 필요한 것

1. **조절 소자 표현**: 스위치 R/C 뱅크와 IDAC를 지금처럼 **합친 트랜지스터**로 그릴지, 개념도답게 **가변 소자 기호**(화살표 달린 가변 R/C, 가변 전류원)로 바꿀지. (예전에 "bias 트랜지스터는 그대로"로 정했지만 목적이 개념도로 바뀌어 다시 여쭙니다.)
2. **여러 차동쌍의 대칭 방식**: 5.2-2의 **중첩 대칭**(한 축, 꼬리 쌓기)을 기본으로 해도 될지, 논문 그림처럼 **쌍별 대칭 나란히**(main 쌍 옆에 탭 쌍)를 원하시는지.
3. **생략된 신호 보기 토글**: 개념도에서는 안 그리지만, 엔지니어가 확인할 때 켜볼 수 있게 "생략된 신호 보기" 토글을 둘지.
4. **8장 RX AFE 예상 분류**가 의도와 맞는지 (특히 중요 제어가 W 버스뿐인지, 입력 종단·ESD 블록을 개념도에 남길지).
