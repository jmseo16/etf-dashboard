# 넷리스트 기반 High-Speed IO 개념도 그리기 — 도면 계획서 (일반판)

> 스킬 이름: **넷리스트 기반 high speed IO 개념도 그리기** (폴더/식별자: `netlist-hsio-concept-diagram`)
> 상태: 계획서 (스킬화 전). `hspice-schematic`(v1), `hspice-schematic-v2`에서 검증된 방법을 바탕으로 한다.
> 이 문서는 **특정 netlist에 맞춘 규칙을 쓰지 않는다.** 예시(RX AFE)는 부록에만 둔다.

---

## 0. 목적과 우선순위

**목적**: HSPICE/Virtuoso netlist를 받아 **High-Speed IO 회로의 개념을 설명하는 그림**을 그린다.
회로를 빠짐없이 옮기는 회로도가 아니라, "고속 신호가 어디로 흐르고 어떤 구조로 처리되는가"를 보여주는 **개념도**다. 기본은 **덜 그리기**다.

**판단 우선순위** (충돌하면 위가 이긴다)
1. **정확성** — 생략은 허용, 틀리게 그리는 것은 절대 금지.
2. **고속 신호 경로가 한눈에** — 고속 데이터·클럭과 중요 제어만 그린다.
3. **대칭** — 차동 회로는 무조건 좌우 대칭.
4. **최소 선·노드·교차** — 꼬인 선, 군더더기 접점, 짧은 꺾임 금지.
5. **교과서(Razavi) 스타일**.

## 1. 어떤 netlist가 와도 의도대로 그리기 위한 원칙

넷 이름, 셀 이름, 계층 구조는 회사·설계자마다 다르다. 그래서 이 스킬은 아래 다섯 가지로 일반성을 확보한다.

1. **이름이 아니라 구조로 판단한다.**
   소자의 역할(입력 트랜지스터, 꼬리 전류원, 스위치 …)과 신호의 흐름을 연결 구조만으로 정한다. 이름(`CLK`, `VB`, `INP`)은 **확인용 힌트**일 뿐이고, 구조와 이름이 다르면 구조를 따르되 사용자에게 확인한다.
2. **회로 역할 사전으로 판단한다.**
   고속 IO에 나오는 소자 역할(§3.1)과 블록 종류(§3.4)를 구조 특징으로 정의한 사전을 두고, 모든 판단은 이 사전에 비추어 한다. 사전에 없는 구조는 "모름"으로 표시한다.
3. **모르면 묻는다.**
   판단마다 확신도를 매기고, 확신이 낮은 것만 사용자에게 짧게 묻는다 (§3.5). 그림을 그리기 전에 **분류 확인 표**를 한 번 보여주는 것은 필수 단계다. 답은 파일로 저장해 같은 회로는 다시 묻지 않는다.
4. **틀리게 그리지 않는다.**
   그린 것은 모두 netlist와 대조해 검증하고(§6), 실패하면 전달하지 않는다. 판단이 틀려도 "틀린 그림"이 아니라 "덜 그린 그림" 또는 "질문"이 되도록 한다.
5. **테스트 모음으로 일반성을 증명한다.**
   여러 종류의 고속 IO 회로 netlist와 정답 분류를 모아 두고(§7), 규칙을 바꿀 때마다 전부 통과해야 한다. **이름 섞기 테스트**(넷·셀 이름을 무작위로 바꿔도 분류가 같아야 함)로 이름에 기대지 않는다는 것을 확인한다. 새 netlist에서 틀리면 그 회로를 모음에 추가한다.

> **보장 범위**: 처음 보는 구조까지 100% 자동으로 맞힌다고는 보장할 수 없다. 대신 (1) 틀린 그림은 검증이 막고, (2) 애매한 것은 묻고, (3) 사전과 테스트 모음이 커질수록 묻는 횟수가 줄어든다.

## 3. 1단계 — 회로 이해 (분석)

### 3.1 소자 역할 (구조로만 판정)

| 역할 | 구조 특징 |
|---|---|
| 입력 트랜지스터 | 게이트가 신호 넷, 드레인이 부하가 있는 노드, 소스가 tail·전원·degeneration 노드 |
| 꼬리 전류원 | 소스가 전원, 드레인이 다른 트랜지스터들의 소스 노드, 게이트가 바이어스 |
| 부하 | 전원으로 가는 R / 게이트가 고정 전위인 PMOS / 다이오드 연결 / active inductor(게이트에 R) |
| 캐스코드 | 게이트가 바이어스, 소스가 다른 소자의 드레인, 드레인이 출력 |
| cross-coupled 쌍 | g1 = d2, g2 = d1 |
| 리셋·프리차지 | 게이트가 클럭, 소스가 전원, 드레인이 내부 노드 |
| 스위치 | 게이트가 정적 제어, 채널이 소자(R·C·전류원)와 직렬 또는 두 노드 사이 |
| 전달 게이트 | 같은 두 넷 사이의 NMOS+PMOS (게이트가 상보 또는 전원에 묶임) |
| 다이오드·미러 | 게이트 = 드레인 |
| 종단 | 고속 입력에서 공통모드 노드·전원으로 가는 R |
| ESD | 패드에서 전원으로, 게이트가 전원에 묶인 MOS 또는 다이오드 |
| 디커플링 | DC 노드에서 전원으로 가는 C |
| 반복 단위(slice) | 숫자만 다르고 구조가 같은 소자 묶음 (합치기 대상) |

### 3.2 신호 추적 규칙

고속 데이터 입력과 클럭 입력에서 출발해, 계층을 넘나들며 따라간다.

| 지나는 곳 | 규칙 |
|---|---|
| 입력 트랜지스터 | 게이트가 신호 → 드레인이 신호 (소스 팔로워면 소스도) |
| 캐스코드 | 소스가 신호 → 드레인이 신호 |
| cross-coupled 쌍 | 한쪽 드레인이 신호 → 양쪽 모두 |
| 직렬 수동소자 | 두 비전원 노드 사이 R·C·L은 양끝이 같은 분류 (전원·공통모드로 가는 것은 제외) |
| 전달 게이트 | 양끝이 같은 분류 |
| 하위 블록 | 블록 안을 추적해 입력→출력 관계를 구하고 위로 전달 |
| latch · flip-flop · 샘플러 | 데이터 입력이 신호면 출력은 **데이터** (클럭 핀은 출력을 클럭으로 만들지 않는다) |
| 피드백 | 그대로 따라간다 (DFE 탭, FFE 지연 신호) |
| **멈추는 곳** | 전원, 꼬리 전류원·캐스코드의 게이트(바이어스), 스위치 게이트(제어) |

클럭은 클럭 입력에서 같은 규칙으로 따로 추적한다 (버퍼·분주기·위상 보간기 출력 = 클럭). 데이터와 클럭 양쪽에서 도달하는 넷은 확인 대상이다.

### 3.3 신호 분류

| 분류 | 일반 정의 | 그림 |
|---|---|---|
| 고속 데이터 | 데이터 입력에서 추적으로 도달 (출력·피드백 포함) | 선 |
| 고속 클럭 | 클럭 입력에서 추적으로 도달 | 굵은 선 |
| **중요 제어** | **다른 고속 신호(또는 다른 클럭 위상)를 고속 노드에 얼마나·어떤 것을 섞을지 정하는 제어** — 예: DFE·FFE 탭 계수, 위상 보간기 가중치 | 버스 1개 |
| 일반 제어 | 한 경로의 파라미터만 조절 — 이득, 피킹 R/C, 대역폭, 종단·오프셋·바이어스 트림, 동작 모드 | 그리지 않음 |
| 바이어스 | 꼬리 전류원·캐스코드 게이트, 다이오드 노드, 기준 전류, 공통모드 | 그리지 않음 |
| 전원 | 공급·접지 | 블록도 숨김, 유닛 레벨 레일 |

중요 제어 판정은 구조로 한다: 제어 → 스위치/DAC → 어떤 가지의 전류·세기, 그리고 그 가지의 입력이 주 입력과 **다른** 고속 신호이고 출력이 고속 노드에서 **합산**되면 중요 제어. 주 경로 하나의 세기만 바꾸면 일반 제어.

### 3.4 블록 역할 사전 (개념 기호와 그리는 방법)

| 분야 | 블록 | 구조 특징 | 블록도 기호 | 유닛 레벨 |
|---|---|---|---|---|
| RX | 종단 · ESD | 입력에서 공통모드/전원으로 R, 전원 클램프 | 입력선 위 R/ESD 표시 | 소자 그대로 |
| RX | CTLE | 소스 degeneration(R∥C) 차동쌍 | 삼각형 "CTLE" | 대칭, R_S·C_S 가로 (가변이면 가변 기호) |
| RX | VGA | 이득 단을 스위치로 더하는 차동쌍 | 삼각형 "VGA" | 대칭, 이득 단 합쳐서 ×N, 꼬리는 가변 전류원 |
| RX | TIA | 피드백 R가 있는 증폭기 | 삼각형 "TIA" | 대칭, 피드백 R |
| RX/TX | Summer (DFE·FFE) | 여러 차동쌍이 같은 출력에 합산 | Σ | 대칭, 탭 쌍 합쳐서, 탭 전류는 가변 전류원 + 계수 버스 |
| RX | 비교기 · 샘플러 | StrongARM, double-tail, CML 샘플러 | 삼각형 + 클럭 | 교과서 배치 (5.4) |
| 공통 | Latch · DFF | cross-coupled + 클럭 스티어링, 두 latch 직렬 | 박스 LATCH/DFF | latch 교과서 배치 |
| RX | Demux | latch/DFF 병렬 + 위상이 다른 클럭 | 박스 "1:N" | — |
| TX | Serializer (MUX) | 클럭으로 고르는 데이터 경로 | 사다리꼴 MUX | — |
| TX | Driver | CML 차동 출력단, SST/전압 모드 세그먼트 | 삼각형 "DRV" | 대칭, 세그먼트 합쳐서 ×N |
| Clock | 버퍼 · 분주기 · 위상 보간기 | CML/CMOS 버퍼, ÷2 latch 루프, 가중 합산 | 삼각형, "÷2", "PI" | 대칭 |
| 공통 | 바이어스 · DAC · 디지털 제어 | 미러, 전류 DAC, 디코더 | **생략** | — |
| 기타 | 사전에 없음 | — | 박스(셀 이름) + 보이는 핀만 | 대칭 가능하면 대칭, 확인 요청 |

### 3.5 확신도와 질문

- 각 판단(고속 입력, 클럭 입력, 중요 제어, 블록 종류)에 **높음 / 낮음**을 매긴다. 구조와 이름이 맞으면 높음, 어긋나거나 사전에 없으면 낮음.
- 낮음만 질문한다. 질문은 선택지로 짧게: "포트 `X`는 고속 데이터 입력입니까? (예 / 클럭 / 제어 / 바이어스)".
- 반드시 묻는 경우: 고속 입력을 구조로 찾을 수 없음, 정의가 없는 블록(블랙박스)이 고속 경로에 있음, 이름은 클럭인데 데이터 경로에서 도달(또는 반대), MUX 선택 신호가 클럭인지 정적 제어인지 불분명, 제어가 중요/일반 어느 쪽인지 불분명.
- 답은 annotations 파일로 저장한다 (항상 자동 판정보다 우선):
```json
{
  "hs_inputs": ["..."], "clock_inputs": ["..."], "hs_outputs": ["..."],
  "important_controls": ["..."], "show_bias": [], "hide": [],
  "block_roles": {"CELL_NAME": "ctle"}
}
```

## 4. 2단계 — 블록 레벨 연결도 (모든 계층에 같은 규칙)

1. **보이는 넷만 그린다**: 고속 데이터, 고속 클럭, 중요 제어.
2. **나머지는 완전히 지운다**: 선·이름표·블록 핀·셀 포트 모두. 블록 심볼은 보이는 핀만으로 크기를 다시 정한다.
3. **고속 신호와 연결이 없는 블록은 생략**하고 생략 목록에 남긴다.
4. **중요 제어는 기능별 버스 하나**: 같은 기능의 비트를 한 버스로 묶어 블록 위에서 한 줄로. 여러 블록이 받으면 줄기 하나에서 갈라진다.
5. **배치**: 왼쪽→오른쪽 신호 흐름, 피드백은 아래로, 클럭은 아래에서, 중요 제어 버스는 위에서. 주 경로는 한 줄로 곧게.
6. **선 수 최소화**: 줄기 하나 + 가지, 핀 높이 정렬로 꺾임 제거.
7. **하위 블록**: 하위 셀의 핀은 위에서 정해진 분류를 따른다. 같은 셀이 여러 곳에 쓰이면 한 곳에서라도 보이는 핀은 보인다.

## 5. 3단계 — 유닛 레벨 (MOSFET 단위)

### 5.1 개념 기호로 바꾸는 소자 묶음

| 묶음 (구조) | 개념 기호 |
|---|---|
| 스위치로 켜고 끄는 R 뱅크, 두 노드 사이에서 저항으로 쓰는 스위치 MOS 묶음 | **가변 저항** (화살표 관통 R) |
| 스위치로 켜고 끄는 C 뱅크 | **가변 커패시터** |
| 전류 DAC(스위치 + 전류원 반복), 스위치로 켜는 꼬리 전류원 | **가변 전류원** (원 + 화살표) |
| 고정 R ∥ 가변 뱅크 | 가변 소자 하나로 합침 |

- 제어 코드가 **일반 제어**면 코드는 그리지 않는다 (기호의 화살표가 "조절 가능"을 나타냄).
- 제어 코드가 **중요 제어**면 버스가 기호로 들어간다 (DFE 탭 전류원).
- 고정 바이어스 트랜지스터(꼬리 전류원 등)는 트랜지스터 그대로 두고, 게이트에는 짧은 회색 이름표만.

### 5.2 차동 증폭기 = 무조건 대칭
1. **한 축 대칭**: P쪽 절반 왼쪽, N쪽 절반 오른쪽, 정확한 거울상. 자기대칭 소자는 축 위.
2. **여러 차동쌍이 출력을 공유할 때의 배치**: 결정 대기 (§10). 어느 쪽이든 각 차동쌍은 거울상.
3. **degeneration 소자**(고정·가변 R/C)는 두 소스 세로선 사이에 가로로, R 위 C 아래.
4. **공유 게이트는 곧은 가로선 하나**: 거울 쌍의 공유 게이트는 두 게이트 사이 직선. 소자를 돌아가는 배선 금지.
5. **입력·출력도 대칭**: INP 왼쪽 · INN 오른쪽, OUTP 왼쪽 끝 · OUTN 오른쪽 끝.
6. **보이지 않는 넷의 게이트**: 짧은 회색 이름표만 (포트 핀·배선 없음).

### 5.3 선과 노드 규칙 (모든 레벨)
1. **가지는 이미 꺾이는 모서리에서**: 모서리 → T 하나. 기존 접점 20px 이내에 새 접점 금지.
2. **꼬임 금지**: 선 길이가 최단 거리의 1.5배를 넘거나 소자를 돌아가면 다시 배치·배선.
3. **짧은 꺾임(20px 미만) 금지**.
4. **대칭 배선**: P쪽 경로는 N쪽 경로의 거울상.
5. **교차**: 구조상 피할 수 없는 곳만 (cross-coupled X 등).

### 5.4 교과서 배치 템플릿 (사전의 각 블록)
- **CTLE**: 부하(대칭) → 입력쌍 → 소스 사이 가로 R_S·C_S → 꼬리 둘(축 대칭) → 접지.
- **CML latch**: 입력쌍 바깥, cross-coupled 안쪽 X, 클럭쌍 거울, 꼬리 축 위.
- **StrongARM**: 위 리셋 PMOS · cross-coupled PMOS, 중간 cross-coupled NMOS, 아래 입력쌍, 맨 아래 클럭 꼬리. 한 축 대칭.
- **Summer / VGA / Driver**: §5.2-2 결정에 따름.
- 사전에 없는 차동 구조: 일반 대칭 배치 + 확인 요청.

## 6. 검증

1. **그린 것은 모두 맞다**: 그림에서 다시 읽은 연결이 netlist와 어긋나지 않는다 (합친 소자는 펼쳐서, 개념 기호는 "기호 단자 = 묶음의 바깥 넷"으로 대조).
2. **보이는 고속 넷은 완전하다**: 화면의 고속 넷은 그 화면의 모든 핀까지 이어져 있다.
3. **생략은 분류대로만**: 그리지 않은 넷·블록 = 숨김 분류, 생략 목록에 전부 있음.
4. **개념 기호는 정확히 묶음을 대신한다**: 묶음의 모든 소자가 기호 하나에 속하고, 묶음 안쪽 넷이 바깥에서 쓰이지 않는다.
5. **품질 검사 (모두 0)**: 글씨 겹침, 소자 관통, 대칭 위반, 꼬임, 짧은 꺾임, 접점 근접, 피할 수 있는 교차.
6. **눈 확인**: 화면별 스크린샷, PPT를 그림으로 바꿔 확인.

## 7. 일반성 검증 — 테스트 netlist 모음

규칙을 바꿀 때마다 아래 모음 전체가 통과해야 한다. 각 netlist에는 **정답 분류 파일**(고속 입력·클럭·중요 제어·생략 대상·블록 역할)과 기대 성질(대칭, 교차 수 상한)을 붙인다.

| 분야 | 포함할 회로 |
|---|---|
| RX | CML 버퍼, RC-CTLE, active-inductor CTLE, 다단 CTLE+VGA, 차동 TIA, 전류 모드 DFE summer(IDAC 탭), loop-unrolled DFE, StrongARM, double-tail 비교기, CML latch/DFF, 1:2·1:4 demux |
| TX | 2:1·4:1 serializer, FFE(pre/post 탭), CML driver, SST driver(세그먼트) |
| Clock | CML 클럭 버퍼, ÷2 분주기, 위상 보간기, CMOS 클럭 버퍼 체인, I/Q 생성 |
| 공통 | 바이어스 발생기, 종단, ESD, 전류 DAC, R/C 뱅크 |
| 형식 | 깔끔한 이름 버전 + Virtuoso식 이름(net12, I3…) 버전 + **이름 섞기** 버전 |

통과 기준: 분류 정답률 100%(묻기로 해결된 것 포함), 모든 화면 검증 통과, 품질 검사 0, 이름 섞기 버전의 분류가 원본과 같음. 새 netlist에서 틀리면 원인을 사전·규칙에 반영하고 그 netlist를 모음에 추가한다.

## 8. 스킬 사용 흐름

1. netlist 받기 → 파싱 → 소자 역할·신호 추적·블록 역할 판정.
2. **분류 확인 표 제시 (필수)** — 짧게:
   ```
   고속 데이터 입력 : RX_INP, RX_INN            (확신 높음)
   클럭 입력        : CLK_INP, CLK_INN          (확신 높음)
   고속 출력        : DOUT_EVEN_P/N, DOUT_ODD_P/N
   중요 제어 (버스) : W<1:4>_<0:3> — DFE 탭 계수 (확신 높음)
   생략             : 제어 10개, 바이어스 3개, 블록 1개 (BIAS_GEN)
   질문             : (없음)
   ```
   확신 낮은 항목만 질문, 답은 annotations로 저장.
3. 개념도 생성 (블록 → 하위 블록 → 유닛).
4. 검증(§6) 전부 통과 확인.
5. 전달: HTML + PPTX + 생략 목록 요약.

## 10. 결정이 필요한 것

1. **여러 차동쌍이 출력을 공유할 때의 배치** (VGA, summer, driver 세그먼트 등) — 그림 `Q2_layout_options.png` 참고
   - **A. 한 축 대칭 (중첩)**: 모든 쌍을 같은 축 기준으로. 주 쌍은 안쪽, 추가 쌍은 바깥쪽, 꼬리는 축 위에 위아래로 쌓음. 전체가 하나의 거울상, 출력은 양옆으로.
   - **B. 쌍별 대칭 (나란히)**: 쌍마다 자기 축으로 대칭하고 옆으로 나란히 (참고 논문 Fig.4(a) 방식). 출력 버스가 두 높이로 한쪽으로 나감.
