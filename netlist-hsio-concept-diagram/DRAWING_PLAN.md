# 넷리스트 기반 High-Speed IO 개념도 그리기 — 도면 계획서 (일반판)

> 스킬 이름: **넷리스트 기반 high speed IO 개념도 그리기** (폴더/식별자: `netlist-hsio-concept-diagram`)
> 상태: **명세서 v6** — v5의 규칙을 한 곳에 하나씩 정리하고 v5 안의 충돌을 정리함 (부록 C).
> 구현 가이드: 같은 폴더의 `SKILL.md` (수치·템플릿·기준 결과 `reference/rx_afe/`). 규칙이 다르면 이 계획서가 이긴다.
> 이 문서는 **특정 netlist에 맞춘 규칙을 쓰지 않는다.** 예시(RX AFE)는 부록에만 둔다.

## 0. 목적·원칙

### 0.1 목적
HSPICE/Virtuoso netlist를 받아 **High-Speed IO 회로의 개념을 설명하는 그림**을 그린다.
회로를 빠짐없이 옮기는 회로도가 아니라, "고속 신호가 어디로 흐르고 어떤 구조로 처리되는가"를 보여주는 **개념도**다. 기본은 **덜 그리기**다.

### 0.2 판단 우선순위 (충돌하면 위가 이긴다)
1. **정확성** — 생략은 허용, 틀리게 그리는 것은 절대 금지.
2. **고속 신호 경로가 한눈에** — 고속 데이터·클럭과 중요 제어를 그린다. 그 밖의 신호는 §2.5-4 표에서 숨김이 아닌 분류만 그린다.
3. **대칭** — 차동 회로는 무조건 좌우 대칭.
4. **최소 선·노드·교차** — 꼬인 선, 군더더기 접점, 짧은 꺾임 금지.
5. **교과서(Razavi) 스타일**.

### 0.3 일반성 원칙
넷 이름, 셀 이름, 계층 구조는 회사·설계자마다 다르다. 그래서 아래 다섯 가지로 일반성을 확보한다.

1. **이름이 아니라 구조로 판단한다.** 소자의 역할(입력 트랜지스터, 꼬리 전류원, 스위치 …)과 신호의 흐름을 연결 구조만으로 정한다. 이름(`CLK`, `VB`, `INP`)은 **확인용 힌트**일 뿐이고, 구조와 이름이 다르면 구조를 따르되 사용자에게 확인한다.
2. **회로 역할 사전으로 판단한다.** 소자 역할(§2.2)과 블록 종류(§2.6)를 구조 특징으로 정의한 사전을 두고, 모든 판단은 이 사전에 비추어 한다. 사전에 없는 구조는 "모름"으로 표시한다.
3. **모르면 묻는다.** 판단마다 확신도를 매기고, 확신이 낮은 것만 사용자에게 짧게 묻는다(§2.7). 그림을 그리기 전에 **분류 확인 표**를 한 번 보여주는 것은 필수 단계다(§1.5). 답은 파일로 저장해 같은 회로는 다시 묻지 않는다.
4. **틀리게 그리지 않는다.** 그린 것은 모두 netlist와 대조해 검증하고(§4.1-1~5), 실패하면 전달하지 않는다. 판단이 틀려도 "틀린 그림"이 아니라 "덜 그린 그림" 또는 "질문"이 되도록 한다.
5. **테스트 모음으로 일반성을 증명한다** (§4.4). **이름 가림 테스트**(넷·셀 이름을 무작위로 바꿔도 분류가 같아야 함)로 이름에 기대지 않는다는 것을 확인한다.

> **보장 범위**: 처음 보는 구조까지 100% 자동으로 맞힌다고는 보장할 수 없다. 대신 (1) 틀린 그림은 검증이 막고, (2) 애매한 것은 묻고, (3) 사전과 테스트 모음이 커질수록 묻는 횟수가 줄어든다.

### 1.3 화면 id·제목·사이드 패널
1. **화면 id**: 블록 `b_<셀 짧은 이름>`, 유닛 `u_<셀 짧은 이름>`(가상 블록은 `u_<부모>_<역할>`), 보정 루프 화면(§3.1-6)은 고리가 한 셀 안에 있으면 그 셀의 블록 화면이 곧 루프 화면(id `b_<셀 짧은 이름>`), 여러 셀에 걸치면 고리를 품은 가장 작은 공통 셀 이름으로 `b_<셀 짧은 이름>_loop`.
2. **제목**: `<셀> — 블록 레벨` / `<셀> — unit level (<역할>)` / 보정 루프 화면은 `<셀> — 블록 레벨 (보정 루프)`(여러 셀에 걸친 고리는 공통 셀 이름).
3. **사이드 패널 순서**: 이 화면 → 생략 목록 → 주석 → 분류 요약 → 질문(가정한 답) → 모든 화면.

### 1.4 선·노드 (모든 화면)
1. **선 굵기·모양**: 모든 배선은 같은 굵기(1.6px)의 **실선**이다 — 고속 데이터·클럭·버스·느린 신호·상태 출력 구분 없음. 점선은 쓰지 않는다. 버스는 굵기가 아니라 사선과 이름으로 구분한다(§3.5-2).
2. **차동 신호**: P/N 두 선.
3. **버스 이름은 `<MSB:LSB>`**: `W<4:1>_<3:0>`, `M_G<3:0>_P`, `din<3:0>`. 2차원도 각 차원 MSB 먼저. 그림·표의 버스 이름은 언제나 이 형식이다 (비트 표기 인식은 §2.5-7).
4. **가지는 이미 꺾이는 모서리에서**: 모서리 → T 하나. 기존 접점에서 **20px 미만** 거리에 새 접점 금지 (20px 이상은 허용).
5. **꼬임 금지**: 선 길이가 두 끝점의 **가로+세로 거리**(|Δx|+|Δy|)의 1.5배를 넘거나 소자를 돌아가면 꼬임이다. 블록 레벨은 이름표로 바꾸고(§3.5-1), 유닛 레벨은 다시 배치한다.
6. **짧은 꺾임 금지**: 꺾인 선분 길이가 **20px 미만**이면 위반 (20px 이상은 허용).
7. **접점**: 한 점에 선분 3개까지(4방향 금지). 서로 다른 넷의 선 끝이 같은 직선 위에 있으면 40px 이상 떨어뜨린다.
8. **대칭 배선**: P쪽 경로는 N쪽 경로의 거울상.
9. **교차는 허용 목록에 있는 것만**: 블록 레벨은 **0개**(교차가 생기면 이름표, §3.5-1). 유닛 레벨은 템플릿마다 정한 것만 — cross-coupled 쌍마다 X 1개, 쌍별 대칭(§3.3-2)은 쌍마다 1개, CML latch의 클럭 스티어링 1개. 이 밖의 교차는 전부 위반이다.

### 1.5 사용 흐름
1. netlist 받기 → 파싱 → 소자 역할·신호 추적·블록 역할 판정 (§2).
2. **분류 확인 표 제시 (필수)** — 짧게:
   ```
   고속 데이터 입력 : RX_INP, RX_INN            (확신 높음)
   클럭 입력        : CLK_INP, CLK_INN          (확신 높음)
   고속 출력        : DOUT_EVEN_P/N, DOUT_ODD_P/N
   중요 제어 (버스) : W<4:1>_<3:0> — DFE 탭 계수 (확신 높음)
   생략             : 제어 10개, 바이어스 3개, 블록 1개 (BIAS_GEN)
   질문             : (없음)
   ```
   확신 낮은 항목만 질문, 답은 annotations로 저장 (§2.7).
3. 개념도 생성 (블록 → 하위 블록 → 유닛, §3).
4. 검증(§4.1-1~5) 전부 통과 확인.
5. 전달: HTML + PPTX + 생략 목록 요약.

## 2. 분석

### 2.1 파싱·전원
파싱과 평탄화 절차는 SKILL §4.1–§4.2.
1. **전원이 여러 개**: PMOS 벌크에 쓰인 넷은 모두 전원, NMOS 벌크에 쓰인 넷은 모두 접지 (vdd, vddq 둘 다 전원).
2. 벌크가 이상하게 묶인 소자(NMOS 벌크가 전원 등)는 그대로 그리고 주석·확인 질문 (netlist 오류일 수 있음, §2.7-4).

### 2.2 소자 역할 (구조로만 판정)
| 역할 | 구조 특징 |
|---|---|
| 입력 트랜지스터 | 게이트가 신호 넷, 드레인이 부하가 있는 노드, 소스가 tail·전원·degeneration 노드 |
| 꼬리 전류원 | 소스가 전원, 드레인이 다른 트랜지스터들의 소스 노드, 게이트가 바이어스, 먹이는 쌍과 **같은 극성** (NMOS 쌍 ↔ NMOS 꼬리) |
| 부하 | 전원으로 가는 R / 게이트가 고정 전위인 PMOS / 다이오드 연결 / active inductor(게이트에 R) |
| 캐스코드 | 게이트가 바이어스, 소스가 다른 소자의 드레인, 드레인이 출력 |
| cross-coupled 쌍 | g1 = d2, g2 = d1 |
| 리셋·프리차지 | 게이트가 클럭, 소스가 전원, 드레인이 내부 노드 |
| 클럭 꼬리 | 꼬리 전류원과 같은 구조(같은 극성 포함)인데 게이트가 클럭 (StrongARM·동적 비교기의 꼬리). 극성이 반대면 리셋·프리차지 |
| 클럭 스티어링 쌍 | 게이트가 클럭 P/N, 두 드레인이 각각 다른 차동쌍의 공통 소스 노드 (드레인에 부하 없음), 소스 공유 (CML latch의 클럭쌍) |
| 정적 CMOS 게이트 | 같은 출력 넷을 구동하는 풀업·풀다운 사슬의 게이트 집합이 같다 — **제어·바이어스 게이트(헤더/풋터 스위치, 다리 enable)는 빼고** 비교. 인버터·NAND·NOR·스택형 모두. 리셋·꼬리 판정보다 **먼저** 인식 |
| 클럭드 인버터 / C2MOS | 출력에 가까운 직렬 PMOS·NMOS의 게이트가 상보 클럭 쌍, 레일 쪽 게이트가 데이터. 출력 노드에 인버터 귀환이 있으면 latch |
| tristate / MUX | 클럭드 인버터와 같은 구조인데 상보 쌍이 정적 선택 신호 → 선택 게이트 |
| 스위치 | 게이트가 정적 제어, 채널이 소자(R·C·전류원)와 직렬 또는 두 노드 사이 |
| 전달 게이트 | 같은 두 넷 사이의 NMOS+PMOS (게이트가 상보 또는 전원에 묶임). 세 가지: **항상 켜짐** — 게이트가 켜는 전원(NMOS→전원, PMOS→접지; §2.1)에 묶임 = **연결**로 추적, 질문 없음 / **항상 꺼짐** — 끄는 전원(NMOS→접지, PMOS→전원)에 묶임 = **끊김** / **상보 선택 신호** = 선택 스위치 |
| 다이오드 · 전류 미러 | 게이트 = 드레인. 다이오드 노드 = 바이어스, 미러 게이트에서 추적 멈춤(§2.3-3) |
| 종단 | 고속 입력에서 공통모드 노드·전원으로 가는 R |
| ESD | 패드에서 전원으로, 게이트가 전원에 묶인 MOS 또는 다이오드 |
| 디커플링 | DC 노드에서 전원으로 가는 C |
| 반복 단위(slice) | 숫자만 다르고 구조가 같은 소자 묶음 (합치기 대상, §3.1-7) |

- **공통모드 노드**: 차동쌍 두 선에서 **같은 값 R 정확히 두 개**가 모이고 다른 신호 경로가 없는 노드만. (R 여러 개가 모이는 SST 출력 노드는 신호다.)

### 2.3 고속 신호 추적
1. 고속 데이터 입력과 클럭 입력에서 출발해, 계층을 넘나들며 따라간다. 클럭은 클럭 입력에서 같은 규칙으로 **따로** 추적한다 (버퍼·분주기·위상 보간기 출력 = 클럭, 분주기는 7항). 데이터와 클럭 양쪽에서 도달하는 넷은 확인 대상이다.
2. 지나는 곳마다:

| 지나는 곳 | 규칙 |
|---|---|
| 입력 트랜지스터 | 게이트가 신호 → 드레인이 신호 (소스 팔로워면 소스도) |
| 캐스코드 · 스택 트랜지스터 | 소스가 신호(전원 아님) → 드레인이 신호. 게이트가 바이어스든 다른 신호든 같다 (예: StrongARM의 cross-coupled NMOS — 소스가 입력쌍 드레인) |
| 정적 CMOS 게이트 | 입력이 신호 → 출력이 같은 분류 (인버터 체인 = 버퍼) |
| cross-coupled 쌍 | 한쪽 드레인이 신호 → 양쪽 모두 |
| 직렬 수동소자 | 두 비전원 노드 사이 R·C·L은 양끝이 같은 분류 (전원·공통모드로 가는 것은 제외) |
| 전달 게이트 | 켜질 수 있으면 양끝이 같은 분류. **항상 꺼진 것은 끊긴 것**으로 보고 전달하지 않는다 (확인 질문: "netlist 오류인가요?", §2.7-4) |
| 하위 블록 | 블록 안을 추적해 입력→출력 관계를 구하고 위로 전달 |
| latch · flip-flop · 샘플러 | 출력의 분류 = **데이터 입력의 분류** (데이터가 들어오면 데이터, 클럭이 들어오면 클럭 — 분주기·I/Q 생성, 분주기 출력은 7항). 클럭 핀은 출력을 클럭으로 만들지 않는다 |
| 피드백 | 그대로 따라간다 (DFE 탭, FFE 지연 신호) |

3. **멈추는 곳**: 전원, 꼬리 전류원·캐스코드의 게이트(바이어스), 스위치 게이트(제어), 미러 게이트, 항상 꺼진 전달 게이트, **RC 저역통과**(직렬 R 뒤 노드에 접지/전원으로 C, 또는 그 사다리 — 예외는 6항), **클럭 역할 게이트**(4항). 클럭 역할 게이트 소자들의 드레인은 클럭이 아니라 데이터 경로의 내부 노드다.
4. **클럭 역할 게이트** (클럭 꼬리·클럭 스티어링·리셋·프리차지 등, §2.2). 순환 금지 — 다음 구조가 먼저 있어야 클럭 역할이다:
   - ① 클럭 꼬리: 먹이는 쌍이 cross-coupled 노드나 latch 노드로 이어짐
   - ② 리셋·프리차지: 클럭 꼬리와 게이트를 공유하고 cross-coupled 노드 옆
   - ③ 스티어링: 드레인이 다른 쌍의 공통 소스 (부하 없음)
   - ④ C2MOS latch의 상보 게이트
   - ⑤ TG latch/DFF의 상보 게이트

   **cross-coupled 소자는 먼저 빼고** 판정한다. 이 판정에는 넷 이름을 쓰지 않는다.
5. **느린 신호(검출)**: RC 저역통과 뒤에서 시작해 추적되는 넷(평균값, 비교기 판정, 루프 필터)은 "느린 신호"로 분류한다(그림 §2.5-4). 이 신호를 받는 비교기의 클럭은 클럭으로 둔다.
6. **배선 RC 예외**: 직렬 R + 접지 C라도 τ=RC가 단위 간격의 1/20보다 작고(또는 10ps 미만) 뒤에서 같은 신호를 다시 구동하면 **배선 RC** — 추적을 계속한다 (그림 §3.4-6).
7. **분주기**: latch·DFF의 데이터 입력이 (인버터를 거쳐) 자기 출력에서만 오고 클럭 핀에 클럭이 들어오면 분주기다. 분주기 출력이 클럭인 것은 그 출력이 다른 블록의 클럭 핀을 구동할 때만이다.
8. **리플 카운터 예외**: 각 단이 앞 단 출력으로 클럭되는 사슬의 Q는 **계수(상태 출력)**이지 클럭이 아니다.
9. **사건 플래그**: D가 상수이고 클럭·리셋이 있는 플립플롭의 출력은 sticky 상태 출력(상수 아님).
10. **포트 방향**: 블록 안 출력단이 구동하는 포트는 출력. 같은 넷을 안에서 다시 읽어도(루프백 탭) 입력으로 세지 않는다.
11. **의사 차동쌍**: 한쪽 게이트가 기준 전압인 쌍은 두 드레인 모두 신호.
12. **비동기 set/reset 핀**은 데이터 추적 대상이 아니다.
13. **미구동 넷**: 구동원이 없고 고속 핀에만 닿는 넷(꺼진 전달 게이트 뒤 등)은 "고속(미구동)" — 그 핀 분류로 그리고 이름표로 끝내며 확인 질문을 남긴다(§2.7-4).

### 2.4 입력 포트 판정
1. **고속 입력 후보는 차동 포트 쌍 또는 종단·ESD가 붙은 패드**만. 단일 디지털 포트는 아래 판정으로 데이터가 되지 않는다.
2. 입력 포트에서 §2.3 규칙으로 추적했을 때:
   - **클럭 역할 게이트**(§2.3-4)에 하나라도 도달 → **클럭 입력** (latch 데이터 입력에도 닿을 수 있음: 분주기·I/Q)
   - 클럭 역할 게이트에는 닿지 않고, 입력 트랜지스터를 거쳐 latch·샘플러의 **데이터 입력**에 도달 → **데이터 입력**
   - 둘 다 아님 → 질문 (§2.7)
3. 클럭이 버퍼 사슬과 RC 저역통과를 거쳐 비교기 데이터 입력에 닿아도 데이터 입력이 아니다 (RC 저역통과에서 멈춤, §2.3-3).
4. 이름(`CLK`, `IN` 등)은 판정에 쓰지 않고 **확신도에만** 쓴다: 구조와 이름이 맞으면 높음, 어긋나면 낮음 → 질문.

### 2.5 제어·비고속 신호 분류
고속 데이터·클럭 추적(§2.3)이 닿지 않은 넷은 이 절 하나로 분류한다.

1. **근거는 끝점·출처·모양 세 가지뿐이다.**
   - **끝점**: 그 넷이 정적 논리(인버터·NAND·NOR·AND·OR·XOR), 레벨 시프터, 디코더, 고속 클럭이 아닌 latch·레지스터를 지나 **결국 닿는 소자 핀의 종류**. 추적은 고속 클럭으로 동작하는 플립플롭·샘플러, 비교기 입력, 고속 데이터와 함께 들어가는 게이트에서 멈추고 그 핀이 끝점이 된다.
   - **출처**: 그 넷이 어디서 오는가 — 최상위 포트, 레지스터(고속 클럭이 아닌 상태 소자), **루프**(6항 O2), 상수(전원·접지·tie 셀).
   - **모양**: 비트 수, 패드·ESD 여부, 출력 포트 여부.
2. **이름은 판정에 쓰지 않는다.** 구조로 정한 뒤 확신도에만 쓴다(§2.7). 구조로 정할 수 없을 때만 이름으로 가정하고 질문을 남긴다. 이름과 구조가 반대 뜻이면 구조를 따르고 질문한다.
3. 끝점이 여러 개면 **끝점 표(5항)에서 가장 위에 있는 분류**가 이긴다. 같은 넷이 출력 포트이기도 하면 O1(6항)을 함께 적용한다(선 하나에 출력 포트 + 버스).
4. **분류 표** — 모든 신호 분류와 그리는 방법:

| 분류 | 판정 | 그림 |
|---|---|---|
| 고속 데이터 | 데이터 입력에서 추적(§2.3)으로 도달 (출력·피드백 포함) | 선 |
| 고속 클럭 | 클럭 입력에서 추적으로 도달 | 선 (데이터와 같은 굵기) |
| 느린 신호(검출) | RC 저역통과 뒤에서 시작해 추적되는 넷 (§2.3-5) | 실선. 선 모양으로 구분하지 않고 분류 표와 화면 설명에만 표시 |
| 워드 속도 디지털 | 1:N 디시리얼라이저의 워드 출력 뒤 / N:1 직렬화기의 워드 입력 앞의 데이터와 그것만 다루는 로직 (PRBS 생성·검사기, 카운터, 잠금 검출) | 박스로만 (§3.1-5) |
| 중요 제어 | 끝점 K1–K6, 출처가 루프인 K7, 패턴 생성 슬라이스의 1비트 입력(P2) | 끝점 표(5항)의 "그림" 열 |
| 일반 제어 | 출처가 포트·레지스터인 K7(트림), K10 | 숨김 |
| 명령 | K8 | 받는 블록으로 가는 실선 한 줄 + 이름표, 버스 아님 |
| 상태 출력 | O1 | 실선 + 출력 포트. 모니터 출력은 이름 옆 "(mon)". 선 모양으로 구분하지 않고 분류 표와 화면 설명에만 표시 |
| 시험 입력 | K9 | 한 줄, 그 (mon) 출력 옆 |
| 기준 | 외부 기준 패드 P1, 기준 전압 (6항) | 회색 실선 + 이름표, 받는 블록의 둘째 입력 핀. 기준 전압을 만드는 DAC는 "VREF" 박스 |
| 바이어스 | 꼬리 전류원·캐스코드 게이트, 다이오드 노드, 기준 전류, 공통모드(§2.2). 끝점으로는 K11 | 숨김 |
| 전원 | 공급·접지 (§2.1) | 블록 화면 숨김, 유닛 화면 레일 (상수 입력은 §3.5-3) |

5. **끝점 표** — 넷이 결국 닿는 곳으로 분류한다:

| # | 넷이 결국 닿는 곳 (구조) | 분류 | 그림 |
|---|---|---|---|
| K1 | 여러 고속 신호(또는 여러 클럭 위상)를 한 노드에 합하는 가지의 전류·세기 | 중요 (a) 가중치 | 버스 |
| K2 | 서로 다른 고속 원천(데이터·클럭·루프백) 중 하나를 고르는 MUX·상보 선택 스위치의 선택 핀 | 중요 (b) 선택 | 선택 핀까지 선 |
| K3 | 고속 경로를 끊거나 잇는 곳: 고속 신호와 함께 들어가는 정적 게이트의 다른 입력(클럭 게이트), 고속 경로의 직렬 스위치, 고속 블록의 꼬리·전원 스위치, 패드 드라이버를 끄는 곳(출력 enable). **그리는 보정 루프(§3.1-6)를 켜고 끄는 곳도 포함** | 중요 (f) 켜기 | 1비트 = 한 줄, 여러 비트 = 버스 |
| K4 | 패드나 고속 노드에 R을 직렬로 거는 스위치 (종단) | 중요 (f) 종단 | 버스 (1비트면 한 줄) |
| K5 | 출력이 같은 패드·고속 출력 노드에 묶인 **병렬 다리**를 켜는 곳 (세기) | 중요 (f) 세기 | 버스 |
| K6 | 비교기·샘플러의 **기준 입력 레벨**을 정하는 코드, 여러 비트 경로(또는 여러 슬라이스)가 **공유**하는 이득 코드 | 중요 (d) | 버스 |
| K7 | 고속 경로 **안쪽 노드**(패드·고속 출력이 아닌 곳)에 C·R·작은 전류를 더해 지연·에지·듀티·오프셋·피킹·이득을 바꾸는 곳 | 출처가 **루프**면 중요 (c), 포트·레지스터면 **일반(트림)** | 중요 = 버스(아날로그면 한 줄), 일반 = 숨김 |
| K8 | 상태 소자(FSM·카운터·레지스터)의 동작을 **한 번** 일으키는 동기 입력(상태 소자의 시작·적재(load)·갱신(update)·동기 set/clear 조건에만 닿고 고속 경로·K3–K7 끝점에는 닿지 않는 1비트). 비동기 set/reset 핀은 K10 | 명령 | 한 줄, 버스 아님 |
| K9 | **모니터 출력 쪽으로만** 가는 경로(그 넷의 끝점이 전부 (mon) 출력을 만드는 게이트·버퍼) | 시험 입력 | 한 줄, 그 (mon) 출력 옆 |
| K10 | 정상 코드 대신 고정값을 넣는 MUX의 선택·데이터(오버라이드), 비동기 set/reset 핀, 한 경로 안의 아날로그 동작 모드(초퍼·저전력) | 일반 | 숨김 |
| K11 | 바이어스 노드(미러 게이트, 꼬리·캐스코드 게이트) | 바이어스 | 숨김 |

   - K3의 "끊거나 잇는다"는 그 핀 값에 따라 고속 신호가 출력에 **나타나거나 사라지는** 것이다. 세기·지연만 바꾸면 K5·K7이다.
   - 공유하지 않는 이득 코드는 K7이다 (출처가 포트·레지스터면 일반 제어).

6. **출처·모양 규칙**
   - **O1 상태 출력**: 최상위(또는 그 화면의) **출력 포트**를 상태 소자(카운터·레지스터·FSM·플래그 플립플롭)가 구동하고 고속 데이터·클럭이 아니면 **상태 출력** — 다비트 코드도 포함. 같은 넷이 안에서 K5 등에 쓰이면 그 경로는 그 끝점 분류로 그린다.
   - **O2 루프 출처**: 넷을 거꾸로 따라가 **검출기**(비교기, 또는 RC 저역통과·적분 C 뒤의 판정)의 출력에서 상태 소자나 적분 C를 거쳐 왔고, 그 검출기의 입력이 이 넷이 바꾸는 노드(또는 그 노드에서 만든 신호)로 돌아오면 **루프**다. 디지털 코드든 아날로그 전압이든 같다. 루프 안의 아날로그 넷은 느린 신호 규칙(§2.3-5, 실선)도 그대로 적용한다.
   - **P1 외부 기준 패드**: ESD가 붙은 포트인데 고속 데이터·클럭 추적이 닿지 않고, 비교기·OTA 입력이나 보정 다리에**만** 닿으면 **기준**. 바이어스 생성(미러)에만 닿는 패드는 바이어스(K11, 숨김).
   - **기준 전압**: 추적되지 않은 넷이 비교기·프리앰프·샘플러의 한쪽 입력으로 들어가 판정 기준이 되면 기준 전압 — 회색 실선, 만드는 DAC는 VREF 박스 (그림은 4항 표 '기준').
   - **P2 패턴 생성 슬라이스**: 직렬화기(클럭으로 고르는 MUX)의 데이터 입력이 **전부** 상수, 또는 1비트 입력 하나와 그 반전으로만 채워지면 패턴 생성 슬라이스다. 출력은 **클럭(스트로브)**, 그 1비트 입력은 **중요 (e)**. 고속 데이터 입력이 아니다(§2.4-1과 같은 방향).
7. **버스 묶기**
   - 같은 기능의 비트는 버스 하나. 이름이 달라 하나의 버스 이름으로 펼칠 수 없으면 버스를 나눈다.
   - netlist의 비트 표기가 `<n>`이 아니어도(`[n]`, `_n`, 숫자 꼬리 등) 이름 줄기가 같고 정수가 연속이면 버스로 묶는다. 이름은 §1.4-3 형식. 표기를 추측했으면(예: `_n`) 분류 표에 적고 확신도 낮음.
   - 이름 줄기가 같아도 **끝점 분류가 다르면** 버스를 나눈다.
8. **제어 허브·디코더**
   - **제어 허브**(입력이 주로 제어 포트이고 출력이 여러 블록의 제어 핀으로 가는 디코더·레지스터·FSM)의 출력은 허브 이름과 상관없이 **그 출력의 끝점**으로 분류한다.
   - 제어 허브·디코더·FSM·레지스터 블록은 출력 중 **하나라도 그리는 분류**(K1–K6, 출처가 루프인 K7, K8 명령, K9 시험 입력, O1 상태 출력, P2 패턴)이면 박스로 그린다.
   - 출력이 모두 숨기는 분류(출처가 포트·레지스터인 K7, K10, K11)이면 생략한다 (생략 목록 문구 "블록 (셀) — 일반 제어만 만듦", §3.5-5).
   - 중요 제어를 만드는 디코더는 생략하지 않고 **"DEC" 박스**로 그린다 (입력 코드 버스 → DEC → 출력 버스). 중요 제어를 만드는 그 밖의 허브(레지스터·FSM)도 같은 꼴로 그린다: 입력 버스 → 박스 → 출력 버스.
9. **분류 확인 표**(`classification.md`)에는 숨기지 않은 제어 넷마다, 그리고 숨긴 다비트 제어마다 **끝점 번호(K#)·끝점 핀 하나(인스턴스.핀)·출처**를 적는다. 새 회로 종류가 오면 먼저 비고속 분류(기준 전압, 상태·명령, 워드 속도 디지털, 이득·VREF 코드)에 해당하는 포트가 있는지 분류 확인 표에 따로 적는다.

### 2.6 블록 역할 사전과 사전 대응
1. **사전** (개념 기호와 그리는 방법):

| 분야 | 블록 | 구조 특징 | 블록도 기호 | 유닛 레벨 |
|---|---|---|---|---|
| RX | 종단 · ESD | 입력에서 공통모드/전원으로 R, 전원 클램프 | 입력선 위 R/ESD 표시 | 소자 그대로 |
| RX | CTLE | C가 영점을 만드는 소스 degeneration 차동쌍 (가변 C 또는 피킹용 큰 C) | 삼각형 "CTLE" | 대칭, R_S·C_S 가로 (가변이면 가변 기호) |
| RX | VGA | 이득 단을 스위치로 더하는 차동쌍, 또는 코드로 degeneration R을 바꾸는 차동쌍 (C는 고정·작음) | 삼각형 "VGA" | 대칭, 이득 단 합쳐서 ×N, 꼬리는 가변 전류원 |
| RX | TIA | 피드백 R가 있는 증폭기 | 삼각형 "TIA" | 대칭, 피드백 R |
| RX/TX | Summer (DFE·FFE) | 여러 차동쌍이 같은 출력에 합산 | Σ | 대칭, 탭 쌍 합쳐서, 탭 전류는 가변 전류원 + 계수 버스 |
| RX | 비교기 · 샘플러 | StrongARM, double-tail, CML 샘플러 | 삼각형 + 클럭 | 교과서 배치 (§3.3-9) |
| 공통 | Latch · DFF | latch: cross-coupled 쌍 + 클럭 스티어링, 또는 클럭드 인버터(C2MOS)나 상보 클럭이 여닫는 전달 게이트로 닫히는 귀환 루프 (§2.2 역할). DFF: 그런 latch 두 개를 반대 클럭으로 직렬 | 박스 LATCH/DFF | latch 교과서 배치 |
| RX | Demux | latch/DFF 병렬 + 위상이 다른 클럭 | 박스 "1:N" | — |
| TX | Serializer (MUX) | 클럭으로 고르는 데이터 경로 | 사다리꼴 MUX | — |
| TX | Driver | CML 차동 출력단, SST/전압 모드 세그먼트 | 삼각형 "DRV" | 대칭, 세그먼트 합쳐서 ×N |
| Clock | 버퍼 · 분주기 · 위상 보간기 | CML/CMOS 버퍼, ÷2 latch 루프, 가중 합산 | 삼각형, "÷2", "PI" | 대칭 |
| 공통 | CML→CMOS 변환기 | — | 삼각형 "C2C" | — |
| 공통 | OTA | — | 삼각형 "OTA" | — |
| 공통 | RC 평균기 | — | 박스 "LPF" | — |
| 공통 | DCC 조정단 | 다리 헤더/풋터로 세기를 바꾸는 인버터 | 가변 세기 인버터 (§3.4-6) | — |
| 공통 | 바이어스 · DAC · 디지털 제어 | 미러, 전류 DAC, 디코더 | **생략**. 예외: 출력 중 하나라도 그리는 분류인 제어 허브·디코더·FSM·레지스터(박스, §2.5-8), 워드 속도 디지털(박스로만, §3.1-5), 기준 전압 DAC "VREF" 박스(§2.5-4), 보정 루프에 속한 것(§3.1-6) | — |
| 공통 | 복합 블록 | 하위 블록이 **모두** 사전에 있는 블록 (예: DFE 슬라이스, 클럭 트리) | 박스(셀 이름) + 보이는 핀만, 확신 높음 (묻지 않음) | — |
| 기타 | 사전에 없음 | — | 박스(셀 이름) + 보이는 핀만 | 대칭 가능하면 대칭, 확인 요청 |

   - 다음도 사전에 있다 — 묻지 않는다: 논리 게이트(INV/NAND/NOR/AND/OR/XOR), SR latch, 클럭 게이팅 셀(ICG), 지연 셀(DLY), 레벨 시프터(LS), CML→CMOS(C2C), OTA. C2MOS latch와 TG latch/DFF는 Latch·DFF 행이다.
2. **이름과 구조가 다르면 구조로 고르고 묻는다** (§0.3-1). 예: 이름은 ÷2인데 latch 루프가 없으면 ÷2 기호가 아니라 LATCH 박스 2개로 그리고 질문한다. VGA·CTLE는 이름과 구조가 맞으면 묻지 않는다.
3. **사전 대응**: 블록을 사전의 한 행으로 그리려면 **그 행의 구조 특징이 모두** 그 블록에 있어야 한다. 일부만 맞으면 "사전에 없음"(§2.7)으로 보고 **소자 구성을 짧게 적은 이름의 일반 박스**로 그린 뒤 질문한다 (그 이름은 블록 제목, §4.1-14). 기본 소자(인버터·NAND·MUX·차동쌍)로 쪼개면 비슷해 보여도 사전 행의 특징이 하나라도 빠지면 다른 블록이다.
4. **`out/block_dictionary.json`** (AGENT 2): 그린 블록(셀)마다 `{"cell", "row" (사전 행 또는 "general"), "matched_features": [...], "missing_features": [...], "confidence"}`. `missing_features`가 있는데 사전 기호로 그렸으면 불통과.

### 2.7 확신도·질문
1. 각 판단(고속 입력, 클럭 입력, 중요 제어, 블록 종류)에 **높음 / 낮음**을 매긴다. 구조와 이름이 맞으면 높음, 어긋나거나 사전에 없으면 낮음.
2. 낮음만 질문한다. 질문은 선택지로 짧게, **템플릿 문장**으로 만든다 (회로 이름을 코드에 박지 않는다).
   - 예: "포트 `X`는 고속 데이터 입력입니까? (예 / 클럭 / 제어 / 바이어스)"
   - 구조와 이름이 다를 때: "`<항목>`: 구조는 `<A>`인데 이름/기능은 `<B>`입니다. (A로 / B로)"
3. **반드시 묻는 경우**: 고속 입력을 구조로 찾을 수 없음, 정의가 없는 블록(블랙박스)이 고속 경로에 있음, 이름은 클럭인데 데이터 경로에서 도달(또는 반대), MUX 선택 신호가 클럭인지 정적 제어인지 불분명, 제어가 중요/일반 어느 쪽인지 불분명.
4. **규칙이 판정을 정한 경우에는 묻지 않는다** (예: 미사용 출력). 예외는 하나 — **netlist 오류일 수 있는 것**(항상 꺼진 전달 게이트 §2.3-2, 짝 없는 소자 §3.3-6, 이상하게 묶인 벌크 §2.1-2, 미구동 고속 넷 §2.3-13)은 규칙대로 그리고 확인 질문을 남긴다. 그 밖에 "질문"·"확인 요청"이 붙은 규칙(사전에 없는 블록, 사전에 일부만 맞는 블록, 데이터·클럭 양쪽에서 닿는 넷 등)은 규칙이 뜻을 정하지 못하는 경우라 그대로 묻는다.
5. 구조 규칙과 그럴듯함이 충돌하면 **구조 규칙대로 분류하고 질문**한다. 사용자가 없으면 구조 답을 쓰되, 규칙이 보강된 경우(예: §2.3-3 RC 저역통과 멈춤, §2.3-5 느린 신호, §2.3-7 분주기, §2.3-13 미구동 넷, §2.4-3)는 보강된 규칙을 따른다. 구조 답을 쓰면 클럭·고속 입력이 사라지는 경우에는 그럴듯한 답을 쓰고 질문을 남긴다.
6. 답은 annotations 파일로 저장한다 (항상 자동 판정보다 우선):
```json
{
  "hs_inputs": ["..."], "clock_inputs": ["..."], "hs_outputs": ["..."],
  "important_controls": ["..."], "show_bias": [], "hide": [],
  "block_roles": {"CELL_NAME": "ctle"}
}
```

## 3. 그리기

### 3.1 화면 구성
1. **화면 종류**: 블록 화면(§3.2, 모든 계층에 같은 규칙)과 유닛 화면(MOSFET 단위, §3.3). 화면 목록을 만드는 절차는 SKILL §5.
2. **트랜지스터와 하위 블록이 섞인 셀**: 트랜지스터를 채널 연결 덩어리별로 묶어 **자동 가상 블록**으로 만든다. 블록 화면에서는 박스(또는 사전의 기호)로 그리고, 클릭하면 그 덩어리의 유닛 화면으로 들어간다. 종단·ESD처럼 사전에서 "입력선 위 표시"로 정한 것은 블록을 만들지 않고 표시만 한다.
3. **같은 가상 블록이 여럿이면 화면 하나**, 핀 이름은 일반 이름(in/out), 인스턴스별 넷은 범례 표.
4. **생략하는 블록**: 고속 신호와 연결이 없는 블록(예: 바이어스 발생기)은 생략하고 생략 목록에 남긴다(문구 §3.5-5). 예외: 출력 중 하나라도 그리는 분류(K1–K6, 출처가 루프인 K7, K8, K9, O1, P2)인 제어 허브·디코더·FSM·레지스터(§2.5-8), 워드 속도 디지털 박스(5항), 기준 전압 DAC "VREF" 박스(§2.5-4), 보정 루프(6항).
5. **박스로만 그리는 블록**: 워드 속도 디지털(§2.5-4)은 최상위에 박스로만 그리고 하위 화면을 만들지 않는다. 박스로만 그리는 것은 워드 속도 디지털과, 루프에 속하지 않는 레지스터·디코더·FSM뿐이다.
6. **보정 루프 화면 (L1)**: 검출기 → 상태 소자(또는 적분) → 코드·제어 → 다리·DAC·조정 소자 → 검출기 입력으로 돌아오는 **고리**는, 단독 netlist든 큰 netlist 안이든 **루프 화면 하나**를 그린다.
   - 고속 경로가 없는 보정 회로(ZQ 등)는 보정 루프(아날로그 노드 → 비교기 → SAR/카운터 → 코드 → 복제 다리)를 주 경로로 그리고, FSM은 그 루프와 주고받는 명령·상태·단계 선택만 보인다. 단계 선택(예: 비교기 입력 교차)은 회색 선택 핀.
7. **합치기**
   - 같은 역할 소자는 하나로 합쳐 `M<3:0>`, 크기는 전부 나열.
   - **반복 인스턴스**: 같은 셀이 같은 연결 패턴으로 여러 번(드라이버 세그먼트, DCC 다리) → 블록 하나 `xi<4:0>` + 배수(m=1,2,4,8,16) 표기 + 범례. 반복 표기(`XI7<7:0>`)가 없어도 **같은 셀이고 연결 패턴이 비트 번호만 다른** 인스턴스들은 반복 블록으로 합친다. 반복 표기 없이 합친 블록은 "첫 … 끝"으로 적는다(예: `X_DQ0 … X_DQ7`). 범례에는 인스턴스를 모두 적고, 적은 이름은 모두 netlist에 있어야 한다.
   - 사슬로 이어진 인버터들은 버퍼 블록 하나. latch·FF 화면 안에서도 같다(중간 넷이 사슬 밖에서 쓰이지 않을 때).
   - **합친 블록의 범례는 필수**: 인스턴스별 넷 대응.
8. **유닛 화면 크기 상한**: 그린 기호가 20개를 넘으면 이 순서로 줄인다 — ① 같은 역할 반복을 하나로 합침(`M<3:0>`), ② 묶음을 개념 기호로 바꿈(가변 R/C/전류원, 게이트 로직은 NAND/NOR 기호), ③ 그래도 넘으면 기능 단위로 화면을 나눔(예: 게이트 로직 / 출력단), 나눈 화면 사이는 화면 밖 연결 기호(§3.5-1). 폰에서 읽힐 필요는 없다.

### 3.2 블록 레벨 (모든 계층에 같은 규칙)
1. **보이는 넷만 그린다**: §2.5-4 표에서 그리는 분류(고속 데이터, 고속 클럭, 중요 제어 …). 나머지는 §3.5-3대로 지운다.
2. 블록 심볼은 **보이는 핀만으로 크기를 다시 정한다** (기호 모양은 §3.4-8).
3. **중요 제어 버스**(기능별 하나, §2.5-7)는 블록 위에서 한 줄로 그린다. 여러 블록이 받으면 줄기 하나에서 갈라진다. 1비트·선택 핀·아날로그 제어의 모양은 끝점 표의 "그림" 열(§2.5-5).
4. **배치**: 왼쪽→오른쪽 신호 흐름, 피드백은 아래로, 클럭은 아래에서, 중요 제어 버스는 위에서. 주 경로는 한 줄로 곧게. (예외: CCI §3.3-7)
5. **선 수 최소화**: 줄기 하나 + 가지, 핀 높이 정렬로 꺾임 제거.
6. **하위 블록**: 하위 셀의 핀은 위에서 정해진 분류를 따른다. 같은 셀이 여러 곳에 쓰이면 한 곳에서라도 보이는 핀은 보인다.
7. 선으로 그리면 교차·우회가 생기는 넷은 이름표로 연결한다 (§3.5-1).

### 3.3 유닛 레벨 (MOSFET 단위)
1. **차동 증폭기 = 무조건 대칭**, 신호선 꼬임 금지, 노드 최소. **한 축 대칭**: P쪽 절반 왼쪽, N쪽 절반 오른쪽, 정확한 거울상. 자기대칭 소자는 축 위.
2. **여러 차동쌍이 출력을 공유할 때 (VGA, summer, driver 세그먼트 등) — 쌍별 대칭, 나란히** (참고 논문 Fig.4(a) 방식, 그림 `Q2_layout_options.png`(또는 같은 그림 `.html`)의 B):
   - 차동쌍마다 **자기 축**으로 거울상이고, 그 쌍의 꼬리는 자기 축 위.
   - **주 쌍**(입력에 가까운 쪽, 신호 추적에서 먼저 도달하는 쌍)이 왼쪽, 추가 쌍(이득 단·탭)이 오른쪽으로 나란히.
   - 부하는 주 쌍 위. 두 출력 노드는 **두 높이의 가로 버스**(위 N쪽, 아래 P쪽)로 오른쪽 쌍들의 드레인까지 이어진다.
   - 교차는 **쌍마다 하나**만 허용: 각 쌍의 N쪽 드레인이 아래 P 버스를 지나는 곳 (그림 B: 쌍 2개 → 교차 2개).
   - 추가 쌍의 게이트 입력은 그림 B처럼 이름표(INP/INN)로 둔다.
3. **degeneration 소자**(고정·가변 R/C)는 두 소스 세로선 사이에 가로로, R 위 C 아래.
4. **공유 게이트는 곧은 가로선 하나**: 거울 쌍의 공유 게이트는 두 게이트 사이 직선. 소자를 돌아가는 배선 금지.
5. **입력·출력 위치**: INP는 왼쪽 게이트 · INN은 오른쪽 게이트. 출력은 차동쌍이 하나면 OUTP 왼쪽 끝 · OUTN 오른쪽 끝(대칭), 여러 쌍이 나란히면 두 출력 모두 **오른쪽 버스 끝 모서리**에서 나간다. 차동 출력의 좌우는 netlist에서 어느 입력이 구동하는지로 정한다(INP가 구동하는 쪽이 INP 쪽). 이름이 반대면 그대로 쓰고 주석. (이 두 문장은 모든 화면)
6. **짝 없는 소자**(netlist가 비대칭): 나머지는 대칭을 지키고, 그 소자만 **연결된 노드 쪽 바깥**에 둔다. 옆에 "비대칭" 표시를 하고 확인 질문을 남긴다(§2.7-4).
7. **cross-coupled 인버터 쌍(CCI, 키퍼·latch 코어)**: 두 노드를 위아래 가로선으로 두고, 인버터 두 개를 **각각 90° 돌려** 나란히 세운다 — 하나는 위 노드 → 아래 노드(아래를 향함), 다른 하나는 아래 노드 → 위 노드(위를 향함). 노드를 돌아가는 선이 없어야 한다. CCI에 한해 왼→오 흐름 규칙(§3.2-4)과 기호 방향 규칙의 예외.
8. **S/D 방향**: 그릴 때 소스를 레일 쪽으로 뒤집어도 된다 (연결 검증은 소스/드레인 구분 없이 채널 두 끝으로).
9. **교과서 배치 템플릿** (사전의 각 블록):
   - **CTLE**: 부하(대칭) → 입력쌍 → 소스 사이 가로 R_S·C_S → 꼬리 둘(축 대칭) → 접지.
   - **CML latch**: 입력쌍 바깥, cross-coupled 안쪽 X, 클럭쌍 거울, 꼬리 축 위.
   - **StrongARM**: 위 리셋 PMOS · cross-coupled PMOS, 중간 cross-coupled NMOS, 아래 입력쌍, 맨 아래 클럭 꼬리. 한 축 대칭.
   - **Summer / VGA / Driver**: 2항의 쌍별 대칭(나란히). 탭 전류는 가변 전류원 + 계수 버스, 이득 단 꼬리는 가변 전류원.
   - 사전에 없는 차동 구조: 일반 대칭 배치 + 확인 요청.

2. **포트**: Virtuoso 핀 — 보여주는 신호의 포트만.
3. **개념 기호** — 조절 소자는 개념 기호로 그린다:

### 3.5 이름표·버스·생략 목록·주석
1. **이름표 연결 (블록 화면)**: 블록 화면에서 선으로 그리면 **교차나 우회**(§1.4-5 꼬임)가 생기는 넷은 같은 이름의 이름표(넷 라벨)로 연결한다.
   - 먼저 선으로 시도하고, 교차·우회가 생길 때만 이름표로 바꾼다.
   - 흔한 경우: 피드백(DFE 탭), 여러 블록으로 가는 클럭, 차동 클럭의 한쪽만 줄기로 그릴 때 다른 쪽(CLKB), 위아래로 놓인 블록으로 가는 두 번째 버스 가지.
   - 주 경로(고속 데이터 입력 → 출력)는 배치로 교차를 먼저 없애고, 그래도 남으면 이름표.
   - 아래 형식과 짝 규칙은 모든 화면에 같다.
   - 형식: 끝마다 짧은 선 + 넷 이름. 차동이면 P/N 둘 다. 버스면 이름표에도 2항의 버스 표시.
   - 한 넷이 '선 줄기 + 이름표 끝'을 함께 쓸 수 있다.
   - 같은 이름표는 화면 안에 짝이 있거나 그 넷의 포트가 있어야 한다 (**짝 없는 이름표 금지**). 예외 둘: ① 미사용 출력(4항), ② 화면 경계를 넘는 넷(유닛 화면·가상 블록 화면에서 부모로 나가는 넷). 경계 넷은 **화면 밖 연결 기호**(작은 오각 화살표 + 이름)로 그려 일반 이름표와 구분한다. 회색 이름표(게이트·선택 핀·숨긴 입력·상수 레일·tie 이름표, 3항·§2.5)는 연결 이름표가 아니므로 모두 짝 규칙에서 뺀다.
2. **버스 표시**: 사선을 그린다. 이름에 `<a:b>`가 있으면 비트 수는 쓰지 않고, 없으면 사선 + 비트 수.
   - **버스 줄기 + 비트 가지**: 버스선에서 갈라지는 가지는 비트 이름표(`rx_d<2>`)를 단다. 가지는 버스와 같은 넷으로 합치지 않고 "그 버스의 한 비트"로 검증한다.
3. **숨긴 넷**: 선·이름표·블록 핀·셀 포트를 모두 그리지 않는다. 예외:
   - 차동 증폭기 유닛 화면(§3.3)에서 보이지 않는 넷의 게이트, 그리고 고정 바이어스 트랜지스터의 게이트: 짧은 회색 이름표만 (포트 핀·배선 없음).
   - 숨긴 선택 신호 때문에 스위치·전달 게이트가 동시에 켜진 것처럼 보이면, 그 선택 핀만 회색 짧은 선 + 회색 이름표 (버스로 그리지 않음).
   - 논리 게이트의 숨긴 입력: 회색 짧은 선 + 회색 이름표 (예: EN) — 1입력 NAND처럼 보이지 않게.
   - **상수**(전원·접지·tie 셀에 묶인 입력 핀): 블록 화면에서 회색 짧은 선 + 레일(또는 tie 넷) 이름표를 허용한다 (전원 숨김의 예외, 상보 선택 스위치가 항상 켜진 것을 보이기 위함). 유닛 화면은 레일 기호.
4. **미사용 출력은 모두 짧은 선 + 넷 이름표**: 고속 신호인데 아무것도 구동하지 않는 출력도, 보조 출력(qb, 쓰지 않는 q)도 같다. 지우지 않고, 그것을 구동하는 소자도 그대로 그린다. 핀 리드만 있고 아무것도 없는 출력은 금지. 생략 목록에는 넣지 않는다(그렸으므로).
5. **생략 목록** (사이드 패널·PPT 메모):
   - 그 화면에 선·검은 이름표·포트·전원 기호로 그린 넷은 빼고, 한 넷은 한 번만.
   - 버스는 비트마다 쓰지 않고 `<MSB:LSB>` 한 줄. 같은 분류끼리 모아 쓴다.
   - 블록 문구: 고속 신호와 무관해 생략한 블록은 "블록 (셀) — 고속 신호와 무관", 일반 제어만 만드는 로직(§2.5-8)은 "블록 (셀) — 일반 제어만 만듦", 박스로만 그린 블록(§3.1-5)은 모두 "블록 (셀) — 박스로만".
6. **크기 표기**: SI 접두어로 `600n/30n`, `16u/45n` (원래 문자열은 툴팁).
7. **설명 문구·주석**: 수치·비교·"같다/다르다" 주장은 netlist에서 읽어 확인한 것만 쓴다. 블록 설명(예: "반전")은 netlist 극성과 맞아야 한다. 셀 이름에서 온 숫자(`_x8`의 8)는 제목·설명의 수치 주장에 쓰지 않는다. 설명 문구가 틀리면 그림이 맞아도 불합격이다.

### 4.3 판정·루프
**역할**: **AGENT 1** — 시험 netlist와 정답지를 만든다(부록 B의 "시험 netlist 설계자"). **AGENT 2** — 그리는 쪽: netlist를 받아(정답지 없이) 그림과 `out/` 파일(§1.2)을 만든다. **AGENT 3** — 검증 쪽: 정답지가 있으면 받아 `checklist.json`(§4.2), `fix_request.md`, 보고서를 만든다. **오케스트레이터** — 루프를 돌리고, `fix_request.md`를 AGENT 2에게 전달하고, 명세서를 고친다.

1. **두 축 판정**: 그린 쪽 원인 불통과 0 → **그림 PASS**. 명세서 원인 불통과 0 → **명세 PASS**. `checklist.json`에 `verdict_drawing`, `verdict_spec`을 따로 적고, 보고서도 두 표로 나눈다.
2. **회로 합격** = 두 축 모두 PASS + ★ 전부 통과.
3. **안쪽 루프 (AGENT 2 ↔ AGENT 3, 회로마다)**: 그림 판정만 대상. 원인이 "그린 쪽"인 불통과 항목을 근거·캡처와 함께 AGENT 2에게 돌려보내 고치게 하고 AGENT 3이 다시 채운다. **최대 3번**. 3번 안에 못 고치면 명세서 문제로 넘긴다.
4. **반송 파일과 정답지**: AGENT 3은 그린 쪽 불통과마다 `fix_request.md`에 근거(netlist 줄, 명세 조항)와 고칠 내용만 쓴다. **정답지 내용은 넣지 않는다.** 오케스트레이터는 이 파일을 그대로 AGENT 2에게 전달한다. 정답지는 검증 쪽에만 준다.
5. **고칠 범위**: 수정 라운드에서 바뀐 화면 외에는 픽셀 단위로 같아야 한다(AGENT 3이 확인, `scene_sha` §4.1-16). 규칙을 생성기 전체에 적용해 다른 화면이 바뀌면 그 사실을 보고한다(§4.1-17).
6. **바깥 루프 (오케스트레이터)**: 명세 판정은 오케스트레이터가 명세서로 고친다 — 원인이 "명세서"인 항목과 안쪽 루프에서 못 고친 항목으로 명세서를 고친다. 세 회로가 모두 ★ 통과하고 명세서 원인 항목이 없을 때만 승인. 다음 회차는 사용자 승인 후. 사용자 리뷰 결과는 다음 회차 전에 명세서에 반영한다.
7. **정답지 분류 대응**: 정답지 분류 이름과 명세서 분류의 대응은 **부록 B**를 쓴다. 부록 B에 없는 정답지 분류가 나오면 AGENT 3은 정의를 읽고 가장 가까운 행으로 판정하되, 그 판단을 "뜻으로 판정" 목록에 적는다(다음 명세서 개정 재료).
8. **실행**: 큰 회로는 사용량 한도에 걸린다 — 동시에 도는 에이전트 수를 줄이고, 끊기면 같은 에이전트를 이어서 돌린다(새로 띄우지 않는다).

### 4.4 일반성 시험
1. 규칙을 바꿀 때마다 아래 모음 전체가 통과해야 한다.
2. 시험용 netlist에는 반드시 **정답지**를 만든다: 정답 분류 파일(고속 입력·클럭·중요 제어·생략 대상·블록 역할)과 기대 성질(대칭, 교차 수 상한). 정답지를 누구에게 주는지는 §4.3-4.
3. **모음**:

| 분야 | 포함할 회로 |
|---|---|
| RX | CML 버퍼, RC-CTLE, active-inductor CTLE, 다단 CTLE+VGA, 차동 TIA, 전류 모드 DFE summer(IDAC 탭), loop-unrolled DFE, StrongARM, double-tail 비교기, CML latch/DFF, 1:2·1:4 demux |
| TX | 2:1·4:1 serializer, FFE(pre/post 탭), CML driver, SST driver(세그먼트) |
| Clock | CML 클럭 버퍼, ÷2 분주기, 위상 보간기, CMOS 클럭 버퍼 체인, I/Q 생성 |
| 공통 | 바이어스 발생기, 종단, ESD, 전류 DAC, R/C 뱅크 |
| 형식 | 깔끔한 이름 버전 + Virtuoso식 이름(net12, I3…) 버전 + **이름 가림** 버전 |

4. **통과 기준**: 분류 정답률 100%(묻기로 해결된 것 포함), 모든 화면 검증 통과, 품질 검사 0, 이름 가림 버전의 분류가 원본과 같음.
5. **새 구조로만 판정**: 일반성은 기준 RX AFE와 **다른** netlist로만 판정한다. 최소: ① Rx 변형(넷·셀 이름 가림, 구조 일부 변경), ② Tx(SST + FFE), ③ DCC. 기준 결과를 그대로 재현하는 실행은 일반성 증거로 세지 않는다.
6. **이름 가림 사본**: 이미 그린 netlist의 이름 가림 사본은 체크리스트 N1로 판정한다.
7. 새 netlist에서 틀리면 원인을 사전·규칙에 반영하고 그 netlist를 모음에 추가한다.

### C.5 루프 기록
- **루프 1회차 (v2)**: 맥락 없는 에이전트가 Rx(CML), Tx(4:1 SST + FFE), DCC를 그리고 독립 검증 에이전트가 판정했다. 세 회로 모두 연결 오류는 없었지만, 명세가 CML 회로 위주라 그리는 쪽이 규칙을 지어내야 했다. v2 보강 규칙은 그 빈틈을 메웠다.
- **루프 2회차 (v4)**: BIST·ZQ 보정·DQS-RX. 세 회로 모두 그린 쪽 불통과는 라운드 2에 0이 되었고, 남은 ★ 불통과는 전부 "고속이 아닌 신호를 어떻게 분류·표시하나"가 명세에 없어서였다.

  | 회로 | 라운드 1 → 2 통과 (28항목) | 그린 쪽 불통과 | 명세서 원인 불통과 |
  |---|---|---|---|
  | DQS-RX | 23 → 25 | 2 → 0 | 2 |
  | ZQ 보정 | 25 → 26 | 1 → 0 | 1 |
  | BIST | 22 → 24 | 2 → 0 | 3 |

  - 안쪽 루프(그리기 ↔ 검증)는 세 회로 모두 2라운드에 수렴했다. 남은 불통과는 전부 명세서 원인이었다.
  - 손으로 대조한 연결(화면 70여 개)에서 틀린 연결 0, 정답지 대비 블록 역할·극성 불일치 0.
- **2회차 교훈 (v4.2)**:
  1. 그린 쪽 불통과는 모두 기계 검사로 잡을 수 있는 종류였다 (떠 있는 포트, 생략 목록 ↔ 그린 넷, 화면 간 선 종류, 합친 블록 범례, 설명 문구 수치). → 자동 검사(§4.1).
  2. 명세서 원인은 "고속이 아닌 신호"에 몰렸다 (기준 전압, 상태·명령, 워드 속도 디지털, 이득·VREF 코드). → §2.5.
  3. 정답지 대조(G1)가 기능 오류를 잡았다 (VGA↔CTLE, 리플 카운터를 클럭으로, 명령을 클럭으로). → 정답지 필수(§4.4-2).
  4. 사용자 눈으로만 잡힌 문제가 있었다 (CCI 배치, 핀만 떠 있는 출력, 점선). → 체크리스트 항목으로 넣었다.
  5. 설명 문구가 틀리면 그림이 맞아도 불합격이다 (unmatched 이유를 틀리게 씀). → §3.5-7.
  6. 고칠 때 범위를 넘기지 않는다. → §4.3-5.
  7. 큰 회로는 사용량 한도에 걸린다. → §4.3-8.
- **루프 3회차 (v5)**: NAND IO 전체(MOS 6833). 그린 쪽 불통과는 3 → 1 → 0으로 수렴했고, 남은 ★ 불통과(G1a·G1c·B3)는 모두 제어 분류 규칙이 이름 목록으로 적혀 있어서 조항끼리 다른 답을 냈기 때문이다 (v5 §11.2-5 "enable = 일반" ↔ §13.2 "run/enable 묶음 = 버스", §11.3-1(c) "지연 코드 = 중요" ↔ §11.3-2 "트림 = 일반", §12.4 "보정 코드 숨김" ↔ §13.1 "결과 상태 = 그림"). v5는 이 분류를 이름이 아니라 구조로 정하는 표 하나로 바꿨다 (사용자 결정, 3회차 후).

### C.9 열린 문제
규칙이 아니다. 다음 개정에서 정할 것.
1. 모니터 출력 "(mon)": 어떤 출력이 모니터 출력인지 정하는 구조 규칙이 없다 (K9와 부록 B가 이 말을 쓴다).
2. 바이어스 DAC(바이어스 발생기)로만 가는 코드: 맞는 끝점 행이 없다 (K11은 바이어스 노드 자체).
3. 구조 특징이 없는 사전 항목: C2C, OTA, RC 평균기, 그리고 논리 게이트·SR latch·ICG·DLY·LS. 사전 대응(§2.6-3)을 적용할 수 없다.
4. 다른 블록의 클럭 핀을 구동하지 않는 분주기 출력: 클럭이 아니라는 것만 정해져 있고(§2.3-7) 무슨 분류인지는 없다.
5. 고속 클럭으로 동작하는 플립플롭·샘플러의 입력(제어 추적이 멈추는 곳, §2.5-1)에 닿는 제어: 맞는 끝점 행이 없다.

### C.10 명세서 고치는 규칙 (오케스트레이터용, v6부터)
1. **골격 고정**: 장은 `0 · 1 · 2 · 3 · 4 · 부록 A · B · C`뿐이다. 새 장을 만들지 않는다. 새 주제는 그것을 찾을 장 안의 절에 넣고, 절을 새로 만들 때는 그 장 번호를 이어 붙인다.
2. **그 자리에서 고친다**: 규칙을 바꾸면 그 규칙이 있는 문장을 고친다. 본문에 "vN:", "대체", "이긴다", 취소선 같은 덮어쓰기 표시를 남기지 않는다.
3. **이력은 부록 C에만**: 바꿀 때마다 C.1(버전 이력)에 한 줄 — 버전, 무엇을, 왜(몇 회차 어떤 불통과·사용자 결정), 고친 절. 정한 충돌은 C.8, 아직 못 정한 것은 C.9.
4. **체크리스트는 §4.2 표 하나**: 항목 id(M·J·G·N)는 바꾸지 않는다. 더하면 그 묶음 끝에 새 번호, 지운 번호는 다시 쓰지 않는다. 항목마다 근거 조항(§ 또는 부록)을 적는다.
5. **커밋 전 검사**: `python3 spec_lint.py`가 0건이어야 한다(골격, 덮어쓰기 표시, § 참조, 체크리스트 id, 버전 기록, SKILL 머리). 그다음 `make_bundle.py`로 묶음을 다시 만든다.
6. **규칙을 고친 회차에는** 바뀐 절 목록을 현황 페이지에 보이고, 다음 회차 시험은 고친 판의 사본으로 돌린다.
