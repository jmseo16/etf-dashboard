## 0. 목적과 우선순위

**목적**: HSPICE/Virtuoso netlist를 받아 **High-Speed IO 회로의 개념을 설명하는 그림**을 그린다.
회로를 빠짐없이 옮기는 회로도가 아니라, "고속 신호가 어디로 흐르고 어떤 구조로 처리되는가"를 보여주는 **개념도**다. 기본은 **덜 그리기**다.

**판단 우선순위** (충돌하면 위가 이긴다)
1. **정확성** — 생략은 허용, 틀리게 그리는 것은 절대 금지.
2. **고속 신호 경로가 한눈에** — 고속 데이터·클럭과 중요 제어만 그린다.
3. **대칭** — 차동 회로는 무조건 좌우 대칭.
4. **최소 선·노드·교차** — 꼬인 선, 군더더기 접점, 짧은 꺾임 금지.
5. **교과서(Razavi) 스타일**.

## 1. 어떤 netlist가 와도 의도대로 그리기 위한 원칙

넷 이름, 셀 이름, 계층 구조는 회사·설계자마다 다르다. 그래서 이 스킬은 아래 다섯 가지로 일반성을 확보한다.

1. **이름이 아니라 구조로 판단한다.**
   소자의 역할(입력 트랜지스터, 꼬리 전류원, 스위치 …)과 신호의 흐름을 연결 구조만으로 정한다. 이름(`CLK`, `VB`, `INP`)은 **확인용 힌트**일 뿐이고, 구조와 이름이 다르면 구조를 따르되 사용자에게 확인한다.
2. **회로 역할 사전으로 판단한다.**
   고속 IO에 나오는 소자 역할(§3.1)과 블록 종류(§3.4)를 구조 특징으로 정의한 사전을 두고, 모든 판단은 이 사전에 비추어 한다. 사전에 없는 구조는 "모름"으로 표시한다.
3. **모르면 묻는다.**
   판단마다 확신도를 매기고, 확신이 낮은 것만 사용자에게 짧게 묻는다 (§3.5). 그림을 그리기 전에 **분류 확인 표**를 한 번 보여주는 것은 필수 단계다. 답은 파일로 저장해 같은 회로는 다시 묻지 않는다.
4. **틀리게 그리지 않는다.**
   그린 것은 모두 netlist와 대조해 검증하고(§6), 실패하면 전달하지 않는다. 판단이 틀려도 "틀린 그림"이 아니라 "덜 그린 그림" 또는 "질문"이 되도록 한다.
5. **테스트 모음으로 일반성을 증명한다.**
   여러 종류의 고속 IO 회로 netlist와 정답 분류를 모아 두고(§7), 규칙을 바꿀 때마다 전부 통과해야 한다. **이름 섞기 테스트**(넷·셀 이름을 무작위로 바꿔도 분류가 같아야 함)로 이름에 기대지 않는다는 것을 확인한다. 새 netlist에서 틀리면 그 회로를 모음에 추가한다.

> **보장 범위**: 처음 보는 구조까지 100% 자동으로 맞힌다고는 보장할 수 없다. 대신 (1) 틀린 그림은 검증이 막고, (2) 애매한 것은 묻고, (3) 사전과 테스트 모음이 커질수록 묻는 횟수가 줄어든다.

## 3. 1단계 — 회로 이해 (분석)

### 3.1 소자 역할 (구조로만 판정)

| 역할 | 구조 특징 |
|---|---|
| 입력 트랜지스터 | 게이트가 신호 넷, 드레인이 부하가 있는 노드, 소스가 tail·전원·degeneration 노드 |
| 꼬리 전류원 | 소스가 전원, 드레인이 다른 트랜지스터들의 소스 노드, 게이트가 바이어스, 먹이는 쌍과 **같은 극성** (NMOS 쌍 ↔ NMOS 꼬리) |
| 부하 | 전원으로 가는 R / 게이트가 고정 전위인 PMOS / 다이오드 연결 / active inductor(게이트에 R) |
| 캐스코드 | 게이트가 바이어스, 소스가 다른 소자의 드레인, 드레인이 출력 |
| cross-coupled 쌍 | g1 = d2, g2 = d1 |
| 리셋·프리차지 | 게이트가 클럭, 소스가 전원, 드레인이 내부 노드 |
| 클럭 꼬리 | 꼬리 전류원과 같은 구조(같은 극성 포함)인데 게이트가 클럭 (StrongARM·동적 비교기의 꼬리). 극성이 반대면 리셋·프리차지 |
| 클럭 스티어링 쌍 | 게이트가 클럭 P/N, 두 드레인이 각각 다른 차동쌍의 공통 소스 노드 (드레인에 부하 없음), 소스 공유 (CML latch의 클럭쌍) |
| 정적 CMOS 게이트 | 같은 입력 넷을 게이트로 받는 NMOS·PMOS가 같은 출력 넷을 구동 (인버터·NAND·NOR). 리셋·꼬리 판정보다 **먼저** 인식 |
| 스위치 | 게이트가 정적 제어, 채널이 소자(R·C·전류원)와 직렬 또는 두 노드 사이 |
| 전달 게이트 | 같은 두 넷 사이의 NMOS+PMOS (게이트가 상보 또는 전원에 묶임). 게이트가 **켜는 전원**(NMOS→VDD, PMOS→VSS)에 묶이면 항상 켜짐, **끄는 전원**(NMOS→VSS, PMOS→VDD)에 묶이면 항상 꺼짐 |
| 다이오드·미러 | 게이트 = 드레인 |
| 종단 | 고속 입력에서 공통모드 노드·전원으로 가는 R |
| ESD | 패드에서 전원으로, 게이트가 전원에 묶인 MOS 또는 다이오드 |
| 디커플링 | DC 노드에서 전원으로 가는 C |
| 반복 단위(slice) | 숫자만 다르고 구조가 같은 소자 묶음 (합치기 대상) |

### 3.2 신호 추적 규칙

고속 데이터 입력과 클럭 입력에서 출발해, 계층을 넘나들며 따라간다.

| 지나는 곳 | 규칙 |
|---|---|
| 입력 트랜지스터 | 게이트가 신호 → 드레인이 신호 (소스 팔로워면 소스도) |
| 캐스코드 · 스택 트랜지스터 | 소스가 신호(전원 아님) → 드레인이 신호. 게이트가 바이어스든 다른 신호든 같다 (예: StrongARM의 cross-coupled NMOS — 소스가 입력쌍 드레인) |
| 정적 CMOS 게이트 | 입력이 신호 → 출력이 같은 분류 (인버터 체인 = 버퍼) |
| cross-coupled 쌍 | 한쪽 드레인이 신호 → 양쪽 모두 |
| 직렬 수동소자 | 두 비전원 노드 사이 R·C·L은 양끝이 같은 분류 (전원·공통모드로 가는 것은 제외) |
| 전달 게이트 | 켜질 수 있으면 양끝이 같은 분류. **항상 꺼진 것은 끊긴 것**으로 보고 전달하지 않는다 (질문: "netlist 오류인가요?") |
| 하위 블록 | 블록 안을 추적해 입력→출력 관계를 구하고 위로 전달 |
| latch · flip-flop · 샘플러 | 출력의 분류 = **데이터 입력의 분류** (데이터가 들어오면 데이터, 클럭이 들어오면 클럭 — 분주기·I/Q 생성). 클럭 핀은 출력을 클럭으로 만들지 않는다 |
| 피드백 | 그대로 따라간다 (DFE 탭, FFE 지연 신호) |
| **멈추는 곳** | 전원, 꼬리 전류원·캐스코드의 게이트(바이어스), 스위치 게이트(제어), **클럭 역할 게이트** — 클럭 꼬리·클럭 스티어링·리셋·프리차지 (§3.1). 이 소자들의 드레인은 클럭이 아니라 데이터 경로의 내부 노드다 |

클럭은 클럭 입력에서 같은 규칙으로 따로 추적한다 (버퍼·분주기·위상 보간기 출력 = 클럭). 데이터와 클럭 양쪽에서 도달하는 넷은 확인 대상이다.

**입력 포트가 클럭인지 데이터인지 (구조로 판정)** — 입력 포트에서 위 규칙으로 추적했을 때:
- **클럭 역할 게이트**(클럭 꼬리·클럭 스티어링·리셋·프리차지)에 하나라도 도달 → **클럭 입력** (latch 데이터 입력에도 닿을 수 있음: 분주기·I/Q)
- 클럭 역할 게이트에는 닿지 않고, 입력 트랜지스터를 거쳐 latch·샘플러의 **데이터 입력**에 도달 → **데이터 입력**
- 둘 다 아님 → 질문 (§3.5)
- 이름(`CLK`, `IN` 등)은 판정에 쓰지 않고 **확신도에만** 쓴다: 구조와 이름이 맞으면 높음, 어긋나면 낮음 → 질문.

### 3.3 신호 분류

| 분류 | 일반 정의 | 그림 |
|---|---|---|
| 고속 데이터 | 데이터 입력에서 추적으로 도달 (출력·피드백 포함) | 선 |
| 고속 클럭 | 클럭 입력에서 추적으로 도달 | 선 (데이터와 같은 굵기) |
| **중요 제어** | **다른 고속 신호(또는 다른 클럭 위상)를 고속 노드에 얼마나·어떤 것을 섞을지 정하는 제어** — 예: DFE·FFE 탭 계수, 위상 보간기 가중치 | 버스 1개 |
| 일반 제어 | 한 경로의 파라미터만 조절 — 이득, 피킹 R/C, 대역폭, 종단·오프셋·바이어스 트림, 동작 모드 | 그리지 않음 |
| 바이어스 | 꼬리 전류원·캐스코드 게이트, 다이오드 노드, 기준 전류, 공통모드 | 그리지 않음 |
| 전원 | 공급·접지 | 블록도 숨김, 유닛 레벨 레일 |

중요 제어 판정은 구조로 한다: 제어 → 스위치/DAC → 어떤 가지의 전류·세기, 그리고 그 가지의 입력이 주 입력과 **다른** 고속 신호이고 출력이 고속 노드에서 **합산**되면 중요 제어. 주 경로 하나의 세기만 바꾸면 일반 제어.

### 3.4 블록 역할 사전 (개념 기호와 그리는 방법)

| 분야 | 블록 | 구조 특징 | 블록도 기호 | 유닛 레벨 |
|---|---|---|---|---|
| RX | 종단 · ESD | 입력에서 공통모드/전원으로 R, 전원 클램프 | 입력선 위 R/ESD 표시 | 소자 그대로 |
| RX | CTLE | 소스 degeneration(R∥C) 차동쌍 | 삼각형 "CTLE" | 대칭, R_S·C_S 가로 (가변이면 가변 기호) |
| RX | VGA | 이득 단을 스위치로 더하는 차동쌍 | 삼각형 "VGA" | 대칭, 이득 단 합쳐서 ×N, 꼬리는 가변 전류원 |
| RX | TIA | 피드백 R가 있는 증폭기 | 삼각형 "TIA" | 대칭, 피드백 R |
| RX/TX | Summer (DFE·FFE) | 여러 차동쌍이 같은 출력에 합산 | Σ | 대칭, 탭 쌍 합쳐서, 탭 전류는 가변 전류원 + 계수 버스 |
| RX | 비교기 · 샘플러 | StrongARM, double-tail, CML 샘플러 | 삼각형 + 클럭 | 교과서 배치 (5.4) |
| 공통 | Latch · DFF | cross-coupled + 클럭 스티어링, 두 latch 직렬 | 박스 LATCH/DFF | latch 교과서 배치 |
| RX | Demux | latch/DFF 병렬 + 위상이 다른 클럭 | 박스 "1:N" | — |
| TX | Serializer (MUX) | 클럭으로 고르는 데이터 경로 | 사다리꼴 MUX | — |
| TX | Driver | CML 차동 출력단, SST/전압 모드 세그먼트 | 삼각형 "DRV" | 대칭, 세그먼트 합쳐서 ×N |
| Clock | 버퍼 · 분주기 · 위상 보간기 | CML/CMOS 버퍼, ÷2 latch 루프, 가중 합산 | 삼각형, "÷2", "PI" | 대칭 |
| 공통 | 바이어스 · DAC · 디지털 제어 | 미러, 전류 DAC, 디코더 | **생략** | — |
| 공통 | 복합 블록 | 하위 블록이 **모두** 사전에 있는 블록 (예: DFE 슬라이스, 클럭 트리) | 박스(셀 이름) + 보이는 핀만, 확신 높음 (묻지 않음) | — |
| 기타 | 사전에 없음 | — | 박스(셀 이름) + 보이는 핀만 | 대칭 가능하면 대칭, 확인 요청 |

- **이름과 구조가 다르면 구조로 고르고 묻는다** (§1-1). 예: 이름은 ÷2인데 latch 루프가 없으면 ÷2 기호가 아니라 LATCH 박스 2개로 그리고 질문한다.

### 3.5 확신도와 질문

- 각 판단(고속 입력, 클럭 입력, 중요 제어, 블록 종류)에 **높음 / 낮음**을 매긴다. 구조와 이름이 맞으면 높음, 어긋나거나 사전에 없으면 낮음.
- 낮음만 질문한다. 질문은 선택지로 짧게: "포트 `X`는 고속 데이터 입력입니까? (예 / 클럭 / 제어 / 바이어스)".
- 반드시 묻는 경우: 고속 입력을 구조로 찾을 수 없음, 정의가 없는 블록(블랙박스)이 고속 경로에 있음, 이름은 클럭인데 데이터 경로에서 도달(또는 반대), MUX 선택 신호가 클럭인지 정적 제어인지 불분명, 제어가 중요/일반 어느 쪽인지 불분명.
- 답은 annotations 파일로 저장한다 (항상 자동 판정보다 우선):
```json
{
  "hs_inputs": ["..."], "clock_inputs": ["..."], "hs_outputs": ["..."],
  "important_controls": ["..."], "show_bias": [], "hide": [],
  "block_roles": {"CELL_NAME": "ctle"}
}
```

## 4. 2단계 — 블록 레벨 연결도 (모든 계층에 같은 규칙)

1. **보이는 넷만 그린다**: 고속 데이터, 고속 클럭, 중요 제어.
2. **나머지는 완전히 지운다**: 선·이름표·블록 핀·셀 포트 모두. 블록 심볼은 보이는 핀만으로 크기를 다시 정한다.
3. **고속 신호와 연결이 없는 블록은 생략**하고 생략 목록에 남긴다.
   - 반대로 고속 신호인데 **아무것도 구동하지 않는 출력**(미사용 출력)은 지우지 않는다: 짧은 선 + 넷 이름표로 끝낸다. 그것을 구동하는 소자도 그대로 그린다.
4. **중요 제어는 기능별 버스 하나**: 같은 기능의 비트를 한 버스로 묶어 블록 위에서 한 줄로. 여러 블록이 받으면 줄기 하나에서 갈라진다.
5. **배치**: 왼쪽→오른쪽 신호 흐름, 피드백은 아래로, 클럭은 아래에서, 중요 제어 버스는 위에서. 주 경로는 한 줄로 곧게.
6. **선 수 최소화**: 줄기 하나 + 가지, 핀 높이 정렬로 꺾임 제거.
7. **하위 블록**: 하위 셀의 핀은 위에서 정해진 분류를 따른다. 같은 셀이 여러 곳에 쓰이면 한 곳에서라도 보이는 핀은 보인다.
   - **트랜지스터와 하위 블록이 섞인 셀**: 트랜지스터를 채널 연결 덩어리별로 묶어 **자동 가상 블록**으로 만든다. 블록도에서는 박스(또는 사전의 기호)로 그리고, 클릭하면 그 덩어리의 유닛 화면으로 들어간다. 종단·ESD처럼 사전에서 "입력선 위 표시"로 정한 것은 블록을 만들지 않고 표시만 한다.
8. **이름표 연결**: 선으로 그리면 **교차나 우회**(§5.3-2 꼬임)가 생기는 넷은 같은 이름의 이름표(넷 라벨)로 연결한다.
   - 먼저 선으로 시도하고, 교차·우회가 생길 때만 이름표로 바꾼다.
   - 흔한 경우: 피드백(DFE 탭), 여러 블록으로 가는 클럭, 차동 클럭의 한쪽만 줄기로 그릴 때 다른 쪽(CLKB), 위아래로 놓인 블록으로 가는 두 번째 버스 가지.
   - 주 경로(고속 데이터 입력 → 출력)는 배치로 교차를 먼저 없애고, 그래도 남으면 이름표.
   - 형식: 끝마다 짧은 선 + 넷 이름. 차동이면 P/N 둘 다, 버스면 이름표에도 비트 수.
   - 한 넷이 '선 줄기 + 이름표 끝'을 함께 쓸 수 있다. 같은 이름표는 화면 안에 짝이 있거나 그 넷의 포트가 있어야 한다 (짝 없는 이름표 금지 — 예외는 §11.5-1).

## 5. 3단계 — 유닛 레벨 (MOSFET 단위)

### 5.1 개념 기호로 바꾸는 소자 묶음

| 묶음 (구조) | 개념 기호 |
|---|---|
| 스위치로 켜고 끄는 R 뱅크, 두 노드 사이에서 저항으로 쓰는 스위치 MOS 묶음 | **가변 저항** (화살표 관통 R) |
| 스위치로 켜고 끄는 C 뱅크 | **가변 커패시터** |
| 전류 DAC(스위치 + 전류원 반복), 스위치로 켜는 꼬리 전류원 | **가변 전류원** (원 + 화살표) |
| 고정 R ∥ 가변 뱅크 | 가변 소자 하나로 합침 |

- 제어 코드가 **일반 제어**면 코드는 그리지 않는다 (기호의 화살표가 "조절 가능"을 나타냄).
- 제어 코드가 **중요 제어**면 버스가 기호로 들어간다 (DFE 탭 전류원).
- 고정 바이어스 트랜지스터(꼬리 전류원 등)는 트랜지스터 그대로 두고, 게이트에는 짧은 회색 이름표만.

### 5.2 차동 증폭기 = 무조건 대칭
1. **한 축 대칭**: P쪽 절반 왼쪽, N쪽 절반 오른쪽, 정확한 거울상. 자기대칭 소자는 축 위.
2. **여러 차동쌍이 출력을 공유할 때 (VGA, summer, driver 세그먼트 등) — 쌍별 대칭, 나란히** (참고 논문 Fig.4(a) 방식, 그림 `Q2_layout_options.png`(또는 같은 그림 `.html`)의 B):
   - 차동쌍마다 **자기 축**으로 거울상이고, 그 쌍의 꼬리는 자기 축 위.
   - **주 쌍**(입력에 가까운 쪽, 신호 추적에서 먼저 도달하는 쌍)이 왼쪽, 추가 쌍(이득 단·탭)이 오른쪽으로 나란히.
   - 부하는 주 쌍 위. 두 출력 노드는 **두 높이의 가로 버스**(위 N쪽, 아래 P쪽)로 오른쪽 쌍들의 드레인까지 이어진다.
   - 교차는 **쌍마다 하나**만 허용: 각 쌍의 N쪽 드레인이 아래 P 버스를 지나는 곳 (그림 B: 쌍 2개 → 교차 2개).
   - 추가 쌍의 게이트 입력은 그림 B처럼 이름표(INP/INN)로 둔다.
3. **degeneration 소자**(고정·가변 R/C)는 두 소스 세로선 사이에 가로로, R 위 C 아래.
4. **공유 게이트는 곧은 가로선 하나**: 거울 쌍의 공유 게이트는 두 게이트 사이 직선. 소자를 돌아가는 배선 금지.
5. **입력·출력 위치**: INP는 왼쪽 게이트 · INN은 오른쪽 게이트. 출력은 차동쌍이 하나면 OUTP 왼쪽 끝 · OUTN 오른쪽 끝(대칭), 여러 쌍이 나란히면 두 출력 모두 **오른쪽 버스 끝 모서리**에서 나간다.
6. **보이지 않는 넷의 게이트**: 짧은 회색 이름표만 (포트 핀·배선 없음).
7. **짝 없는 소자**(netlist가 비대칭): 나머지는 대칭을 지키고, 그 소자만 **연결된 노드 쪽 바깥**에 둔다. 옆에 "비대칭" 표시를 하고 질문한다.

### 5.3 선과 노드 규칙 (모든 레벨)
1. **가지는 이미 꺾이는 모서리에서**: 모서리 → T 하나. 기존 접점에서 **20px 미만** 거리에 새 접점 금지 (20px 이상은 허용).
2. **꼬임 금지**: 선 길이가 두 끝점의 **가로+세로 거리**(|Δx|+|Δy|)의 1.5배를 넘거나 소자를 돌아가면 꼬임이다. 블록 레벨은 이름표로 바꾸고(§4-8), 유닛 레벨은 다시 배치한다.
3. **짧은 꺾임 금지**: 꺾인 선분 길이가 **20px 미만**이면 위반 (20px 이상은 허용).
4. **대칭 배선**: P쪽 경로는 N쪽 경로의 거울상.
5. **교차**: 허용 목록에 있는 것만 (§6-5).

### 5.4 교과서 배치 템플릿 (사전의 각 블록)
- **CTLE**: 부하(대칭) → 입력쌍 → 소스 사이 가로 R_S·C_S → 꼬리 둘(축 대칭) → 접지.
- **CML latch**: 입력쌍 바깥, cross-coupled 안쪽 X, 클럭쌍 거울, 꼬리 축 위.
- **StrongARM**: 위 리셋 PMOS · cross-coupled PMOS, 중간 cross-coupled NMOS, 아래 입력쌍, 맨 아래 클럭 꼬리. 한 축 대칭.
- **Summer / VGA / Driver**: §5.2-2의 쌍별 대칭(나란히). 탭 전류는 가변 전류원 + 계수 버스, 이득 단 꼬리는 가변 전류원.
- 사전에 없는 차동 구조: 일반 대칭 배치 + 확인 요청.

## 6. 검증

1. **그린 것은 모두 맞다**: 그림에서 다시 읽은 연결이 netlist와 어긋나지 않는다 (합친 소자는 펼쳐서, 개념 기호는 "기호 단자 = 묶음의 바깥 넷"으로 대조, 같은 화면의 같은 이름표는 한 넷).
2. **보이는 고속 넷은 완전하다**: 화면의 고속 넷은 그 화면의 모든 핀까지 **선 또는 같은 이름표로** 이어져 있다. 짝 없는 이름표는 오류.
3. **생략은 분류대로만**: 그리지 않은 넷·블록 = 숨김 분류, 생략 목록에 전부 있음.
4. **개념 기호는 정확히 묶음을 대신한다**: 묶음의 모든 소자가 기호 하나에 속하고, 묶음 안쪽 넷이 바깥에서 쓰이지 않는다.
5. **품질 검사 (모두 0)**: 글씨 겹침, 소자 관통, 대칭 위반, 꼬임, 짧은 꺾임, 접점 근접, 허용 목록 밖의 교차.
   - **교차 허용 목록**: 블록 레벨은 **0개** (교차가 생기면 이름표, §4-8). 유닛 레벨은 템플릿마다 정한 것만 — cross-coupled 쌍마다 X 1개, 쌍별 대칭(§5.2-2)은 쌍마다 1개, CML latch의 클럭 스티어링 1개. 이 밖의 교차는 전부 위반이다.
6. **눈 확인**: 화면별 스크린샷, PPT를 그림으로 바꿔 확인.

## 7. 일반성 검증 — 테스트 netlist 모음

규칙을 바꿀 때마다 아래 모음 전체가 통과해야 한다. 각 netlist에는 **정답 분류 파일**(고속 입력·클럭·중요 제어·생략 대상·블록 역할)과 기대 성질(대칭, 교차 수 상한)을 붙인다.

| 분야 | 포함할 회로 |
|---|---|
| RX | CML 버퍼, RC-CTLE, active-inductor CTLE, 다단 CTLE+VGA, 차동 TIA, 전류 모드 DFE summer(IDAC 탭), loop-unrolled DFE, StrongARM, double-tail 비교기, CML latch/DFF, 1:2·1:4 demux |
| TX | 2:1·4:1 serializer, FFE(pre/post 탭), CML driver, SST driver(세그먼트) |
| Clock | CML 클럭 버퍼, ÷2 분주기, 위상 보간기, CMOS 클럭 버퍼 체인, I/Q 생성 |
| 공통 | 바이어스 발생기, 종단, ESD, 전류 DAC, R/C 뱅크 |
| 형식 | 깔끔한 이름 버전 + Virtuoso식 이름(net12, I3…) 버전 + **이름 섞기** 버전 |

통과 기준: 분류 정답률 100%(묻기로 해결된 것 포함), 모든 화면 검증 통과, 품질 검사 0, 이름 섞기 버전의 분류가 원본과 같음. 새 netlist에서 틀리면 원인을 사전·규칙에 반영하고 그 netlist를 모음에 추가한다.

## 8. 스킬 사용 흐름

1. netlist 받기 → 파싱 → 소자 역할·신호 추적·블록 역할 판정.
2. **분류 확인 표 제시 (필수)** — 짧게:
   ```
   고속 데이터 입력 : RX_INP, RX_INN            (확신 높음)
   클럭 입력        : CLK_INP, CLK_INN          (확신 높음)
   고속 출력        : DOUT_EVEN_P/N, DOUT_ODD_P/N
   중요 제어 (버스) : W<4:1>_<3:0> — DFE 탭 계수 (확신 높음)

   질문             : (없음)
   ```
   확신 낮은 항목만 질문, 답은 annotations로 저장.
3. 개념도 생성 (블록 → 하위 블록 → 유닛).
4. 검증(§6) 전부 통과 확인.
5. 전달: HTML + PPTX + 생략 목록 요약.

| 항상 꺼진 전달 게이트 | 끊긴 것으로 처리 + 질문 (§3.1, §3.2) |
| 이름과 구조가 다른 블록 (루프 없는 ÷2 등) | 구조대로 그림 + 질문 (§3.4) |
| 짝 없는 소자 | 연결된 쪽 바깥 + "비대칭" 표시 + 질문 (§5.2-7) |
| 아무것도 구동하지 않는 고속 출력 | 지우지 않음: 짧은 선 + 이름표 (§4-3) |
| 트랜지스터와 블록이 섞인 셀 | 자동 가상 블록 (§4-7) |

| 20px 경계 | 20px 미만 = 위반, 20px 이상 = 허용 (§5.3) |

## 11. v2 보강 규칙 (루프 1회차: Rx·Tx·DCC 결과 반영)

> 1회차에서 맥락 없는 에이전트가 Rx(CML), Tx(4:1 SST + FFE), DCC를 그리고 독립 검증 에이전트가 판정했다. 세 회로 모두 연결 오류는 없었지만, 명세가 CML 회로 위주라 그리는 쪽이 규칙을 지어내야 했다. 아래 규칙은 그 빈틈을 메운다. **이 절은 앞 절과 다르면 이 절이 이긴다.**

### 11.1 분석 — 전원·역할
1. **전원이 여러 개**: PMOS 벌크에 쓰인 넷은 모두 전원, NMOS 벌크에 쓰인 넷은 모두 접지 (vdd, vddq 둘 다 전원). 벌크가 이상하게 묶인 소자(NMOS 벌크가 전원 등)는 그대로 그리고 주석·질문.
2. **CMOS 역할 추가** (§3.1 표에 더함):
   | 역할 | 구조 |
   |---|---|
   | 정적 CMOS 게이트 (확장) | 풀업·풀다운 사슬의 게이트 집합이 같다 — **제어·바이어스 게이트(헤더/풋터 스위치, 다리 enable)는 빼고** 비교. 인버터·NAND·NOR·스택형 모두 |
   | 클럭드 인버터 / C2MOS | 출력에 가까운 직렬 PMOS·NMOS의 게이트가 상보 클럭 쌍, 레일 쪽 게이트가 데이터. 출력 노드에 인버터 귀환이 있으면 latch |
   | tristate / MUX | 같은 구조인데 상보 쌍이 정적 선택 신호 → 선택 게이트 |
   | 전달 게이트 3종 | 항상 켜짐(NMOS→전원, PMOS→접지) = **연결**로 추적, 질문 없음 / 항상 꺼짐 = **끊김** / 상보 선택 신호 = 선택 스위치 |
   | 전류 미러 | 다이오드 노드 = 바이어스, 미러 게이트에서 추적 멈춤 |
3. **클럭 역할 게이트 정의 (순환 금지)**: 다음 구조가 먼저 있어야 클럭 역할이다 — ① 클럭 꼬리: 먹이는 쌍이 cross-coupled 노드나 latch 노드로 이어짐, ② 리셋·프리차지: 클럭 꼬리와 게이트를 공유하고 cross-coupled 노드 옆, ③ 스티어링: 드레인이 다른 쌍의 공통 소스 (부하 없음), ④ C2MOS latch의 상보 게이트. **cross-coupled 소자는 먼저 빼고** 판정한다. 이 판정에는 넷 이름을 쓰지 않는다.
4. **공통모드 노드**: 차동쌍 두 선에서 **같은 값 R 정확히 두 개**가 모이고 다른 신호 경로가 없는 노드만. (R 여러 개가 모이는 SST 출력 노드는 신호다.)

### 11.2 분석 — 신호 추적
1. **멈추는 곳 추가**: 미러 게이트, 항상 꺼진 전달 게이트, **RC 저역통과**(직렬 R 뒤 노드에 접지/전원으로 C, 또는 그 사다리).
2. **새 분류 "느린 신호(검출)"**: RC 저역통과 뒤에서 시작해 추적되는 넷(평균값, 비교기 판정, 루프 필터). 그림: 실선 (v4.1, §13.5-8 — 점선 쓰지 않음). 이 신호를 받는 비교기의 클럭은 클럭으로 둔다.
3. **÷2 / 분주기**: latch·DFF의 데이터 입력이 (인버터를 거쳐) 자기 출력에서만 오고 클럭 핀에 클럭이 들어오면 분주기 → 출력은 **클럭**.
4. **미구동 넷**: 구동원이 없고 고속 핀에만 닿는 넷(꺼진 전달 게이트 뒤 등)은 "고속(미구동)" — 그 핀 분류로 그리고 이름표로 끝내며 질문한다.
5. **입력 포트 판정 보강 (§3.2)**: 클럭이 버퍼 사슬과 RC 저역통과를 거쳐 비교기 데이터 입력에 닿아도 데이터 입력이 아니다(2번에서 멈춤). 클럭을 거르는 정적 게이트(NAND/AND)의 다른 입력은 **enable(일반 제어)** 후보.

### 11.3 분석 — 제어 분류
1. **중요 제어** (§3.3 대체): 아래 중 하나
   - (a) 다른 고속 신호를 섞는 가중치 — DFE·FFE 탭 계수, PI 가중치
   - (b) 서로 다른 고속 신호 중 하나를 골라 고속 노드에서 합산되게 하는 **탭 선택** (FFE의 슬라이스별 pre/main/post 선택)
   - (c) **블록의 주 기능을 정하는 코드** — 듀티·지연·위상 조정 코드, P/N에 반대 극성으로 들어가는 보정 코드
2. **일반 제어**: 이득, 피킹, 대역폭, 종단·임피던스 보정(zcal), 세그먼트 enable(드라이버 세기), oe, idle, 모드·초퍼 선택, enable.
3. 중요 제어를 만드는 **디코더는 생략하지 않고 "DEC" 박스**로 그린다 (입력 코드 버스 → DEC → 출력 버스).
4. 숨긴 선택 신호 때문에 스위치·전달 게이트가 동시에 켜진 것처럼 보이면, 그 선택 핀만 **회색 짧은 선 + 회색 이름표**로 남긴다 (버스로 그리지 않음).
5. 같은 기능 비트는 버스 하나. 이름이 달라 하나의 버스 이름으로 펼칠 수 없으면 버스를 나눈다.

### 11.4 그리기 — 기호
| 대상 | 기호 |
|---|---|
| **MUX** | 사다리꼴: 왼쪽 변 높이 = 입력 수×20+20, 오른쪽 변 = 왼쪽의 0.6배, 폭 50. 선택 핀은 아래 경사면 |
| **반전 블록** | 입력→출력이 반전이면 출력에 동그라미(r4). 한 기능을 여러 블록으로 나눠 그렸으면 블록마다 극성이 netlist와 맞아야 한다 |
| **가변 세기 인버터** (다리 헤더/풋터로 세기를 바꾸는 인버터, DCC 조정단) | 인버터 삼각형 + 위(PU)·아래(PD)에 가변 전류원 기호, 코드 핀 |
| **SST/전압모드 드라이버 슬라이스** | 풀업 = 가변 저항(+직렬 R), 풀다운 = 거울상 아래, 출력은 가운데. 게이트 로직은 NAND/NOR 기호 |
| **부하 C** (노드에서 접지로) | 선 위 짧은 가지 + 커패시터 + 접지 기호, 값 표시 |
| **출력 패드 ESD / 킵퍼** | 출력선 위 작은 박스 "ESD" / 종단 표시와 같은 모양에 "KEEP" |
| **선택 스위치** (상보 선택 전달 게이트) | 스위치 기호 + 회색 선택 핀 |
| **종단 끝** | 숨긴 공통모드 쪽은 열린 원(r3), 이름표 없음 |
| **논리 게이트의 숨긴 입력** | 회색 짧은 선 + 회색 이름표 (예: EN) — 1입력 NAND처럼 보이지 않게 |

### 11.5 그리기 — 배치·이름표·크기
1. **짝 없는 이름표 예외** (§4-8, §6-2 보강): ① 미사용 출력, ② 화면 경계를 넘는 넷(유닛 화면·가상 블록 화면에서 부모로 나가는 넷). 경계 넷은 **화면 밖 연결 기호**(작은 오각 화살표 + 이름)로 그려 일반 이름표와 구분한다.
2. ~~미사용 보조 출력: 핀만 남기고 이름표 없음~~ → §13.5-10으로 대체 (핀만 떠 있는 출력 금지).
3. **반복 인스턴스 합치기**: 같은 셀이 같은 연결 패턴으로 여러 번(드라이버 세그먼트, DCC 다리) → 블록 하나 `xi<4:0>` + 배수(m=1,2,4,8,16) 표기 + 범례. 사슬로 이어진 인버터들은 버퍼 블록 하나.
4. **같은 가상 블록이 여럿이면 화면 하나**, 핀 이름은 일반 이름(in/out), 인스턴스별 넷은 범례 표.
5. **유닛 화면 크기 상한**: 그린 기호가 20개를 넘으면 이 순서로 줄인다 — ① 같은 역할 반복을 하나로 합침(`M<3:0>`), ② 묶음을 개념 기호로 바꿈(가변 R/C/전류원, 게이트 로직은 NAND/NOR 기호), ③ 그래도 넘으면 기능 단위로 화면을 나눔(예: 게이트 로직 / 출력단), 나눈 화면 사이는 화면 밖 연결 기호. 폰에서 읽힐 필요는 없다.
6. **크기 표기**: SI 접두어로 `600n/30n`, `16u/45n` (원래 문자열은 툴팁). §6.5의 "netlist 표기 그대로"를 대체한다.
7. **버스 이름표**: 이름에 `<a:b>`가 들어 있으면 비트 수 표시 생략, 아니면 사선 + 비트 수.
8. **접점**: 한 점에 선분 3개까지(4방향 금지). 서로 다른 넷의 선 끝이 같은 직선 위에 있으면 40px 이상 떨어뜨린다.
9. **S/D 방향**: 그릴 때 소스를 레일 쪽으로 뒤집어도 된다 (연결 검증은 소스/드레인 구분 없이 채널 두 끝으로).
10. **생략 목록 일관성**: 그 화면에 선으로 그린 넷은 생략 목록에 넣지 않는다.
11. **설명 문구**: 블록 설명(예: "반전")은 netlist 극성과 맞아야 한다.

### 11.6 질문과 산출물
1. 질문은 **템플릿 문장**으로 만든다 (회로 이름을 코드에 박지 않는다): "`<항목>`: 구조는 `<A>`인데 이름/기능은 `<B>`입니다. (A로 / B로)".
2. 계획서에 이미 규칙이 있는 항목은 묻지 않는다 (예: 미사용 출력).
3. 구조 규칙과 그럴듯함이 충돌하면 **구조 규칙대로 분류하고 질문**한다. 사용자가 없으면 구조 답을 쓰되, §11.2처럼 규칙이 보강된 경우는 보강된 규칙을 따른다.
4. 블록 사전에 추가: C2MOS latch(→ Latch/DFF), CML→CMOS 변환기("C2C" 삼각형), OTA(삼각형 "OTA"), RC 평균기("LPF" 박스), DCC 조정단(가변 세기 인버터), 분주기("÷2").

### 11.7 테스트 모음 (최소)
기준 RX AFE와 **다른** netlist로만 일반성을 판정한다: ① Rx 변형(넷·셀 이름 섞기, 구조 일부 변경), ② Tx(SST + FFE), ③ DCC. 기준 결과를 그대로 재현하는 실행은 일반성 증거로 세지 않는다.


## 12. 산출물 형식 계약과 검증 루프 (루프 1회차 후 사용자 결정)

### 12.1 공통 형식
1. **선 굵기**: 모든 배선 1.6px (데이터·클럭·버스 같음). 버스는 사선 + 비트 수 + 이름으로 구분.

### 12.3 검증 루프
- **안쪽 루프 (AGENT 2 ↔ AGENT 3, 회로마다)**: 원인이 "그린 쪽"인 불통과 항목을 근거·캡처와 함께 AGENT 2에게 돌려보내 고치게 하고 AGENT 3이 다시 채운다. **최대 3번**. 3번 안에 못 고치면 명세서 문제로 넘긴다.
- **바깥 루프 (오케스트레이터)**: 원인이 "명세서"인 항목과 안쪽 루프에서 못 고친 항목으로 명세서를 고친다. 세 회로가 모두 ★ 통과하고 명세서 원인 항목이 없을 때만 승인. 다음 회차는 사용자 승인 후.

### 12.4 고속과 무관한 블록 (ODT 로직, 보정 FSM, 레지스터 등)
- 고속 넷과 연결이 없는 블록 → 생략, 생략 목록에 "블록 (셀) — 고속 신호와 무관".
- 고속 노드에 직접 붙는 부분(ODT 종단 다리, 보정 DAC가 바꾸는 저항·전류)은 그 자리의 **개념 기호**로 그린다 (예: ODT → 입출력선 위 가변 종단 R). 그 코드는 §11.3 분류를 따른다(종단·임피던스 보정 = 일반 제어 → 숨김).
- 그 코드를 만드는 로직(ODT 디코더, 보정 FSM)은 생략한다. 단 중요 제어를 만드는 디코더는 DEC 박스(§11.3-3).


## 13. v4 보강 (루프 2회차: BIST·ZQ 보정·DQS-RX, 정답지 대조 결과)

> 2회차에서 세 회로 모두 그린 쪽 불통과는 라운드 2에 0이 되었고, 남은 ★ 불통과는 전부 "고속이 아닌 신호를 어떻게 분류·표시하나"가 명세에 없어서였다. 아래는 그 규칙과 사용자 결정이다. **§13이 앞 절과 다르면 §13이 이긴다.**

### 13.1 새 분류 (§3.3 표에 더함)
| 분류 | 정의 | 그림 |
|---|---|---|
| **기준 전압** | 비교기·프리앰프·샘플러의 한쪽 입력으로 들어가 판정 기준이 되는 전압 (VREF, VREFDQ) | **그린다**: 회색 실선 + 이름표, 받는 블록의 둘째 입력 핀. 만드는 DAC는 "VREF" 박스 |
| **상태·시험 출력** | 진행·결과 상태(busy, done, lock, err, 오류 카운트, overflow 플래그), 모니터 출력 | **그린다** (사용자 결정): 실선 + 출력 포트. 모니터는 이름 옆 "(mon)" |
| **명령 입력** | 블록 동작을 시작·정지·적재·갱신하는 1회성 입력 (start, stop, latch/load, update) | **그린다** (사용자 결정): 받는 블록으로 가는 실선 한 줄 + 이름표, 버스 아님 |
| **워드 속도 디지털** | 1:N 디시리얼라이저의 워드 출력 뒤 / N:1 직렬화기의 워드 입력 앞의 데이터와 그것만 다루는 로직 (PRBS 생성·검사기, 카운터, 잠금 검출) | **최상위에 박스로만** (사용자 결정). 하위 화면을 만들지 않고 생략 목록에 "워드 속도 디지털 — 박스로만" |

### 13.2 중요 제어 (§11.3-1에 (d)·(e) 추가, 사용자 결정)
- (d) **데이터 경로의 판정 결과를 바꾸는 다비트 코드**: 수신기 VREF 레벨 코드, 여러 비트가 공유하는 VGA 이득 코드. → 중요 제어(버스). *부록 A(RX AFE)의 이득 코드 G<3:0>도 이 규칙에 따라 중요 제어로 바뀐다.*
- (e) **명령 입력과 모드 레지스터**: start/stop/load 명령, 고속 경로의 원천·패턴·경로를 고르는 모드 비트(PRBS 다항식, 내부 루프백/외부 입력, 오류 주입). 레지스터 데이터 포트는 기능 하나 = 버스 하나.
- §11.3-2의 "모드 선택"은 **한 경로 안의 아날로그 동작 모드**(초퍼, 저전력)로 좁힌다. 고속 신호의 원천을 바꾸는 선택(루프백 MUX)은 (b).
- 중요 제어를 받는 **제어 FSM·모드 레지스터는 생략하지 않고 박스**로 그린다 (§12.4 예외). 그 출력 중 고속 블록을 켜고 끄는 run/enable 묶음은 버스 하나.

### 13.3 블록 사전 보정 (§3.4)
- **VGA** = 이득 단을 스위치로 더하는 차동쌍 **또는 코드로 degeneration R을 바꾸는 차동쌍**(C는 고정·작음). **CTLE** = C가 영점을 만드는 degeneration(가변 C 또는 피킹용 큰 C). 이름과 구조가 맞으면 묻지 않는다.
- **고속 경로가 없는 보정 회로**(ZQ 등): 보정 루프(아날로그 노드 → 비교기 → SAR/카운터 → 코드 → 복제 다리)를 주 경로로 그리고, FSM은 그 루프와 주고받는 명령·상태·단계 선택만 보인다. 단계 선택(예: 비교기 입력 교차)은 회색 선택 핀.
- 논리 게이트(INV/NAND/NOR/AND/OR/XOR), SR latch, TG latch/DFF, 클럭 게이팅 셀(ICG), 지연 셀(DLY), 레벨 시프터(LS), CML→CMOS(C2C), OTA를 사전에 넣는다 — 묻지 않는다.

### 13.4 추적 규칙 보정 (§3.2, §11.2)
1. **배선 RC 예외**: 직렬 R + 접지 C라도 τ=RC가 단위 간격의 1/20보다 작고(또는 10ps 미만) 뒤에서 같은 신호를 다시 구동하면 **배선 RC** — 추적을 계속한다. 그림: 선 위 "RC" 표시(값 함께).
2. **리플 카운터 예외**: 각 단이 앞 단 출력으로 클럭되는 사슬의 Q는 **계수(상태 출력)**이지 클럭이 아니다. 분주기 출력이 클럭인 것은 그 출력이 다른 블록의 클럭 핀을 구동할 때만.
3. **사건 플래그**: D가 상수이고 클럭·리셋이 있는 플립플롭의 출력은 sticky 상태 출력(상수 아님).
4. **포트 방향**: 블록 안 출력단이 구동하는 포트는 출력. 같은 넷을 안에서 다시 읽어도(루프백 탭) 입력으로 세지 않는다.
5. **의사 차동쌍**: 한쪽 게이트가 기준 전압인 쌍은 두 드레인 모두 신호.
6. **비동기 set/reset 핀**은 데이터 추적 대상이 아니다.
7. **TG latch/DFF의 상보 게이트**는 클럭 역할 게이트다 (§11.1-3에 ⑤).
8. **고속 입력 후보는 차동 포트 쌍 또는 종단·ESD가 붙은 패드**만. 단일 디지털 포트는 §3.2로 데이터가 되지 않는다.
9. 구조 답을 쓰면 클럭·고속 입력이 사라지는 경우에는 그럴듯한 답을 쓰고 질문을 남긴다 (§11.6-3 보정).

### 13.5 그리기 보정
1. **버스 표시**: 이름에 `<a:b>`가 있으면 사선은 그리고 비트 수는 쓰지 않는다. 없으면 사선 + 비트 수.
2. ~~점선도 1.6px~~ → §13.5-8로 대체 (점선 쓰지 않음).
3. **버스 줄기 + 비트 가지**: 버스선에서 갈라지는 가지는 비트 이름표(`rx_d<2>`)를 단다. 가지는 버스와 같은 넷으로 합치지 않고 "그 버스의 한 비트"로 검증한다.
4. **출력 이름의 좌우**: 차동 출력의 좌우는 netlist에서 어느 입력이 구동하는지로 정한다(INP가 구동하는 쪽이 INP 쪽). 이름이 반대면 그대로 쓰고 주석.
5. **설명 문구**: 수치·비교·"같다/다르다" 주장은 netlist에서 읽어 확인한 것만 쓴다.
6. **합친 블록의 범례 필수**: 인스턴스별 넷 대응.
7. **생략 목록**: 그 화면에 선·검은 이름표·포트·전원 기호로 그린 넷은 빼고, 한 넷은 한 번만.
8. **모든 배선은 실선** (사용자 결정, v4.1): 고속·느린 신호·상태 출력·클럭·버스 구분 없이 1.6px 실선. 느린 신호·상태 출력은 분류 표와 화면 설명에만 표시한다. §11.2-2와 §13.1의 점선 표기를 대체한다.
9. **cross-coupled 인버터 쌍(CCI, 키퍼·latch 코어)** (사용자 결정, v4.1): 두 노드를 위아래 가로선으로 두고, 인버터 두 개를 **각각 90° 돌려** 나란히 세운다 — 하나는 위 노드 → 아래 노드(아래를 향함), 다른 하나는 아래 노드 → 위 노드(위를 향함). 노드를 돌아가는 선이 없어야 한다. CCI에 한해 왼→오 흐름 규칙(§4-5)과 기호 방향 규칙의 예외.
10. **미사용 출력은 모두 짧은 선 + 넷 이름표** (사용자 결정 5-4로 통일, v4.1): 보조 출력(qb, 쓰지 않는 q)도 같다. 핀 리드만 있고 아무것도 없는 출력은 금지. 생략 목록에는 넣지 않는다(그렸으므로).

### 13.6 체크리스트·루프 보정 (§12.2, §12.3)
1. **AGENT 2 자체 점검 산출물**: `out/self_checklist.json` (§12.2와 같은 형식). 아래 5개는 **자동 검사**로 채운다: 떠 있는 포트(모든 포트 기호에서 선이 시작), 생략 목록 ↔ 그린 넷, 같은 넷의 화면 간 선 종류 일치, 합친 블록 범례 유무, 설명 문구의 수치가 netlist와 일치.
2. **G1을 넷으로**: G1a ★ 포트 분류 · G1b ★ 블록 역할 · G1c ★ 신호 흐름 · G1d 극성 — 정답지 대조 (정답지가 있을 때만).
3. **AGENT 3 반송 파일**: 그린 쪽 불통과마다 `fix_request.md`에 근거(netlist 줄, 명세 조항)와 고칠 내용만 쓴다. **정답지 내용은 넣지 않는다.** 오케스트레이터는 이 파일을 그대로 AGENT 2에게 전달.
4. 판정: ★ 항목 통과 + 명세서 원인 0 = 회로 합격. 안쪽 루프 최대 3번.
