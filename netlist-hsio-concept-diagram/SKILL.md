# 넷리스트 기반 High-Speed IO 개념도 그리기 — 구현·사용 가이드

> **명세서 v2**: `DRAWING_PLAN.md` §11(루프 1회차 보강 규칙)이 이 문서의 해당 절보다 우선한다 — 여러 전원, CMOS·C2MOS·MUX·SST 역할, 순환 없는 클럭 역할 판정, RC 저역통과에서 멈춤과 "느린 신호" 분류, 넓어진 중요 제어 정의, 새 기호, 짝 없는 이름표 예외, 반복 인스턴스 합치기, 유닛 화면 크기 상한, SI 크기 표기.

이 문서는 **처음 보는 LLM이 이 문서와 같은 폴더의 파일만으로 똑같은 그림을 그리게** 하려고 쓴 가이드다.
"똑같은 그림"의 뜻: 같은 netlist에서 **같은 분류, 같은 화면 목록, 같은 기호, 같은 배치 순서와 방향, 같은 선/이름표 선택, 같은 교차 수**가 나온다. 좌표가 몇 px 다른 것은 괜찮지만 구조가 다르면 틀린 것이다.

## 4. 분석 — 정확한 절차

### 4.1 파싱
- `*` 줄 주석, `$` 뒤 주석(줄 맨 앞이거나 앞이 공백일 때), `+` 줄은 앞 줄에 이어 붙임, 대소문자 무시(처음 나온 철자를 대표로).
- `.subckt/.ends`, `.include`(있으면 펼침), `.param`, `.global`, `.model`(nmos/pmos 판별). 소자: `M d g s b model k=v`, `R/C/L n1 n2 value`, `X nodes… subckt`. 그 외 dot 카드는 무시.
- `..SUBCKT`처럼 점이 두 개인 오타도 `.SUBCKT`로 읽는다 (Gemini가 만든 netlist에서 실제로 나옴).
- MOS 극성: `.model` 타입 → 모델 이름 힌트(`p`, `pch`, `pmos` / `n`, `nch`, `nmos`).
- top: 다른 셀이 인스턴스하지 않는 셀 중 계층이 가장 깊은 것.
- 값은 netlist 표기 그대로 보관하고, 그림에는 SI 접두어로 쓴다 (`600e-9` → `600n`, 계획서 §11.5-6).

### 4.2 평탄화
- 소자 경로 이름(`X_DFE_EVEN/X_SUM/M_MP`)과 핀별 평탄 넷(`X_DFE_EVEN/SUMP`)을 만든다. 포트 넷은 부모 넷으로 이어진다.
- 셀마다 `로컬 넷 ↔ 평탄 넷` 표(인스턴스마다)를 둔다. 분류는 평탄 넷에서 하고, 셀 로컬 넷의 분류는 **그 셀의 모든 인스턴스에서 받은 분류의 합집합**이다.

### 4.3 전원
- 전원·접지 = PMOS 벌크에 쓰인 넷 **모두** 전원, NMOS 벌크에 쓰인 넷 **모두** 접지 (계획서 §11.1-1). 이름(`VDD`, `VSS`, `GND`, `AVDD`…)은 확인용.

### 4.4 소자 역할 판정 (이 순서로, 먼저 맞은 것이 이긴다)
계획서 §3.1의 표를 구현한다. 순서가 중요하다.
1. **반복 단위 합치기 후보**: 이름의 숫자만 다르고 연결 구조가 같은 소자 묶음 (`MS_G0..3` → `MS_G<0:3>`), 같은 두 넷 사이 병렬 수동소자.
2. **정적 CMOS 게이트**: 같은 입력 넷을 게이트로 받는 NMOS·PMOS가 같은 출력 넷을 구동 (인버터·NAND·NOR). 리셋·꼬리보다 먼저.
3. **전달 게이트**: 같은 두 넷 사이 NMOS+PMOS. 게이트가 켜는 전원(NMOS→전원, PMOS→접지)이면 항상 켜짐, 끄는 전원(NMOS→접지, PMOS→전원)이면 **항상 꺼짐**.
4. **다이오드·미러**: 게이트 = 드레인.
5. **cross-coupled 쌍**: g1 = d2, g2 = d1.
6. **꼬리 전류원 / 클럭 꼬리**: 소스가 전원·접지, 드레인이 같은 극성 차동쌍의 공통 소스 노드. 게이트가 바이어스면 꼬리, 클럭이면 클럭 꼬리. **극성이 반대면 꼬리가 아니라 리셋·프리차지.**
7. **클럭 스티어링 쌍**: 소스 공유, 게이트가 클럭 P/N, 두 드레인이 각각 다른 차동쌍의 공통 소스 노드 (CML latch).
8. **리셋·프리차지**: 게이트가 클럭, 소스가 전원, 드레인이 내부 노드.
9. **입력 트랜지스터(차동쌍)**: 게이트가 신호, 드레인에 부하, 소스가 꼬리·degeneration 노드. 쌍 = 같은 크기·같은 소스 노드.
10. **캐스코드·스택**: 소스가 다른 소자의 드레인(전원 아님).
11. **부하**: 전원으로 가는 R, 게이트가 고정 전위인 PMOS, 다이오드 연결, active inductor(게이트에 R이 걸린 MOS).
12. **스위치**: 게이트가 정적 제어, 채널이 R·C·전류원과 직렬이거나 두 노드 사이.
13. **종단**: 고속 입력에서 공통모드 노드·전원으로 가는 R. **ESD**: 패드에서 전원으로, 게이트가 전원에 묶인 MOS. **디커플링**: DC 노드에서 전원으로 가는 C.
14. 나머지: "모름".

### 4.5 신호 추적 (작업 목록)
평탄 그래프에서 고속 데이터 입력 집합으로 시작하는 작업 목록 알고리즘. 넷 하나를 꺼내 그 넷에 닿는 소자마다 아래 규칙을 적용하고, 새로 표시된 넷을 목록에 넣는다. 클럭은 클럭 입력에서 **따로** 같은 방법으로 돈다.

| 지나는 곳 | 규칙 |
|---|---|
| 입력 트랜지스터 | 게이트가 신호 → 드레인이 신호 (소스 팔로워면 소스도) |
| 캐스코드·스택 | 소스가 신호(전원 아님) → 드레인이 신호. 게이트가 무엇이든 같다 (StrongARM의 cross-coupled NMOS) |
| 정적 CMOS 게이트 | 입력이 신호 → 출력이 같은 분류 (인버터 체인 = 버퍼) |
| cross-coupled 쌍 | 한쪽 드레인이 신호 → 양쪽 모두 |
| 직렬 수동소자 | 두 비전원 노드 사이 R·C·L은 양끝 같은 분류. 전원·공통모드 노드로 가는 것은 제외 |
| 전달 게이트 | 켜질 수 있으면 양끝 같은 분류. **항상 꺼진 것은 끊긴 것** (전달 안 함, 질문) |
| latch·flip-flop·샘플러 | 출력 분류 = **데이터 입력의 분류** (클럭이 데이터 입력에 들어오면 출력도 클럭 — 분주기·I/Q). 클럭 핀은 출력을 클럭으로 만들지 않는다 |
| 피드백 | 그대로 따라간다 |
| **멈춤** | 전원, 꼬리·캐스코드의 게이트(바이어스), 스위치 게이트(제어), **클럭 역할 게이트**(클럭 꼬리·스티어링·리셋·프리차지) — 이 소자들의 드레인은 클럭이 아니다 |

- 데이터와 클럭 양쪽에서 닿는 넷은 질문 대상.
- 추적으로 닿았지만 아무것도 구동하지 않는 출력(미사용 출력)은 분류를 그대로 두고 `unused_output` 표시만 붙인다 (지우지 않는다, §7).

### 4.6 입력 포트 분류 (구조로)
최상위 입력 포트마다 4.5 규칙으로 추적했을 때:
- **클럭 역할 게이트에 하나라도 도달** → 클럭 입력 (latch 데이터 입력에도 닿을 수 있다).
- 클럭 역할 게이트에 닿지 않고 입력 트랜지스터를 거쳐 latch·샘플러의 **데이터 입력**에 도달 → 고속 데이터 입력.
- 둘 다 아님 → 제어/바이어스/전원 후보 (4.7) 또는 질문.
- 이름은 **확신도에만** 쓴다: 구조와 이름이 맞으면 높음, 어긋나면 낮음(질문).

### 4.7 추적되지 않은 넷: 제어·바이어스
- **중요 제어**: 제어 → 스위치/DAC → 어떤 가지의 전류(꼬리), 그리고 그 가지의 입력이 **주 입력과 다른 고속 신호**이고 출력이 고속 노드에서 **합산**. (주 쌍 = 데이터 입력에서 BFS 거리가 가장 짧은 쌍.) 예: DFE 탭 계수, FFE 탭, PI 가중치.
- **일반 제어**: 한 경로의 파라미터만 조절 — 이득 단(같은 입력의 추가 쌍), degeneration R/C 뱅크, 대역폭, 트림, 모드.
- **바이어스**: 꼬리·캐스코드 게이트, 다이오드 노드, 기준 전류, **공통모드 노드**(종단 중점 포함).
- **전원**: 4.3.
- 같은 기능의 중요 제어 비트는 버스 하나로 묶는다 (n차원 이름: `W1_0..W4_3` → `W<1:4>_<0:3>`, 16비트).

### 4.8 셀 단위 분류
셀 로컬 넷 분류 = 인스턴스 합집합. 그릴 때 하나만 고를 때의 우선순위: 데이터 > 클럭 > 중요 제어 > 일반 제어 > 바이어스 > 전원. **한 곳에서라도 보이는 핀은 그 셀의 모든 화면에서 보인다.**

### 4.9 블록 역할 (계획서 §3.4 사전)
셀마다 구조 특징으로 역할을 정한다: `ctle`(degeneration R∥C 차동쌍), `vga`(같은 입력의 추가 쌍을 스위치로 더함), `summer`(다른 입력의 쌍들이 같은 출력에 합산), `strongarm`, `latch`(cross-coupled + 클럭 스티어링), `dff`(latch 두 개 직렬, 클럭 반대), `cml_buffer`, `inverter`, `dac`, `bias`, `composite`(하위가 **모두** 사전에 있는 블록 — 묻지 않음), `unknown`(질문).
- 이름과 구조가 다르면 **구조로 고르고 묻는다** (이름은 ÷2인데 루프가 없으면 LATCH 두 개).
- **고속 신호와 연결이 없는 블록**(바이어스 발생기 등)은 생략하고 생략 목록에.

### 4.10 묶음과 개념 기호 대상 (계획서 §5.1)
- 스위치 R 뱅크, 두 노드 사이 저항으로 쓰는 스위치 MOS 묶음 → **가변 저항**. 고정 R이 병렬이면 하나로 합침.
- 스위치 C 뱅크 → **가변 커패시터**. 스위치 없이 항상 붙은 C들은 **고정 C 하나**로 합침.
- 전류 DAC(스위치 + 전류원 반복), 스위치로 켜는 꼬리 → **가변 전류원**. 중요 제어가 들어가면 버스 핀을 단다.
- 같은 역할 반복 소자(이득 단 쌍 ×4) → 하나로 `M_G<0:3>_P`, 크기는 전부 나열.
- 기호가 대신하는 소자 목록은 화면 아래 "묶음·병합" 범례에 적는다.

### 4.11 확신도와 질문
판단마다 높음/낮음. 낮음만 묻는다. **반드시 묻는 경우**: 고속 입력을 구조로 못 찾음 / 블랙박스가 고속 경로에 있음 / 이름과 구조가 다름 / MUX 선택이 클럭인지 제어인지 불분명 / 중요·일반 제어 불분명 / 항상 꺼진 전달 게이트 / 짝 없는 소자 / 사전에 없는 블록. 질문 문장은 선택지로 짧게.

## 7. 블록 레벨 배치·배선 (모든 계층 공통, 결정적 절차)

**원칙**: 보이는 넷(고속 데이터, 고속 클럭, 중요 제어)만. 나머지는 선·이름표·핀·포트 **모두 없음**. 생략은 사이드 패널과 PPT 메모의 생략 목록에만 (다시 켜는 토글 없음).

1. **기호 고르기**: 역할 → ctle/vga/cml_buffer/strongarm = 삼각형(SA는 클럭 표시), summer = Σ 박스, latch = LATCH 박스, dff = DFF 박스, composite·unknown = 박스(셀 이름), inverter = 인버터, 종단·ESD = 입력선 표시, 항상 꺼진 TG = 열린 스위치.
2. **핀 쪽**: 데이터 입력 왼쪽(주 입력 P, N 먼저, 그다음 피드백·탭 입력을 합산되는 탭 순서로), 데이터 출력 오른쪽(주 출력 먼저), 클럭 아래(CLK, CLKB 순), 중요 제어 버스 위. **P 위, N 아래.** 핀 간격 20.
3. **열(층)**: 데이터 그래프(출력 핀 → 같은 넷의 입력 핀)를 고속 입력이 들어가는 블록부터 DFS, 되돌아가는 간선은 피드백으로 빼고, 최장 경로로 층을 정한다. 주 경로는 **한 줄(같은 높이)로 곧게**, 블록 사이 간격 약 80px(삼각형은 160px 피치).
4. **병렬 블록**(같은 셀, 같은 주 입력 — 예: even/odd 슬라이스): 같은 열에 위아래로 netlist 순서대로 쌓는다 (기준: y 125, 445).
5. **클럭만 다루는 블록**(보이는 핀이 모두 클럭): 주 경로 아래 행, 왼쪽부터. 클럭 입력 포트는 그 행의 왼쪽 끝.
6. **포트**: 입력은 왼쪽 끝, 출력은 오른쪽 끝, 연결된 핀과 같은 높이. 중요 제어 버스 포트는 첫 받는 블록 바로 위에서 아래로. 생략된 넷의 포트는 없다.
7. **선 또는 이름표 (사용자 결정, 계획서 §4-8)**: 넷마다 아래 순서로 선을 시도하고, **교차나 우회가 생기면 그 핀은 이름표**로 연결한다.
   - 순서: (a) 주 경로 층 사이 데이터 → (b) 출력 포트 → (c) 중요 제어 버스 줄기 → (d) 클럭 → (e) 피드백.
   - 후보 경로: 직선 → ㄱ자(가로 먼저) → ㄱ자(세로 먼저) → Z자(가운데 세로). 첫 번째로 아래를 모두 만족하는 것:
     교차 0 · 블록 몸통(±9) 관통 없음 · 길이 ≤ 1.5 × (|Δx|+|Δy|) · 새 접점이 기존 접점에서 20px 이상 · 꺾인 선분 20px 이상.
   - 여러 핀 넷: 구동 핀에서 줄기를 만들고 가까운 핀부터 붙인다. 실패한 핀만 이름표.
   - 이름표는 핀에서 짧은 선(40~46px) + 넷 이름. **같은 이름표는 화면 안에 짝(선에 붙은 같은 이름의 이름표나 그 넷의 포트)이 있어야 한다.** 구동 쪽 선 끝에도 같은 이름을 붙인다.
   - 차동이면 P/N 둘 다 이름표, 버스면 이름표에도 비트 수.
   - 결과적으로 블록 레벨 교차는 **0개**여야 한다.
8. **미사용 출력**: 지우지 않는다. 짧은 선 + 넷 이름표로 끝낸다. 그것을 구동하는 소자(더미 인버터 등)도 그린다.
9. 인스턴스 이름은 기호 위, 셀 이름은 아래. 글자가 선·다른 글자와 겹치면 후보 위치(위/아래/오른쪽 위…)로 옮긴다.

공통 (계획서 §5): 차동은 **무조건 한 축 대칭**(P 왼쪽, N 오른쪽, 거울상), 레일은 위(VDD 가로선) 아래(접지 기호), PMOS는 NMOS보다 위, 게이트 입력 포트는 게이트에서 40px 바깥, 숨긴 넷 게이트는 회색 이름표, 출력 포트는 출력 노드 높이의 가장자리. 좌표의 정답은 기준 코드의 함수.

## 9. 검증 (계획서 §6)

1. **연결 재추출 — 그림의 기하만 사용**: 선 끝점, 핀 좌표, 접점 점, 이름표·포트·전원 기호의 앵커만 읽는다 (선에 붙은 넷 이름 속성은 쓰지 않는다).
   - 선 끝이 다른 선 위에 닿으면 T 연결(접점 점 필수). 끝 없이 두 선이 지나가면 **교차 = 연결 아님**.
   - 같은 화면의 같은 이름표/포트 이름 = 같은 넷. 짝 없는 이름표는 오류.
   - 합친 소자는 비트별로 펼쳐 대조, 개념 기호는 "기호 단자 = 묶음의 바깥 넷"으로 대조.
   - 오류: 핀 누락, 없는 핀, OPEN(한 넷이 조각남), SHORT(두 넷이 한 덩어리), 이름표가 다른 넷 위.
2. **보이는 고속 넷 완전성**: 화면의 고속 넷은 그 화면의 모든 해당 핀까지 선 또는 이름표로 이어짐.
3. **생략 = 분류**: 그리지 않은 넷·블록은 전부 숨김 분류이고 생략 목록에 있음.
4. **기호 = 묶음**: 묶음의 모든 소자가 기호 하나에 속하고 묶음 안쪽 넷이 바깥에서 안 쓰임.
5. **품질 (모두 0)**:
   - 글씨 겹침 (브라우저 `getBBox`로 측정: `work/measure.js`), 선이 심볼 관통, 대칭 위반(쌍의 높이·거울 x), PMOS가 NMOS 아래.
   - **꼬임**: 선 길이 > 1.5 × (|Δx|+|Δy|).
   - **짧은 꺾임**: 꺾인 선분 < 20px. **접점 근접**: 접점 사이 < 20px. (정확히 20은 허용)
   - **교차**: 허용 목록 밖이면 위반. 블록 레벨 0. 유닛 레벨은 §8 표의 허용 수와 위치(템플릿이 선언한 자리 ±12px)만.
6. **검증기를 검증**: 일부러 오류를 넣어(포트 뒤바꿈, 선 삭제, 선 이동, 접점 삭제, 이름표 바꿈, 소자 삭제) 모두 잡히는지 확인.
7. **눈 확인**: 화면마다 스크린샷(deviceScaleFactor 1, 1820×1000), PPTX는 LibreOffice로 PNG 변환해서 본다.

## 10. HTML 뷰어와 PPTX

기준 구현: `work/render_html.py`, `work/make_pptx.py`.
- **HTML 구조**: 위 막대(`header`): 화면 제목, 경로 링크(‹›), 오른쪽에 `▲ 위로`(맨 위에서 비활성), 체크박스 `W/L·m 표시`(끄면 `body.nosize .size{display:none}`), `PPT 내려받기`(data: URI). 가운데 그림 카드(SVG), 오른쪽 사이드 패널(330px).
- **사이드 패널 순서**: 이 화면(셀·레벨, 클릭하면 내려가는 하위 목록) → 생략 목록(이 화면, `넷 — 분류` / `블록 (셀) — 이유`) → 주석 → 분류 요약(전체) → 가정한 답(질문) → 모든 화면 링크.
- **이동**: 블록 위 투명 클릭 영역(`hot` 사각형, 마우스 올리면 점선 강조) → 하위 화면. 주소 `#화면id`로 이동, 뒤로가기 동작.
- **모바일**: 900px 이하에서 사이드 패널이 아래로, 그림은 폭 640px 고정·카드 안 가로 스크롤 (페이지 자체는 가로로 넘치지 않음).
- **PPTX**: 13.333×7.5in, 1장 = 요약(분류 확인 표 + 가정한 답), 그다음 화면마다 1장(HTML 화면 순서). 그림은 PowerPoint 도형(선, 다각형, 원, 텍스트 상자)으로, 블록마다 투명 사각형 + 하위 슬라이드로 click_action, 오른쪽 위 `▲ 부모` 링크, **슬라이드 메모에 생략 목록**. 글꼴 Arial, 굵기·색은 HTML과 같게. PPTX에는 토글이 없으므로 W/L 글자는 항상 보인다(각각 따로 된 텍스트 상자라 지울 수 있다).

## 13. 앞선 시도에서 결과가 갈렸던 곳 (같은 실수 금지)

맥락 없는 에이전트 두 개에게 계획서만 주고 실행했을 때 서로 달랐던 지점이다. 지금은 모두 규칙으로 정해져 있다.
1. 블록 화면에서 피드백·클럭·두 번째 슬라이스를 전부 선으로 그려 교차 10개 → **교차·우회가 생기면 이름표** (§7-7).
2. "교차 1개만"을 문자 그대로 → 그림 B는 쌍마다 1개 (§8).
3. StrongARM의 cross-coupled NMOS에서 추적이 끊김 → 스택 규칙(소스→드레인).
4. 클럭 추적이 StrongARM·latch 내부 노드를 클럭으로 칠함 → 클럭 역할 게이트에서 멈춤.
5. 리셋 PMOS를 꼬리로 오인 → 꼬리는 같은 극성.
6. 인버터 PMOS를 리셋으로 오인 → 정적 CMOS 먼저.
7. 항상 꺼진 전달 게이트를 연결로 그림 → 끊긴 것 + 질문.
8. 짝 없는 소자를 축 위에 둠 → 연결된 쪽 바깥.
9. 부하 없는 출력을 지울지 고민 → 지우지 않는다 (이름표).
10. "피할 수 있는 교차"를 각자 선언해 검사를 무력화 → 허용 목록 고정.
11. 꼬임 기준 거리·20px 경계가 달라 결과가 다름 → 가로+세로 거리, 20 미만만 위반.
12. 섞인 셀을 유닛 화면에 블록 기호를 섞어 그림 → 자동 가상 블록.
13. "C 뱅크" 이름을 믿고 가변 C로 그림 → 구조를 따르고 묻는다.
