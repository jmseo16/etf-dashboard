hsio_draw — netlist에서 고속 IO 개념도를 그리는 도구

SPICE netlist 하나를 넣으면 신호를 분류하고, 블록 화면과 트랜지스터 화면을 모두 그리고, 그림 좌표만으로 연결을 다시 읽어 netlist와 대조한 결과까지 냅니다. 이 HTML 한 파일에 도구 소스 전부가 들어 있습니다.

1. 풀기

방법 A (권장) — 아래 스크립트를 restore.py로 저장하고 실행합니다. 파일마다 SHA-256을 확인합니다.

#!/usr/bin/env python3
"""usage: python3 restore.py HSIO_R0.3_DRAWTOOL.html [out dir]   -- unpacks every file and checks its SHA-256"""
import base64, hashlib, json, os, re, sys
src = open(sys.argv[1], encoding='utf-8').read()
out = sys.argv[2] if len(sys.argv) > 2 else '.'
m = re.search(r'<script id="bundle" type="application/json">(.*?)</script>', src, re.S)
bad = 0
for it in json.loads(m.group(1)):
    b = base64.b64decode(it['b64'])
    ok = hashlib.sha256(b).hexdigest() == it['sha256']
    bad += not ok
    p = os.path.join(out, it['path'])
    os.makedirs(os.path.dirname(p), exist_ok=True)
    open(p, 'wb').write(b)
    print('OK ' if ok else 'BAD', it['path'])
print(bad, 'checksum mismatches')
sys.exit(1 if bad else 0)


python3 restore.py HSIO_R0.3_DRAWTOOL.html .
# 모든 줄이 OK, 마지막 줄이 "0 checksum mismatches"

2. 필요한 것과 첫 실행

  • Python 3.8 이상 (필수). 추가 패키지 없이 HTML·검증 결과까지 나옵니다.
  • python-pptx (선택): 있으면 concept.pptx를 만들고 HTML에 넣습니다.
  • Node.js + Playwright (선택): 있으면 화면별 PNG를 만듭니다. 없으면 SVG만 남고 --no-png로 건너뜁니다.
python3 drawtool/hsio_draw.py sample/rx_s1/netlist.sp -o out_s1 --no-png
# 기대 결과 (v0.6):  views 15, connectivity 15, quality 15
#                       self-test: 111/111 injected errors caught; questions: 0

숫자가 다르면 풀기에서 파일이 바뀐 것입니다. out_s1/concept.html을 브라우저로 열어 그림을 확인합니다.

3. 검증 절차 (도구가 그린 뒤)

  1. 도구 안 (자동): 화면마다 연결 검사 6종, 품질 검사 14종, 오류 주입 시험. draw_report.md와 verify_report.json에 0건인지 확인합니다.
  2. 분류 확인: classification.md와 questions.json을 읽고, 틀렸다고 확신하는 것만 annotations.json에 적어 다시 실행합니다.
  3. 눈으로 검토: 최상위 화면과 대표 화면 3–5장을 직접 엽니다. 검증기가 세지 못하는 것(회로 묶음이 떨어져 놓임, 화면이 넓어 글자가 작음, 긴 직선)은 여기서만 잡힙니다.

5. 사용 설명 (README)

netlist 하나를 넣으면 분류 → 화면 구성 → 배치·배선 → 검증까지 한 번에 하고 결과를 폴더에 씁니다. 그림은 도구가 그립니다. 사람(또는 모델)이 할 일은 도구를 돌리고, 도구가 묻는 질문에 답하고, 결과를 확인하는 것뿐입니다.

실행

python3 tool/hsio_draw.py <netlist.sp> -o <결과 폴더>
python3 tool/hsio_draw.py <netlist.sp> -o <결과 폴더> --annotations <answers.json>   # 답을 넣어 다시 그리기

필요한 것: Python 3.8+. PPTX는 python-pptx, PNG는 Node.js + Playwright가 있으면 만들어집니다(없으면 그 파일만 빠지고 나머지는 나옵니다). 끝나면 한 줄 요약이 나옵니다: views N, connectivity N, quality N — 세 숫자가 같으면 모든 화면이 검사를 통과한 것입니다. 종료 코드는 모두 통과 0, 아니면 1.

질문에 답하기 / 분류 고치기 (annotations.json)

{
  "answers":        {"ctl:wl_ck": "K9"},
  "net_class":      {"some_port": "K3"},
  "block_role":     {"some_cell": "box"},
  "hide_instances": ["xi38"],
  "pairs":          [["ckp", "ckn"]]
}
  • answers: questions.json의 질문 id → 그 질문의 선택지 중 하나.
  • net_class: 최상위 포트의 분류를 직접 지정. 값: hs_data, hs_clock, reference, bias, hidden, K1 … K11.
  • block_role: 셀의 기호. 값: box, inv, buf, samp, sum, vref, dec, omit.
  • hide_instances: 그리지 않을 인스턴스 이름.
  • pairs: 이름으로 찾지 못한 차동 포트 쌍.
  • 쓰지 않는 항목은 비워 두거나 지우면 됩니다. 도구의 판정이 맞으면 아무것도 적지 않습니다.

도구가 지키는 그리기 규칙

  1. 모든 핀은 이어져 있다. 선으로 잇지 못하면 같은 이름의 이름표로 잇고, 끝이 떠 있는 선은 만들지 않는다.
  2. 직선이 먼저다. 두 끝을 직선으로 이을 수 있으면 직선으로 긋고, 불가피할 때만 꺾는다(꺾임 수 최소 → 길이 최소 순으로 찾는다). 직선 거리의 1.5배를 넘게 돌아가야 하면 선 대신 이름표로 잇는다. 배치 단계에서부터 지킨다: 블록의 입력 핀을 앞 블록의 출력 핀과 같은 높이에 두고, 자리가 겹쳐 밀려나면 밀려난 블록 대신 앞 블록을 옮겨 높이를 맞춘다. 마주 보는 두 핀이 40px 이하로 어긋나 생기는 계단 꺾임(jog)은 검사에서 실패로 센다.
  3. 블록 화면에서는 선이 교차하지 않는다(교차가 생길 곳은 이름표). 트랜지스터 화면에서는 거울 쌍의 두 넷만 한 번 교차할 수 있다.
  4. 신호는 왼쪽에서 오른쪽으로 흐른다. 제어는 위, 클럭은 아래, 출력은 오른쪽, 기준은 왼쪽 둘째 자리.
  5. 트랜지스터는 접지에서 전원 쪽으로 세로로 쌓고, 직렬 소자는 한 열에 둔다. 차동 회로는 쌍마다 자기 축에 대칭, 여러 쌍은 나란히.
  6. 버스는 사선과 <MSB:LSB> 이름, 같은 셀의 반복 인스턴스는 한 블록 ×N + 주석. 직렬 저항 6개 이상은 R ×N 한 블록(쓰이는 마디는 탭 버스), 같은 셀로 만든 선택 트리는 MUX N:1 한 블록(잎 입력 버스, 단별 선택 버스)으로 접어 그리고 주석에 원래 소자를 적는다. 버스가 다른 쓰임과 일부만 겹쳐 접을 수 없으면 원래대로 펼쳐 그린다.
  7. 숨기는 것(정적 트림, 바이어스, 전원, 고속 신호와 무관한 블록, 더미, 안테나 다이오드)은 그리지 않고 생략 목록에 적는다. 전원은 화면에서 국소 전원 기호로만 보인다.
  8. 한 점에 선은 세 개까지, 접점에는 점. 글자는 서로, 또 선과 겹치지 않는다.
  9. 포트는 열린 쪽을 향한다. 입력은 왼쪽, 출력은 오른쪽 바깥에 두고, 포트 기호와 이름 바로 너머(가로 40px, 세로 60px 안)에 다른 기호가 있으면 port_facing_in으로 실패한다. 전송 게이트의 포트는 테두리 가운데에서 옆으로 나간다(테두리 안쪽에는 아무것도 두지 않는다). 스위치로만 이어진 포트들 중 스위치가 가장 많이 모이는 포트가 출력이다(MUX의 z).
  10. 트랜지스터 기호: 채널에서 소스/드레인 리드까지 가로 선을 12px로 두고, 소스 쪽 가로 선 위에 채운 화살표를 곧게 그린다.
  11. 화면에 빈 띠를 만들지 않는다. 기호도 글자도 없이 선만 지나가는 구간이 세로 600px(가로 1200px)을 넘으면 empty_band로 실패한다.

검증기(hd/verify.py)는 배선기의 내부 자료를 쓰지 않고 그림 좌표만으로 연결을 다시 읽어 netlist와 비교하며, 위 규칙 1–3, 8–10을 화면마다 셉니다. 실행할 때마다 정상 그림에 오류를 일부러 넣어(선 지우기, 선 끝 당기기, 불필요한 꺾임, 마주 보는 핀 20px 어긋내기, 접점 지우기, 이름표 바꾸기, 글자 겹치기, 핀 뒤바꾸기) 검증기가 잡는지도 시험합니다.

아직 하지 않는 것

  • 개념 기호로 묶기(가변 저항·가변 전류원·가변 커패시터), 패드 위 ESD·종단 표시: 지금은 소자와 박스 그대로 그립니다.
  • 비교기·증폭기 삼각형, MUX 사다리꼴: 지금은 박스입니다(인버터·버퍼만 삼각형).
  • 보정 루프 화면, 워드 속도 디지털 박스, 유닛 화면의 20개 상한에 따른 화면 나누기, cross-coupled 인버터의 90° 배치.
  • 검증기가 세지 못하는 것: 그룹이 화면에서 떨어져 놓이는 것, 화면이 너무 넓어 글자가 작아지는 것, 같은 쌍의 한쪽은 선·한쪽은 이름표로 이어지는 것. 스크린샷을 몇 장 직접 열어 확인하십시오.
  • 분류는 구조 규칙의 일부만 구현했습니다. 확신이 낮으면 질문으로 남기지만, 틀린 채 확신하는 경우가 있을 수 있습니다.
